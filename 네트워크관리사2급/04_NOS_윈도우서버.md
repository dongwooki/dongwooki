## 1. NOS 기본 개념

### 1-1. NOS란?

**NOS(네트워크 운영체제)** 는 여러 컴퓨터가 네트워크로 연결되어 **자원(파일, 프린터, 계정, 서비스)을 공유하고 관리**할 수 있게 해 주는 운영체제다. 대표적으로 **Windows Server**, **Linux/UNIX** 가 있다.

일반 OS(Windows 10/11 같은 클라이언트 OS)도 파일 공유 정도는 되지만, NOS는 다음 기능에 특화되어 있다.

| NOS의 주요 기능 | 설명 |
|---|---|
| 사용자·계정 관리 | 계정을 서버에서 중앙 관리, 인증(로그온) 처리 |
| 자원 공유 | 파일 서버, 프린터 서버 |
| 보안 | 접근 권한, 감사(Audit), 암호화 |
| 네트워크 서비스 | DNS, DHCP, 웹(IIS), FTP, 원격 접속 |
| 안정성·확장성 | 이중화(클러스터), 다중 CPU·대용량 메모리, 백업 |

### 1-2. 네트워크 구성 모델: P2P vs 클라이언트/서버

| 구분 | 피어 투 피어(P2P) | 클라이언트/서버(서버 기반) |
|---|---|---|
| 구조 | 모든 컴퓨터가 **동등** (서버이자 클라이언트) | **전용 서버**가 서비스 제공, 클라이언트는 요청 |
| 관리 | 각 컴퓨터마다 따로 관리 (분산) | 서버에서 **중앙 관리** |
| 보안 | 약함 (각자 설정) | 강함 (중앙 인증·권한) |
| 비용 | 저렴, 구축 간단 | 서버 구입·관리자 필요 |
| 규모 | **소규모**(대략 10대 내외) | **중·대규모** |
| 윈도우에서 | **워크그룹(Workgroup)** | **도메인(Domain)** |

### 1-3. 워크그룹 vs 도메인 (★단골)

- **워크그룹(Workgroup)**
  - P2P 방식. **각 컴퓨터가 자기만의 로컬 계정 DB(SAM)** 를 가진다.
  - 컴퓨터 A의 자원을 쓰려면 A에 내 계정이 따로 있어야 함 → 컴퓨터가 많아지면 관리가 지옥.
  - 중앙 인증(SSO) 없음.
- **도메인(Domain)**
  - 서버 기반. **도메인 컨트롤러(DC)** 가 **Active Directory(AD DS)** 로 사용자·컴퓨터 계정을 **중앙 관리**.
  - 한 번 로그온하면 도메인 내 허용된 자원 모두 사용 (**SSO, Single Sign-On**).
  - 최소 **1대 이상의 DC** 가 필요하고, AD는 **DNS** 가 있어야 동작한다.

> 💡 시험 포인트: "워크그룹 = 각자 SAM, 분산 관리 / 도메인 = DC가 AD로 중앙 관리" 구분을 묻는 '옳지 않은 것' 문제가 나온다.

## 2. Windows Server 버전·에디션·설치 옵션

### 2-1. 주요 버전 흐름 (특징 위주로만)

| **Windows 2000 Server** | **Active Directory 최초 도입** |
| Windows Server 2003 | AD 개선, IIS 6.0 |
| **Windows Server 2008** | **Server Core** 설치 옵션, **Hyper-V**, **RODC** 도입, 서버 관리자 |

| **Windows Server 2012 / R2** | **ReFS** 도입, 새 서버 관리자(대시보드), 저장소 공간(Storage Spaces), dcpromo 대신 서버 관리자/PowerShell로 DC 승격 |
| **Windows Server 2016** | **Nano Server**, 컨테이너, 중첩 가상화 |
| Windows Server 2019 / 2022 / 2025 | 하이브리드(클라우드 연동), 보안 강화 |

### 2-2. 에디션

| 에디션 | 특징 |
|---|---|
| **Essentials** | 소규모 기업용 (사용자 수 제한, 약 25명 수준) |
| **Standard** | 일반 서버용. 가상화 권한 **VM 2개** (라이선스 기준) |
| **Datacenter** | 고밀도 가상화. **VM 무제한**, 고급 기능(Storage Spaces Direct, 차폐 VM 등) |

### 2-3. 설치 옵션

| 옵션 | 설명 |
|---|---|
| **데스크톱 환경 포함(GUI)** | 익숙한 그래픽 화면. 관리 편하지만 무겁고 공격 표면이 넓음 |
| **Server Core** | **GUI 없이 명령줄(cmd, PowerShell)** 로만 관리. 디스크·메모리 사용 적고, **패치·재부팅 횟수 감소, 보안 향상**. 로컬에서는 `sconfig` 로 기본 설정 |
| **Nano Server** (2016) | Server Core보다 더 작은 **초경량** 서버. 로컬 로그온 화면 없이 **원격 관리 전용**. 이후에는 컨테이너 이미지 용도로 축소 |

> 💡 시험 포인트: "GUI 없이 최소 구성으로 설치하여 보안·자원 효율이 높은 설치 옵션 = Server Core". 버전별로는 "AD 최초 = 2000", "RODC·Hyper-V·Server Core = 2008", "ReFS = 2012"가 자주 쓰인다.

## 3. Active Directory (AD DS)

### 3-1. AD란?

**Active Directory Domain Services(AD DS)** = 네트워크의 사용자, 컴퓨터, 그룹, 프린터, 공유 폴더 등 **모든 개체(Object) 정보를 저장하는 디렉터리 서비스(전화번호부 같은 DB)**.

- **LDAP(Lightweight Directory Access Protocol)** 기반으로 개체를 검색·관리 (LDAP 기본 포트 389)
- 개체 이름 표기 예: `CN=홍길동,OU=영업부,DC=korea,DC=com` (CN=일반 이름, OU=조직 단위, DC=도메인 구성 요소)
- 인증 프로토콜: 기본 **Kerberos** (구형 호환용 NTLM)
- AD 데이터베이스 파일: **NTDS.dit**, 그룹 정책·로그온 스크립트 공유 폴더: **SYSVOL**
- **AD는 DNS에 의존**한다 (클라이언트가 DNS의 SRV 레코드로 DC를 찾음). DNS 없으면 AD 설치 불가.

### 3-2. AD의 논리적 구조 (★최다 출제)

작은 것 → 큰 것 순서로 기억: **OU < 도메인 < 트리 < 포리스트**

| 구성 요소 | 설명 |
|---|---|
| **개체(Object)** | 사용자, 컴퓨터, 그룹, 프린터 등 AD에 저장되는 하나하나 |
| **OU (Organizational Unit, 조직 구성 단위)** | 도메인 **안에서** 개체를 묶는 **컨테이너**. 부서별로 만들고 **관리 권한 위임**, **GPO 연결**의 단위 |
| **도메인 (Domain)** | AD의 **핵심 관리 단위·보안 경계·복제 단위**. 예: `korea.com` |
| **트리 (Tree)** | **연속된 DNS 이름 공간**을 공유하는 도메인들의 계층. 예: `korea.com` ← `seoul.korea.com`, `busan.korea.com` |
| **포리스트 (Forest)** | **하나 이상의 트리 집합**. AD의 **최상위 단위**이자 최종 보안 경계. 포리스트 안의 모든 도메인은 **같은 스키마, 같은 구성, 같은 글로벌 카탈로그**를 공유. 이름 공간은 달라도 됨(`korea.com` 트리 + `japan.net` 트리) |

- 포리스트에서 **처음 만든 도메인 = 포리스트 루트 도메인**
- **스키마(Schema)**: AD에 저장할 수 있는 개체 클래스와 속성의 **정의(설계도)**. 포리스트 전체에 하나.

### 3-3. AD의 물리적 구조

| 구성 요소 | 설명 |
|---|---|
| **도메인 컨트롤러(DC)** | AD DS 역할이 설치되어 **AD DB를 보관하고 인증을 처리**하는 서버. DC끼리는 **다중 마스터 복제**(어느 DC에서 바꿔도 다른 DC로 복제) |
| **사이트(Site)** | **물리적 위치(IP 서브넷)** 기준의 묶음. **복제 트래픽 조절**, 클라이언트가 **가까운 DC로 로그온**하도록 함. 논리 구조(도메인)와 무관 |
| **RODC (Read-Only DC)** | **읽기 전용 DC** (2008~). **물리 보안이 취약한 지사**에 배치. AD DB의 읽기 전용 사본, RODC에서 변경한 내용은 다른 DC로 복제되지 않음(단방향 복제), **암호 캐싱을 지정한 계정만** 저장 가능 → 서버를 도난당해도 피해 최소화. FSMO 역할을 가질 수 없고, 포리스트의 첫 DC가 될 수 없음 |
| **글로벌 카탈로그(GC)** | 포리스트의 **모든 개체의 일부 속성(부분 복제본)** 을 가진 DC. **포리스트 전체 검색**, 로그온 시 **유니버설 그룹 멤버십 확인**에 사용. 포리스트의 **첫 DC는 자동으로 GC**. (포트 3268) |

### 3-4. FSMO (Flexible Single Master Operations) 5가지 역할 (★)

AD는 다중 마스터 복제지만, 충돌하면 안 되는 작업은 **딱 한 DC만** 담당한다. 이것이 FSMO(운영 마스터) 역할.

| 범위 | 역할 | 하는 일 |
|---|---|---|
| **포리스트당 1개** | **스키마 마스터** | 스키마 변경을 담당 |
| **포리스트당 1개** | **도메인 명명 마스터** | 포리스트에 **도메인 추가/삭제** 담당 |
| 도메인당 1개 | **RID 마스터** | 각 DC에 **RID 풀(상대 식별자)** 배분 → 개체의 **SID**가 중복되지 않게 함 |
| 도메인당 1개 | **PDC 에뮬레이터** | **시간 동기화** 기준, **암호 변경 우선 처리**, 계정 잠금 처리, 구형(NT) 호환 |
| 도메인당 1개 | **인프라 마스터** | 다른 도메인 개체 참조 정보(그룹 멤버 등) 갱신 |

> 암기: **포리스트 = "스키마·명명(2개)"**, 도메인 = "RID·PDC·인프라(3개)" → 포리스트에 1+1, 도메인에 3 = 총 5.
> 역할 확인 명령: `netdom query fsmo`

### 3-5. 트러스트(Trust, 신뢰 관계)

다른 도메인 사용자가 내 도메인 자원에 접근할 수 있게 해 주는 관계. **신뢰하는(Trusting) 도메인 = 자원 있는 쪽**, **신뢰받는(Trusted) 도메인 = 계정 있는 쪽**.

| 트러스트 종류 | 특징 |
|---|---|
| 부모-자식 / 트리-루트 트러스트 | 포리스트 안에서 **자동 생성**, **양방향 + 전이적(transitive)** |
| 바로 가기(Shortcut) 트러스트 | 같은 포리스트 안 먼 도메인 간 **인증 경로 단축** |
| 외부(External) 트러스트 | **다른 포리스트의 특정 도메인**과 연결, **비전이적** |
| 포리스트(Forest) 트러스트 | **포리스트 루트끼리** 연결, 전이적 |
| 영역(Realm) 트러스트 | 윈도우가 아닌 **Kerberos 영역(UNIX 등)** 과 연결 |

- **전이적(Transitive)**: A↔B, B↔C 이면 A↔C 도 자동 신뢰.

### 3-6. 도메인/포리스트 기능 수준(Functional Level)

- 도메인(포리스트)에서 사용할 수 있는 **AD 기능의 수준**을 정하는 값. 보통 **가장 오래된 DC의 OS 버전** 기준.
- 기능 수준을 올리면 **새 기능 사용 가능**, 대신 **그보다 낮은 버전 OS의 DC는 추가할 수 없다**.

### 3-7. AD 설치(승격) 흐름

1. 고정 IP, DNS 설정 확인
2. 서버 관리자 → 역할 추가 → **Active Directory 도메인 서비스**
3. "이 서버를 도메인 컨트롤러로 승격" → 새 포리스트 / 기존 도메인에 추가 선택
4. (2008 R2까지는 **`dcpromo`** 명령, 2012부터는 서버 관리자 또는 PowerShell `Install-ADDSForest`)
5. **DSRM(디렉터리 서비스 복원 모드) 암호** 설정 → 재부팅

진단 명령: `dcdiag`(DC 상태 진단), `repadmin`(복제 확인), `ntdsutil`(AD DB 관리)

> 💡 시험 포인트: "포리스트 = 트리들의 집합, 같은 스키마·GC 공유", "사이트 = 물리적(IP 서브넷) 단위, 복제 제어", "OU = 위임·GPO 단위", "포리스트당 1개 FSMO = 스키마/도메인 명명", "RODC = 지사용 읽기 전용".

## 4. 그룹 정책 (Group Policy)

### 4-1. 개념

**그룹 정책 개체(GPO)** = 사용자·컴퓨터 환경을 **중앙에서 일괄 설정**하는 규칙 묶음.
예: 암호 정책(최소 길이, 복잡성), 계정 잠금 정책, 바탕화면 고정, 제어판 차단, USB 사용 금지, 소프트웨어 배포, 로그온 스크립트, 드라이브 매핑.

- GPO는 **컴퓨터 구성** / **사용자 구성** 두 부분으로 나뉜다.
  - 컴퓨터 구성 → 컴퓨터 부팅 시 적용
  - 사용자 구성 → 사용자 로그온 시 적용
- GPO는 **사이트, 도메인, OU** 에 **연결(Link)** 한다. (기본 컨테이너인 `Users`, `Computers` 폴더에는 연결 불가 → 그래서 OU를 만든다)
- 기본 GPO: **Default Domain Policy**(도메인에 연결, 암호/계정 잠금 정책), **Default Domain Controllers Policy**(DC OU에 연결)

### 4-2. 적용 순서: **LSDOU** (★)

```
L(Local, 로컬) → S(Site, 사이트) → D(Domain, 도메인) → OU(조직 구성 단위, 상위 OU → 하위 OU)
```

- **나중에 적용된 것이 이긴다(덮어쓴다).** → 설정이 충돌하면 **OU(가장 하위 OU)** 의 설정이 최종 적용.
- 예외 옵션
  - **상속 차단(Block Inheritance)**: 하위 OU가 상위 GPO를 받지 않음
  - **강제(Enforced, 구 No Override)**: 상위 GPO가 하위에서 덮어써지거나 차단되지 않음 → **강제가 상속 차단보다 우선**
  - **보안 필터링**: 특정 그룹에만 GPO 적용
  - **WMI 필터**: 특정 조건(OS 버전 등) 컴퓨터에만 적용

### 4-3. 적용 시점과 명령어

| 항목 | 내용 |
|---|---|
| 자동 갱신 주기 | 일반 컴퓨터 **90분 (+0~30분 임의 지연)**, DC는 **5분** |
| **`gpupdate /force`** | 변경된 그룹 정책을 **즉시 강제 적용** |
| **`gpresult /r`** | 현재 사용자·컴퓨터에 **적용된 GPO 결과(RSoP) 확인** |
| `gpedit.msc` | **로컬** 그룹 정책 편집기 (한 대의 컴퓨터) |
| `gpmc.msc` | **그룹 정책 관리 콘솔** (도메인 GPO 생성·연결·관리) |

> 💡 시험 포인트: "LSDOU 순서, 충돌 시 OU가 최종", "즉시 적용 = gpupdate /force", "적용 결과 확인 = gpresult".

## 5. 사용자·그룹 계정

### 5-1. 사용자 계정 종류

| 종류 | 저장 위치 | 관리 도구 |
|---|---|---|
| **로컬 사용자 계정** | 해당 컴퓨터의 **SAM** (`%SystemRoot%\System32\config\SAM`) | `lusrmgr.msc`, `net user` |
| **도메인 사용자 계정** | **AD DS (DC)** | `dsa.msc`(AD 사용자 및 컴퓨터), `New-ADUser` |

- 계정마다 고유 식별자 **SID(Security Identifier)** 가 붙는다. 이름을 바꿔도 SID는 그대로 → 권한 유지. 계정을 **삭제 후 같은 이름으로 다시 만들면 SID가 달라** 예전 권한이 사라진다.

### 5-2. 기본 제공 계정

| 계정 | 특징 |
|---|---|
| **Administrator** | 최고 관리자. **삭제 불가**, **이름 변경·비활성화는 가능** (보안상 이름 변경 권장) |
| **Guest** | 임시 사용자용. **기본적으로 비활성화**. 삭제 불가 |

### 5-3. 그룹 종류 (Type)

| 종류 | 용도 |
|---|---|
| **보안 그룹** | **권한(사용 권한·사용자 권한) 할당** 가능 + 메일 배포도 가능 |
| **배포 그룹** | **이메일 배포 목록 전용**. **권한 할당 불가** |

### 5-4. 그룹 범위 (Scope) (★)

| 범위 | 구성원으로 넣을 수 있는 것 | 권한을 줄 수 있는 곳 |
|---|---|---|
| **도메인 로컬** | 모든(신뢰) 도메인의 사용자·글로벌 그룹·유니버설 그룹, 같은 도메인의 도메인 로컬 그룹 | **자기 도메인 안**의 리소스만 |
| **글로벌** | **같은 도메인**의 사용자·글로벌 그룹 | **포리스트 내 모든 도메인**(신뢰 도메인) |
| **유니버설** | **포리스트 내 모든 도메인**의 사용자·글로벌·유니버설 그룹 | **포리스트 내 모든 도메인** (멤버십이 **글로벌 카탈로그에 저장**) |
| (로컬 그룹) | 도메인이 아닌 **한 컴퓨터의 SAM** 에 있는 그룹 | 그 컴퓨터만 |

한 줄 요약:
- **글로벌 = "우리 도메인 사람을 모으는 그룹"**
- **도메인 로컬 = "우리 도메인 자원에 권한을 주는 그룹"**
- **유니버설 = "포리스트 어디서나, 대신 GC 복제 부담"**

### 5-5. AGDLP 전략 (★)

권장 권한 부여 순서:

```
A (Accounts, 사용자 계정)
  → G (Global group, 글로벌 그룹에 넣고)
    → DL (Domain Local group, 도메인 로컬 그룹에 넣고)
      → P (Permissions, 도메인 로컬 그룹에 권한 부여)
```

- 다중 도메인이면 **AGUDLP** (중간에 Universal 추가)
- 예: 영업부 사용자들 → `G_영업부`(글로벌) → `DL_영업자료_읽기`(도메인 로컬) → 영업자료 폴더에 "읽기" 권한

### 5-6. 주요 기본 그룹

| 그룹 | 역할 |
|---|---|
| **Administrators** | 컴퓨터(또는 도메인 DC)의 모든 권한 |
| **Users** | 일반 사용자, 시스템 설정 변경 제한 |
| **Guests** | 매우 제한된 권한 |
| **Backup Operators** | 권한과 무관하게 파일 **백업·복원** 가능 |
| **Remote Desktop Users** | **원격 데스크톱 로그온** 허용 |
| **Account Operators** | (도메인) 사용자·그룹 계정 생성·관리 |
| **Server Operators** | (도메인) DC의 서비스·공유·백업 관리 |
| **Print Operators** | (도메인) 프린터 관리 |
| **Event Log Readers** | 이벤트 로그 읽기 |
| **Domain Admins** (글로벌) | 도메인 전체 관리자 |
| **Enterprise Admins** (유니버설, 루트 도메인) | **포리스트 전체** 관리자 |
| **Schema Admins** (유니버설, 루트 도메인) | **스키마 수정** 권한 |
| **Domain Users** | 도메인의 모든 사용자가 자동 소속 |

> 💡 시험 포인트: "포리스트 전체에 쓰이고 GC에 저장 = 유니버설", "메일 전용 권한 불가 = 배포 그룹", "AGDLP 순서", "Administrator 삭제 불가·Guest 기본 비활성".

## 6. 파일 시스템, EFS, BitLocker

### 6-1. 파일 시스템 비교 (★)

| 항목 | FAT32 | exFAT | **NTFS** | ReFS |
|---|---|---|---|---|
| 단일 파일 최대 | **4GB (정확히 4GB-1바이트)** | 사실상 무제한 | 매우 큼 | 매우 큼 |
| 주 용도 | 구형 호환, 작은 USB | **대용량 USB·SD카드** (플래시 메모리) | **윈도우 기본** (시스템·서버) | **대용량 서버 저장소** (2012~) |
| 파일/폴더 권한(ACL) | ✕ | ✕ | **○** | ○ |
| EFS 암호화 | ✕ | ✕ | **○** | ✕ |
| 압축 | ✕ | ✕ | **○** | (제한적) |
| 디스크 할당량 | ✕ | ✕ | **○** | ✕ |
| 저널링(장애 복구) | ✕ | ✕ | **○** | ○ |
| 부팅(시스템) 볼륨 | ○ | - | **○** | **✕** |
| 특징 | 호환성 최고 | FAT의 대용량판 | 보안·안정성 | **체크섬 기반 무결성, 손상 자동 복구**, 저장소 공간과 결합 |

- **FAT/FAT32 → NTFS 변환**: `convert D: /fs:ntfs` → **데이터 유지하며 변환 가능**
- **NTFS → FAT32** 는 변환 명령이 없음 → **포맷** 필요 (데이터 삭제)
- NTFS의 **저널링**: 디스크 변경 내역을 로그로 남겨 갑작스러운 전원 차단 후에도 파일 시스템을 일관된 상태로 복구.

### 6-2. EFS (Encrypting File System)

- **NTFS 전용**, **파일/폴더 단위** 암호화.
- 암호화한 **사용자 본인(인증서·키 보유자)과 복구 에이전트만** 열 수 있음. 다른 사용자는 관리자라도 열 수 없음(복구 에이전트 제외).
- 파일 속성 → 고급 → "데이터 보호를 위해 내용을 암호화", 명령어 **`cipher`**.
- **NTFS 압축과 EFS는 동시에 사용할 수 없다** (둘 중 하나).
- 암호화 파일을 **FAT32 볼륨으로 복사하면 암호화가 풀린다**(지원 안 하므로).

### 6-3. BitLocker

- **볼륨(드라이브) 전체** 암호화. 디스크를 뽑아 다른 PC에 꽂아도 못 읽게 함 → **도난·분실 대비**.
- **TPM(신뢰 플랫폼 모듈) 칩** 과 연동 (TPM 없으면 USB 시동 키/암호로도 가능).
- **BitLocker To Go**: USB 같은 **이동식 드라이브** 암호화 (FAT 계열 드라이브도 가능).
- 복구 키(48자리 숫자) 반드시 보관. 명령어 `manage-bde`.
- 서버에서는 "기능 추가"로 BitLocker 드라이브 암호화 설치.

| 비교 | EFS | BitLocker |
|---|---|---|
| 단위 | **파일/폴더** | **볼륨 전체** |
| 대상 위협 | 같은 PC의 **다른 사용자** | **디스크 도난·분실** |
| 필요 조건 | NTFS | TPM(권장) |
| 명령 | `cipher` | `manage-bde` |

> 💡 시험 포인트: "FAT32 = 파일 4GB 제한", "NTFS만 권한·EFS·할당량·압축", "convert는 데이터 유지하며 NTFS로", "EFS = 파일 단위 / BitLocker = 볼륨 단위·TPM", "ReFS = 2012 도입·무결성·자동 복구".

## 7. NTFS 권한과 공유 권한

### 7-1. NTFS 표준 권한

| 권한 | 할 수 있는 일 |
|---|---|
| **모든 권한 (Full Control)** | 아래 전부 + **권한 변경 + 소유권 가져오기** |
| **수정 (Modify)** | 읽기·쓰기·실행 + **삭제** |
| **읽기 및 실행 (Read & Execute)** | 읽기 + 프로그램 실행 |
| **폴더 내용 보기 (List Folder Contents)** | 폴더 안 목록 보기 (**폴더에만** 있음) |
| **읽기 (Read)** | 파일 내용·속성·권한 보기 |
| **쓰기 (Write)** | 파일 생성·내용 변경 (※ **삭제는 수정 이상**) |
| 특수 권한 | 위를 세분화한 고급 권한 |

- **소유자(Owner)**: 파일을 만든 사람. 소유자는 언제든 권한을 바꿀 수 있음. 관리자는 **소유권 가져오기(Take Ownership)** 가능.

### 7-2. NTFS 권한 적용 규칙 (★)

1. **누적(합산)**: 사용자 권한 + 소속된 모든 그룹 권한을 **합친다**.
   - 예: 본인 "읽기" + 그룹1 "쓰기" → **읽기+쓰기**
2. **거부(Deny) 우선**: 어디서든 **거부**가 있으면 허용보다 **우선**.
   - 예: 본인 "읽기" 허용 + 그룹1 "쓰기" 허용 + 그룹2 "모든 권한" **거부** → **액세스 불가**
   - (심화) 정확한 우선순위는 **명시적 거부 > 명시적 허용 > 상속된 거부 > 상속된 허용**. 시험에서는 대부분 "거부 우선"으로 풀면 된다.
3. **상속**: 상위 폴더의 권한이 하위 폴더·파일로 **기본 상속**. 상속을 끄면 기존 권한을 "복사"하거나 "제거" 선택.
4. **파일 권한 > 폴더 권한**: 파일에 직접 준 권한이 폴더 권한보다 우선(폴더는 못 열어도 파일 경로를 알면 파일 권한대로 접근 가능).

### 7-3. 복사·이동 시 권한 변화 (★단골)

| 작업 | 결과 권한 |
|---|---|
| **같은 볼륨 내 이동** | **원래 권한 유지** (데이터가 실제로 이동하지 않고 위치 정보만 바뀌므로) |
| 같은 볼륨 내 **복사** | **대상 폴더 권한 상속** (새 파일이 생기는 것이므로) |
| **다른 볼륨으로 이동** | **대상 폴더 권한 상속** (실제로는 복사 후 원본 삭제) |
| 다른 볼륨으로 복사 | **대상 폴더 권한 상속** |
| NTFS → **FAT32** 로 복사/이동 | **권한·EFS 암호화 모두 사라짐** (FAT32는 권한 개념이 없음) |

> 암기: **"같은 볼륨에서 이동할 때만 유지, 나머지는 전부 상속"**

### 7-4. 공유 권한 (Share Permission)

- 폴더를 **네트워크로 공유**할 때 설정. **FAT32 폴더에도 설정 가능**(NTFS 아니어도 됨).
- 종류: **읽기 / 변경 / 모든 권한** (3가지뿐)
- 기본값(2003 이후): **Everyone – 읽기**
- **네트워크로 접근할 때만** 적용. 그 컴퓨터에 **로컬 로그온해서 접근하면 공유 권한은 무시**되고 NTFS 권한만 적용.

### 7-5. 공유 권한 + NTFS 권한 조합 (★)

**네트워크 접근 시 유효 권한 = 공유 권한과 NTFS 권한 중 "더 제한적인(작은) 것"**

| 공유 권한 | NTFS 권한 | 네트워크 접근 시 유효 권한 |
|---|---|---|
| 모든 권한 | 읽기 | **읽기** |
| 읽기 | 수정 | **읽기** |
| 변경 | 읽기 | **읽기** |
| 변경 | 모든 권한 | **변경(≈수정)** |
| 거부 포함 | (무엇이든) | **액세스 불가** |

- 실무 권장: 공유 권한은 넉넉히(Everyone 또는 Authenticated Users에 모든 권한/변경), **세밀한 통제는 NTFS 권한**으로.

### 7-6. 숨김 공유와 관리 공유 (★)

- 공유 이름 **끝에 `$`** 를 붙이면 **네트워크 검색(탐색 목록)에 보이지 않는 숨김 공유**가 된다. 경로를 직접 입력하면 접근 가능: `\\서버\자료$`
- **관리 공유(기본 숨김 공유)**: 윈도우가 자동 생성

| 관리 공유 | 대상 |
|---|---|
| **C$, D$ …** | 각 **드라이브 루트** |
| **ADMIN$** | **`%SystemRoot%`** (보통 `C:\Windows`) — 원격 관리용 |
| **IPC$** | **명명된 파이프(Named Pipe)** — 프로세스 간 통신(원격 관리 연결) |
| PRINT$ | 프린터 드라이버 (프린터 공유 시) |

- DC에는 추가로 **NETLOGON**, **SYSVOL** 공유가 생긴다($ 없음 = 보이는 공유).
- 공유 목록 확인: `net share`, 컴퓨터 관리 → 공유 폴더(`fsmgmt.msc`)

> 💡 시험 포인트: "누적 + 거부 우선", "같은 볼륨 이동만 권한 유지", "공유+NTFS = 더 제한적인 것", "숨김 공유 = 이름 끝 $", "ADMIN$ = Windows 폴더, IPC$ = 명명된 파이프".

## 8. 디스크 관리

### 8-1. 파티션 형식: MBR vs GPT (★)

| 항목 | MBR (Master Boot Record) | GPT (GUID Partition Table) |
|---|---|---|
| 최대 디스크 크기 | **2TB** | **2TB 초과 지원** (사실상 무제한급) |
| 파티션 개수 | **주 파티션 최대 4개** (또는 주 3 + **확장 파티션** 1 → 그 안에 논리 드라이브) | **최대 128개** (윈도우 기준), 확장 파티션 개념 없음 |
| 부팅 펌웨어 | **BIOS(레거시)** | **UEFI** |
| 안정성 | 파티션 정보 한 곳에 저장 | **헤더·파티션 테이블 백업본**을 디스크 끝에 보관, CRC 검사 |

### 8-2. 기본 디스크 vs 동적 디스크

| 구분 | 기본 디스크 (Basic) | 동적 디스크 (Dynamic) |
|---|---|---|
| 단위 | **파티션** (주/확장/논리) | **볼륨** (단순/스팬/스트라이프/미러/RAID-5) |
| 여러 디스크 묶기 | ✕ | **○** |
| 기본값 | 윈도우 기본 | 필요 시 변환 |
| 변환 | 기본 → 동적: **데이터 손실 없이** 가능 | 동적 → 기본: **볼륨을 모두 삭제해야** 가능 (데이터 손실) |

- 참고: 최근 윈도우는 동적 디스크 대신 **저장소 공간(Storage Spaces)** 을 권장. 시험에는 여전히 동적 디스크 볼륨이 단골.

### 8-3. 동적 디스크 볼륨 종류 (★최다 출제)

| 볼륨 | 최소 디스크 | RAID 대응 | 내결함성 | 사용 가능 용량 | 특징 |
|---|---|---|---|---|---|
| **단순 볼륨** | 1 | - | ✕ | 해당 공간 | 디스크 1개의 공간 |
| **스팬 볼륨** | **2** | (JBOD) | **✕** | **모든 디스크 합** | 여러 디스크의 빈 공간을 **이어 붙여** 하나처럼. 하나 고장 나면 **전체 손실**. 크기 달라도 됨 |
| **스트라이프 볼륨** | **2** | **RAID 0** | **✕** | **모든 디스크 합** | 데이터를 **나눠서 동시에 기록** → **읽기/쓰기 가장 빠름**. 하나 고장 → 전체 손실 |
| **미러 볼륨** | **2 (정확히 2개)** | **RAID 1** | **○** | **절반** (50%) | 같은 데이터를 두 디스크에 **복제**. 한 디스크 고장 나도 OK |
| **RAID-5 볼륨** | **3** | **RAID 5** | **○** | **(N-1) × 디스크 크기** | 데이터 + **패리티** 분산 저장. **디스크 1개 고장**까지 복구 |

- **내결함성(Fault Tolerance) 있는 것 = 미러, RAID-5 뿐!** (단순·스팬·스트라이프는 없음)
- 계산 예시
  - 1TB 디스크 3개로 RAID-5 → (3-1)×1TB = **2TB**
  - 500GB 디스크 4개로 RAID-5 → (4-1)×500GB = **1.5TB**
  - 1TB 디스크 2개로 미러 → **1TB**
  - 1TB 디스크 2개로 스트라이프 → **2TB**
- 시스템/부팅 볼륨은 **미러**는 가능하지만 스팬·스트라이프·RAID-5로는 만들 수 없다.

### 8-4. 디스크 할당량 (Disk Quota)

- **NTFS 볼륨**에서 **사용자별**로 사용 가능한 디스크 공간을 제한.
- 기준: 파일의 **소유자**가 사용한 양(압축 전 크기로 계산).
- **경고 수준**과 **제한 수준** 설정, "할당량 한도를 초과하는 사용자에게 디스크 공간 거부" 선택 가능.
- 단위가 **볼륨 단위**(폴더 단위로 하려면 FSRM의 할당량 사용 → 9-7 참고).

### 8-5. 볼륨 섀도 복사본 (VSS, Volume Shadow Copy)

- 공유 폴더의 파일을 **특정 시점 스냅숏**으로 자동 보관 → 사용자가 실수로 지우거나 고쳐도 **"이전 버전"** 탭에서 직접 복원.
- 볼륨 단위로 설정, 기본 일정(평일 7:00, 12:00).
- 백업을 대체하는 것은 아님(같은 디스크에 저장되므로 디스크 고장 시 함께 손실).

### 8-6. 관련 도구

- **`diskmgmt.msc`** : 디스크 관리 (GUI)
- **`diskpart`** : 명령줄 디스크 관리 (`list disk`, `select disk 1`, `convert gpt`, `convert dynamic`, `create partition primary`)
- **`chkdsk C: /f /r`** : 디스크 오류 검사·복구 (`/f` 오류 수정, `/r` 불량 섹터 찾아 복구)
- **`convert D: /fs:ntfs`** : FAT32 → NTFS 변환

> 💡 시험 포인트: "MBR = 2TB·주 파티션 4개 / GPT = 2TB 초과·128개·UEFI", "동적 → 기본 변환은 데이터 삭제 필요", "내결함성 = 미러(2개)·RAID-5(3개 이상)", "RAID-5 용량 = (N-1)×크기", "할당량 = NTFS·사용자별·볼륨 단위".

## 9. 서버 역할 (Server Roles)

> 서버 관리자 → **역할 및 기능 추가** 로 설치. **역할(Role)** = 서버의 주된 서비스(DNS, DHCP, IIS…), **기능(Feature)** = 보조 기능(BitLocker, 백업, 장애 조치 클러스터링, .NET…).

### 9-1. IIS (Internet Information Services) — 웹/FTP 서버

- 역할 이름: **웹 서버(IIS)**. FTP 서버는 IIS의 하위 구성요소로 설치.
- 관리 도구: **IIS 관리자** (`inetmgr`)
- 주요 개념
  - **사이트 바인딩**: IP 주소 + 포트(기본 HTTP 80 / HTTPS 443) + **호스트 헤더(호스트 이름)** → 한 서버에서 **여러 웹 사이트** 운영 가능
  - **기본 문서**: 주소만 입력했을 때 보여줄 파일 (`index.html`, `default.aspx` 등)
  - **가상 디렉터리**: 실제 다른 위치의 폴더를 웹 경로처럼 연결
  - **응용 프로그램 풀(Application Pool)**: 웹 앱을 분리된 작업자 프로세스에서 실행 → 하나가 죽어도 다른 사이트 영향 없음
  - **인증 방식**: 익명 인증, 기본 인증(평문에 가까움 → SSL과 함께), Windows 인증
  - HTTPS 사용 시 **서버 인증서** 바인딩
- FTP 사이트: 기본 포트 21, 익명/기본 인증, **FTP 사용자 격리** 기능

### 9-2. DNS 서버 (★)

DNS = 도메인 이름 ↔ IP 주소 변환. (레코드 종류 A/AAAA/CNAME/MX/PTR/NS/SOA/SRV 의 상세는 TCP/IP 노트 참고)

**영역(Zone)** = DNS 서버가 책임지고 관리하는 이름 공간 범위.

| 조회 방향 | 설명 |
|---|---|
| **정방향 조회 영역** | **이름 → IP** (A, AAAA 레코드) |
| **역방향 조회 영역** | **IP → 이름** (**PTR** 레코드, `x.x.x.in-addr.arpa`) |

| 영역 유형 | 설명 |
|---|---|
| **주 영역 (Primary)** | 영역의 **원본**. **읽기/쓰기** 가능 |
| **보조 영역 (Secondary)** | 주 영역으로부터 **영역 전송(Zone Transfer)** 을 받아 만든 **읽기 전용 복사본**. 부하 분산·장애 대비 |
| **스텁 영역 (Stub)** | 해당 영역의 **SOA, NS, 글루(A) 레코드만** 보관 → 그 영역의 권한 있는 DNS 서버가 어디인지만 앎 |
| **AD 통합 영역** | 영역 데이터를 **AD DB에 저장**. **DC에서만** 가능. AD 복제로 동기화(**다중 마스터**, 모든 DC에서 수정 가능), **보안 동적 업데이트** 지원 |

그 밖의 DNS 서버 개념
- **전달자(Forwarder)**: 내가 모르는 이름은 **지정한 다른 DNS 서버로 넘김** (예: ISP DNS)
- **조건부 전달자**: 특정 도메인만 특정 DNS 서버로 넘김
- **루트 힌트**: 전달자가 없을 때 사용할 **루트 DNS 서버 목록**
- **동적 업데이트**: 클라이언트(또는 DHCP)가 자기 레코드를 자동 등록
- **캐싱 전용 DNS 서버**: 영역 없이 조회 결과만 캐시
- 관리 도구: `dnsmgmt.msc`

### 9-3. DHCP 서버 (★)

DHCP = 클라이언트에 **IP 주소·서브넷 마스크·게이트웨이·DNS** 를 **자동 할당**. (DORA 과정은 TCP/IP 노트 참고)

| 용어 | 설명 |
|---|---|
| **범위 (Scope)** | 할당할 **IP 주소 풀** (예: 192.168.1.100 ~ 192.168.1.200) |
| **제외 범위 (Exclusion)** | 범위 안이지만 **할당하지 않을 주소** (서버·프린터용 고정 IP 영역) |
| **예약 (Reservation)** | 특정 **MAC 주소** 장치에 **항상 같은 IP** 할당 (프린터, 서버) |
| **임대 기간 (Lease Duration)** | IP를 빌려주는 기간. **윈도우 기본 8일**. 기간의 50% 지나면 갱신 시도 |
| **범위 옵션** | 003 라우터(기본 게이트웨이), 006 DNS 서버, 015 DNS 도메인 이름 등 |
| **슈퍼 범위 (Superscope)** | 여러 범위를 묶어 하나의 물리 네트워크에 제공 |
| **DHCP 장애 조치 (2012~)** | 두 DHCP 서버가 임대 정보를 공유 (부하 분산 / 핫 스탠바이) |
| **권한 부여 (Authorize)** | 도메인 환경에서는 DHCP 서버를 **AD에 권한 부여**해야 동작 (불법 DHCP 서버 방지) |

**DHCP 릴레이 에이전트 (★)**
- 클라이언트가 처음 보내는 **DHCP Discover 는 브로드캐스트** → **라우터는 브로드캐스트를 넘기지 않는다.**
- 그래서 **DHCP 서버와 다른 서브넷**의 클라이언트는 IP를 못 받음 → 라우터(또는 서버)에 **DHCP 릴레이 에이전트**를 설정해 브로드캐스트를 DHCP 서버로 **유니캐스트 전달**.
  - 윈도우: **RRAS(라우팅 및 원격 액세스)** 의 DHCP 릴레이 에이전트
  - 시스코 라우터: `ip helper-address <DHCP서버IP>`
- 관리 도구: `dhcpmgmt.msc`

### 9-4. WSUS (Windows Server Update Services)

- 마이크로소프트 업데이트를 **사내 서버가 대신 받아서**, 관리자가 **승인한 업데이트만** 클라이언트에 배포.
- 장점: 인터넷 대역폭 절약, 업데이트 테스트 후 배포, 설치 현황 보고.
- 클라이언트는 **그룹 정책**으로 WSUS 서버 주소 지정.

### 9-5. Hyper-V (★)

- 마이크로소프트의 **하이퍼바이저 기반 가상화** (Type 1, 베어메탈형).
- 요구 사항: **64비트 CPU**, **하드웨어 가상화 지원(Intel VT-x / AMD-V)**, **SLAT**, DEP(데이터 실행 방지).
- 관리 도구: **Hyper-V 관리자** (`virtmgmt.msc`)

**가상 스위치 3종 (★)**

| 가상 스위치 | 통신 범위 |
|---|---|
| **외부 (External)** | **물리 NIC에 연결** → VM이 **실제 외부 네트워크**와 통신 (VM ↔ 호스트 ↔ 외부 모두) |
| **내부 (Internal)** | **VM ↔ VM, VM ↔ 호스트** 만. 외부 물리 네트워크와는 직접 통신 ✕ |
| **개인 (Private)** | **VM ↔ VM** 끼리만. **호스트와도 통신 ✕** (가장 격리됨) |

기타 용어
- **검사점(Checkpoint)**: VM의 **특정 시점 상태 저장**(예전 이름 스냅숏) → 테스트 후 되돌리기
- **가상 디스크**: **VHD**(최대 2TB) / **VHDX**(최대 64TB, 2012~, 손상 방지 강화)
- 디스크 유형: 고정 크기 / **동적 확장**(쓰는 만큼 커짐) / 차이점 디스크(부모 디스크 기반 변경분만)
- **1세대 VM**(BIOS) / **2세대 VM**(UEFI, 보안 부팅)
- **라이브 마이그레이션**: 실행 중인 VM을 **중단 없이** 다른 호스트로 이동
- **동적 메모리**: VM 사용량에 따라 메모리 자동 조절
- **복제본(Hyper-V Replica)**: VM을 다른 호스트로 비동기 복제(재해 복구)

### 9-6. 원격 데스크톱 서비스 (RDS)

- 사용자가 원격에서 서버의 데스크톱/앱을 사용 (**RDP 프로토콜, TCP 3389**), 클라이언트 프로그램 **`mstsc`**.
- 관리 목적 원격 데스크톱은 **동시 2세션**까지 별도 라이선스 없이 가능.
- 여러 사용자가 동시에 쓰려면 **RD 세션 호스트 + RD 라이선싱(RDS CAL)** 필요.
- 구성 요소: RD 세션 호스트, RD 연결 브로커, RD 웹 액세스, RD 게이트웨이(HTTPS로 외부 접속 중계), RD 라이선싱.
- 원격 로그온 허용 그룹: **Remote Desktop Users**

### 9-7. 파일 서버: FSRM, DFS

**FSRM (File Server Resource Manager, 파일 서버 리소스 관리자)**
- **할당량(Quota)**: **폴더 단위**(또는 볼륨) 용량 제한, **하드(초과 차단)/소프트(경고만)**. 사용자 구분 없이 폴더 전체 기준 → NTFS 디스크 할당량(사용자·볼륨 단위)과 차이점!
- **파일 차단(File Screening)**: 특정 확장자(예: `.mp3`, `.exe`) 저장 금지
- **저장소 보고서**: 큰 파일, 중복 파일, 오래된 파일 보고

| 비교 | NTFS 디스크 할당량 | FSRM 할당량 |
|---|---|---|
| 단위 | **볼륨** | **폴더**(또는 볼륨) |
| 기준 | **사용자(소유자)별** | 폴더 전체 사용량 |
| 추가 기능 | 없음 | 파일 차단·보고서·템플릿 |

**DFS (Distributed File System, 분산 파일 시스템)**
- **DFS 네임스페이스**: 여러 서버에 흩어진 공유 폴더를 **하나의 논리 경로**로 묶음 (`\\korea.com\공용\…`) → 사용자는 실제 서버 위치를 몰라도 됨
- **DFS 복제(DFS-R)**: 여러 서버의 폴더를 **자동 동기화**, 변경된 부분만 압축 전송(RDC)

### 9-8. Windows Server Backup

- "기능"으로 설치. 명령줄 **`wbadmin`**.
- 백업 대상: 전체 서버, 특정 볼륨/폴더, **시스템 상태(System State: 레지스트리·AD·부팅 파일 등)**, **완전 복구(Bare Metal Recovery)**.
- 블록 수준 백업, 증분 방식 지원. 외부 디스크·네트워크 공유에 저장.

### 9-9. 고가용성: NLB vs 장애 조치 클러스터

| 구분 | **네트워크 부하 분산 (NLB)** | **장애 조치 클러스터 (Failover Cluster)** |
|---|---|---|
| 목적 | 요청을 여러 서버에 **나눠서 처리** (성능·가용성) | 한 서버 장애 시 **다른 노드가 서비스 인수** (가용성) |
| 적합한 서비스 | **상태 없는(stateless)** 서비스: **웹(IIS)**, VPN, 프록시 | **상태 있는(stateful)** 서비스: **DB(SQL), 파일 서버, Hyper-V** |
| 저장소 | 각 노드가 동일한 데이터 복사본 | **공유 저장소**(SAN, iSCSI 등) 필요 |
| 핵심 개념 | 가상 IP 하나로 여러 노드가 응답 (최대 32노드) | **하트비트**로 상태 감시, **쿼럼(Quorum)** 으로 클러스터 유지 판단 |

> 💡 시험 포인트: "보조 영역 = 영역 전송으로 받은 읽기 전용", "AD 통합 영역 = DC에서만·다중 마스터", "예약 = MAC 기준 고정 IP / 제외 = 할당 안 함", "다른 서브넷 DHCP = 릴레이 에이전트", "개인 스위치 = VM끼리만", "웹 = NLB / DB·파일 = 장애 조치 클러스터", "FSRM = 폴더 할당량·파일 차단".

### 10-4. 성능·상태 모니터링 도구

| 도구 | 용도 |
|---|---|
| **작업 관리자** (`taskmgr`, Ctrl+Shift+Esc) | 실행 중인 프로세스·앱 확인 및 **강제 종료**, CPU/메모리 실시간 사용률, 시작 프로그램 |
| **리소스 모니터** (`resmon`) | CPU·메모리·**디스크·네트워크**를 **프로세스별로 상세히** 실시간 확인 (어떤 프로세스가 어떤 파일·포트를 쓰는지) |
| **성능 모니터** (`perfmon`) | **카운터** 기반 그래프, **데이터 수집기 집합**으로 장기간 기록, 보고서 → **병목 분석·기준선(Baseline)** |
| 안정성 모니터 (`perfmon /rel`) | 날짜별 시스템 안정성 지수와 오류 이력 |

성능 모니터 대표 카운터
- `Processor \ % Processor Time` : CPU 사용률 (지속적으로 80% 이상이면 CPU 병목 의심)
- `Memory \ Available MBytes`, `Memory \ Pages/sec` : 메모리 부족 여부
- `PhysicalDisk \ % Disk Time`, `Avg. Disk Queue Length` : 디스크 병목
- `Network Interface \ Bytes Total/sec` : 네트워크 사용량

> 💡 시험 포인트: ".msc 이름과 도구 짝 맞추기"(특히 dsa, gpmc, gpedit, secpol, lusrmgr, compmgmt), "로그온 실패 기록 = 보안 로그", "서비스 시작 실패·드라이버 = 시스템 로그".

## 12. 레지스트리 (Registry)

- 윈도우의 **하드웨어·소프트웨어·사용자 설정을 저장하는 계층형 데이터베이스**. 편집기 **`regedit`**.
- 실제 파일(하이브)은 `%SystemRoot%\System32\config` 폴더(SAM, SECURITY, SOFTWARE, SYSTEM 등)와 사용자 프로필의 `NTUSER.DAT`.
- 잘못 수정하면 부팅 불가 → 수정 전 **내보내기(백업)** 필수.

**루트 키 5개 (★)**

| 루트 키 | 약어 | 내용 |
|---|---|---|
| **HKEY_CLASSES_ROOT** | HKCR | **파일 확장자 연결**, COM 개체 정보 |
| **HKEY_CURRENT_USER** | HKCU | **현재 로그온한 사용자**의 설정(바탕화면, 제어판 설정) |
| **HKEY_LOCAL_MACHINE** | HKLM | **컴퓨터 전체**(하드웨어, 소프트웨어, 보안, 드라이버) 설정 — 하위 키 HARDWARE, SAM, SECURITY, SOFTWARE, SYSTEM |
| **HKEY_USERS** | HKU | 컴퓨터의 **모든 사용자 프로필** 설정 (HKCU는 이 중 현재 사용자 부분) |
| **HKEY_CURRENT_CONFIG** | HKCC | **현재 하드웨어 프로필** 정보 |

- 값의 데이터 형식: `REG_SZ`(문자열), `REG_DWORD`(32비트 숫자), `REG_BINARY`(이진), `REG_MULTI_SZ`(여러 문자열), `REG_EXPAND_SZ`(환경 변수 포함 문자열)

> 💡 시험 포인트: "루트 키가 아닌 것 고르기" — 그럴듯한 가짜(HKEY_CURRENT_SYSTEM, HKEY_LOCAL_USER 등)를 골라낸다.

## ★ 핵심사항 (시험 직전 10분 암기용)

- 워크그룹 = P2P, **각 컴퓨터 SAM** 분산 관리 / 도메인 = **DC + AD DS** 중앙 관리(SSO)
- AD 최초 도입 = **Windows 2000 Server** / RODC·Hyper-V·Server Core = **2008** / ReFS = **2012** / Nano Server = **2016**
- **Server Core** = GUI 없는 최소 설치 → 보안↑, 자원↓, 패치↓
- AD = **LDAP** 기반 디렉터리 서비스, 인증은 **Kerberos**, DB는 **NTDS.dit**, **DNS 필수**
- 구조 크기: **OU < 도메인 < 트리 < 포리스트** / **사이트 = 물리적(IP 서브넷) 단위**
- **포리스트** = 트리들의 집합, 같은 **스키마·GC** 공유
- **OU** = 관리 **위임** + **GPO 연결** 단위
- **글로벌 카탈로그** = 포리스트 전체 개체의 부분 복제, 검색·유니버설 그룹 확인, 첫 DC 자동 GC
- **FSMO**: 포리스트당 = **스키마 마스터, 도메인 명명 마스터** / 도메인당 = **RID, PDC 에뮬레이터, 인프라**
- **RODC** = 지사용 읽기 전용 DC, 변경 복제 안 됨, 암호 캐싱 제한
- GPO 적용 = **L → S → D → OU**, 충돌 시 **OU 승**. 강제(Enforced) > 상속 차단
- **`gpupdate /force`** 즉시 적용, **`gpresult /r`** 결과 확인
- 그룹 종류: **보안**(권한 O) / **배포**(메일 전용, 권한 X)
- 그룹 범위: **글로벌**(같은 도메인 구성원) / **도메인 로컬**(자기 도메인 권한) / **유니버설**(포리스트 전체, GC 저장)
- **AGDLP** = 계정 → 글로벌 → 도메인 로컬 → 권한
- **Administrator 삭제 불가**(이름 변경 가능), **Guest 기본 비활성**
- NTFS 권한 = **누적**, **거부 우선**, 기본 **상속**
- **같은 볼륨 내 이동만 권한 유지**, 그 외(복사, 다른 볼륨 이동) **대상 폴더 권한 상속**, FAT32로 가면 권한 소멸
- 공유 권한 = 읽기/변경/모든 권한, **네트워크 접근 시만** 적용 → NTFS와 조합 시 **더 제한적인 것**
- 공유 이름 끝 **`$` = 숨김 공유**. **C$** 드라이브, **ADMIN$** Windows 폴더, **IPC$** 명명된 파이프
- **FAT32 = 파일 4GB 제한**, 권한·EFS·할당량 없음 / **NTFS** = 권한·EFS·압축·할당량·저널링 / **ReFS** = 무결성·자동 복구, 부팅 불가
- `convert D: /fs:ntfs` = 데이터 유지하며 NTFS로 (반대는 포맷)
- **EFS = 파일 단위**(NTFS, `cipher`, 압축과 동시 불가) / **BitLocker = 볼륨 전체**(TPM, To Go = 이동식)
- **MBR** = 2TB, 주 파티션 4개, BIOS / **GPT** = 2TB 초과, 128개, UEFI
- 기본→동적 변환 데이터 유지 / **동적→기본은 볼륨 삭제 필요**
- 동적 볼륨: 스팬(2+, 이어붙임) · 스트라이프(2+, RAID0, 최고 속도) → **내결함성 X** / **미러(정확히 2, RAID1, 50%)** · **RAID-5(3+, (N-1)×용량)** → **내결함성 O**
- 디스크 할당량 = NTFS, **사용자별, 볼륨 단위** / FSRM 할당량 = **폴더 단위** + 파일 차단
- DNS 영역: 정방향(이름→IP) / 역방향(IP→이름, PTR) / **주(읽기·쓰기)** / **보조(영역 전송, 읽기 전용)** / **스텁(SOA·NS·글루만)** / **AD 통합(DC만, 다중 마스터, 보안 동적 업데이트)**
- DHCP: **제외** = 할당 안 함 / **예약** = MAC 기준 고정 IP / 임대 기본 **8일** / 다른 서브넷은 **릴레이 에이전트**(라우터는 브로드캐스트 차단)
- Hyper-V 스위치: **외부**(물리 네트워크) / **내부**(VM+호스트) / **개인**(VM끼리만) / 검사점 = 시점 저장
- **NLB = 웹 등 상태 없는 서비스 분산** / **장애 조치 클러스터 = DB·파일 등 상태 있는 서비스, 공유 저장소**
- .msc: **dsa**(AD 사용자·컴퓨터) / **gpmc**(그룹 정책 관리) / **gpedit**(로컬 GPO) / **secpol**(로컬 보안 정책) / **lusrmgr**(로컬 사용자·그룹) / **compmgmt**(컴퓨터 관리) / **diskmgmt**(디스크) / **devmgmt**(장치) / **services**(서비스) / **eventvwr**(이벤트)
- 이벤트 로그: **보안 = 로그온·감사**, 시스템 = 드라이버·서비스, 응용 프로그램 = 앱
- PowerShell cmdlet = **동사-명사**, `Get-Help`, `Install-WindowsFeature`
- `net user`(계정) / `net share`(공유) / `net use`(드라이브 연결) / `sfc /scannow`(시스템 파일 복구) / `whoami`(현재 사용자)
- 레지스트리 루트 키 5개: **HKCR, HKCU, HKLM, HKU, HKCC**

## ⚠️ 헷갈리는 함정 포인트

| 헷갈리는 쌍 | 구분법 |
|---|---|
| **트리 vs 포리스트** | 트리 = **연속된** DNS 이름(korea.com, seoul.korea.com) / 포리스트 = 이름이 **달라도 되는** 트리들의 묶음 |
| **도메인 vs 사이트** | 도메인 = **논리적**(관리·보안 경계) / 사이트 = **물리적**(IP 서브넷, 복제 제어) |
| **OU vs 그룹** | OU = **관리 위임·GPO 연결용 컨테이너**(권한 할당 X) / 그룹 = **권한 할당**용 |
| **GC vs FSMO** | GC = 포리스트 전체 개체 **검색용 사본** / FSMO = **단일 마스터 작업 역할** |
| **글로벌 vs 도메인 로컬** | 글로벌 = **사람 모으기**(같은 도메인 구성원) / 도메인 로컬 = **권한 받기**(자기 도메인 자원) |
| **보안 그룹 vs 배포 그룹** | 배포 그룹은 **권한 할당 불가** |
| **gpedit.msc vs gpmc.msc** | gpedit = **로컬** 한 대 / gpmc = **도메인** GPO 관리 |
| **secpol.msc vs lusrmgr.msc** | secpol = **로컬 보안 정책** / lusrmgr = **로컬 사용자 및 그룹** |
| **gpupdate vs gpresult** | gpupdate = **적용** / gpresult = **결과 확인** |
| **같은 볼륨 이동 vs 복사** | 이동 = **유지** / 복사 = **상속** |
| **공유 권한 vs NTFS 권한** | 공유 = **네트워크 접근 시만**, 3종류, FAT32에도 가능 / NTFS = **로컬·네트워크 모두**, NTFS만 |
| **EFS vs BitLocker** | EFS = **파일/폴더** / BitLocker = **볼륨 전체**(TPM) |
| **스팬 vs 스트라이프** | 둘 다 내결함성 X, 용량 = 합. 스팬 = **순서대로 채움** / 스트라이프 = **동시 분산 기록(빠름)**, 같은 크기로 사용 |
| **미러 vs RAID-5** | 미러 = **정확히 2개, 50%** / RAID-5 = **3개 이상, (N-1)** |
| **NTFS 할당량 vs FSRM 할당량** | NTFS = **사용자별·볼륨** / FSRM = **폴더별** |
| **주 영역 vs 보조 영역 vs 스텁** | 주 = 원본(쓰기 O) / 보조 = **전체 사본(읽기 전용)** / 스텁 = **SOA·NS·글루만** |
| **제외 범위 vs 예약** | 제외 = **아무에게도 안 줌** / 예약 = **특정 MAC에게만 항상 줌** |
| **내부 스위치 vs 개인 스위치** | 내부 = VM + **호스트** / 개인 = **VM끼리만** |
| **NLB vs 장애 조치 클러스터** | NLB = **웹(상태 없음)·분산** / 클러스터 = **DB·파일(상태 있음)·인수** |
| **net share vs net use** | share = **내 폴더를 공유** / use = **남의 공유를 드라이브로 연결** |
| **sfc vs chkdsk** | sfc = **시스템 파일** 무결성 / chkdsk = **디스크·파일 시스템** 오류 |
| **HKCU vs HKU** | HKCU = **현재 사용자만** / HKU = **모든 사용자** |

## 🧠 암기 팁

- **AD 구조 크기 순서**: "**오도트포**" = **O**U < **도**메인 < **트**리 < **포**리스트 ("오도독 트포 씹는다")
- **GPO 적용 순서 LSDOU**: "**L**ocal **S**ite **D**omain **OU**" → "**엘사도 오우!**" 마지막에 외친 OU가 이긴다
- **AGDLP**: "**A**pple **G**ood, **DL** **P**ack" → 계정 → 글로벌 → 도메인 로컬 → 권한 / 또는 "**아가들(AG DL) 피(P)곤해**"
- **FSMO 포리스트용 2개**: "**스명**(스키마·명명)은 숲(포리스트)에 하나" / 도메인용 3개: "**RPI**"(RID·PDC·Infra) → "**알피아이**"
- **권한 유지 규칙**: "**같은 집 안에서 방만 옮기면 짐 그대로, 이사·복사는 새집 규칙**"
- **공유+NTFS**: "**두 문 중 좁은 문**으로만 들어간다"
- **동적 볼륨 내결함성**: "**미라(미러·RAID-5)는 살아남는다**", 나머지(단순·스팬·스트라이프)는 하나 죽으면 다 죽음
- **RAID-5 용량**: "**한 개는 패리티 몫**" → (N-1)
- **Hyper-V 스위치**: 외부 = **세상**까지 / 내부 = **우리 집(호스트)** 까지 / 개인 = **방(VM) 끼리만**
- **관리 공유**: "**ADMIN$ = 윈도우 폴더, IPC$ = 파이프(Pipe → IPC)**"
- **레지스트리 5개**: "**클·커·로·유·컨**" (Classes_Root, Current_User, Local_Machine, Users, Current_Config)
- **DHCP 예약 vs 제외**: "**예약**은 **예**약한 손님(MAC)만, **제외**는 아무도 못 앉는 자리"
