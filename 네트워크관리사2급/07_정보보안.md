## 1. 정보보안의 기본 개념

### 1-1. 정보보안 3요소 (CIA Triad)

"보안"이라는 말은 막연하게 들리지만, 시험에서는 세 가지 목표로 정리한다. **누가 보면 안 되는가(기밀성)**, **바뀌면 안 되는가(무결성)**, **필요할 때 못 쓰면 안 되는가(가용성)**.

| 요소 | 영어 | 의미 | 보호 기술 예 | 침해 공격 예 |
|---|---|---|---|---|
| **기밀성** | Confidentiality | 인가된 사람만 정보에 접근·열람 | 암호화, 접근통제 | 스니핑, 도청, 가로채기 |
| **무결성** | Integrity | 인가되지 않은 사람이 정보를 **변경·삭제**하지 못함 | 해시, 전자서명, MAC(메시지 인증 코드) | 변조, 위조 |
| **가용성** | Availability | 인가된 사용자가 **필요할 때 언제든** 사용 가능 | 이중화, 백업, DDoS 대응 장비 | DoS / DDoS |

### 1-2. 3요소 외 추가 보안 요소

| 요소 | 의미 | 대표 기술 |
|---|---|---|
| **인증 (Authentication)** | 사용자가 **"자기가 주장하는 그 사람이 맞는지"** 확인 | 패스워드, OTP, 인증서, 생체 인식 |
| **부인 방지 (Non-repudiation)** | 메시지를 보낸/받은 사실을 **나중에 부인하지 못하게** 함 | **전자서명**, 공증 |
| **접근 통제 (Access Control)** | 인증된 사용자가 **어떤 자원에 어떤 권한**으로 접근할지 제한 | ACL, DAC/MAC/RBAC |
| **책임 추적성 (Accountability)** | 누가 무엇을 했는지 기록·추적 | 로그, 감사(Audit) |

> 인증 = "당신은 누구인가?" / 인가(권한 부여) = "이 작업을 해도 되는가?" / 부인 방지 = "보낸 사실을 나중에 부인할 수 없다"

### 1-3. 보안 위협의 4가지 분류 (정상 흐름: 송신자 → 수신자)

| 위협 | 영어 | 상황 | 침해되는 요소 | 공격 성격 |
|---|---|---|---|---|
| **가로막기** | Interruption | 송신자 → ✕ (수신자에게 전달되지 않음) | **가용성** | 능동적 |
| **가로채기** | Interception | 송신자 → 수신자, 중간에 제3자가 **몰래 엿봄** | **기밀성** | 수동적 |
| **변조** | Modification | 제3자가 중간에서 **내용을 바꿔서** 전달 | **무결성** | 능동적 |
| **위조** | Fabrication | 제3자가 송신자인 **척하고 가짜 메시지** 전송 | **무결성 / 인증** | 능동적 |

- **수동적 공격**: 데이터를 바꾸지 않고 엿보기만 함 → 탐지가 어려움 (도청, 트래픽 분석, 스니핑). 대응은 **예방(암호화)** 중심.
- **능동적 공격**: 데이터를 바꾸거나 서비스를 방해 → 탐지는 상대적으로 쉬움 (변조, 위조, 재전송, DoS). 대응은 **탐지·복구** 중심.

> 💡 시험 포인트: "가로채기 → 기밀성 / 가로막기 → 가용성 / 변조 → 무결성 / 위조 → 인증(무결성)" 짝 맞추기와 "부인 방지는 전자서명"이 단골.

## 2. 악성코드 (Malware)

악성코드를 구분하는 핵심 기준은 **① 스스로 복제하는가 ② 숙주(다른 파일)가 필요한가 ③ 목적이 무엇인가** 세 가지다.

| 종류 | 자기 복제 | 숙주 필요 | 특징 |
|---|---|---|---|
| **바이러스 (Virus)** | O | **O** (다른 실행 파일·부트 영역에 기생) | 감염된 파일을 실행해야 퍼짐 |
| **웜 (Worm)** | O | **X** (독립 실행) | **네트워크를 통해 스스로 확산**, 대역폭·시스템 자원 고갈 |
| **트로이 목마 (Trojan Horse)** | **X** | X | **정상 프로그램으로 위장**, 사용자가 직접 실행하도록 유도한 뒤 정보 유출·원격 제어 |
| **백도어 (Backdoor / Trapdoor)** | X | - | 정상 인증 절차를 **우회**하는 비밀 출입구. 개발자가 유지보수용으로 만든 통로가 악용되기도 함 |
| **루트킷 (Rootkit)** | X | - | 관리자(root) 권한 획득 + **자신의 흔적(프로세스·파일·로그) 은폐** 도구 모음 |
| **랜섬웨어 (Ransomware)** | - | - | 파일을 **암호화하고 복호화 대가(몸값)**를 요구 |
| **스파이웨어 (Spyware)** | - | - | 사용자 몰래 설치되어 개인정보·이용 습관 수집 |
| **애드웨어 (Adware)** | - | - | 광고를 자동으로 띄움 |
| **키로거 (Keylogger)** | - | - | **키보드 입력**을 가로채 ID·비밀번호 탈취 |
| **논리 폭탄 (Logic Bomb)** | X | - | 특정 **날짜·조건**이 충족되면 악성 동작 실행 |
| **봇 / 봇넷 (Bot / Botnet)** | - | - | 감염된 PC(**좀비 PC**)들이 **C&C 서버**의 명령을 받아 DDoS·스팸 발송 등 수행 |
| **혹스 (Hoax)** | X | - | 실제 악성코드가 아닌 **거짓 경고**로 불안감 조성 |

**바이러스의 종류**
- 부트 바이러스: 부트 섹터(MBR) 감염
- 파일 바이러스: 실행 파일(.exe, .com) 감염
- 매크로 바이러스: 문서(워드·엑셀)의 매크로 기능을 이용 → 실행 파일이 아닌 **문서 파일**도 감염
- 다형성(Polymorphic) 바이러스: 감염될 때마다 모양(코드)을 바꿔 백신 탐지 회피

> 💡 시험 포인트: "숙주 없이 네트워크로 스스로 퍼짐 = **웜**", "정상 프로그램 위장 + 자기 복제 없음 = **트로이 목마**", "흔적 숨김 = **루트킷**", "몸값 = **랜섬웨어**".

## 3. 서비스 거부 공격 (DoS / DDoS / DRDoS)

### 3-1. 개념

- **DoS (Denial of Service)**: 시스템 자원(CPU, 메모리, 대역폭, 연결 큐)을 고갈시켜 **정상 사용자가 서비스를 못 쓰게** 만드는 공격 → **가용성** 침해.
- **DDoS (Distributed DoS)**: **여러 대의 감염 PC(좀비)** 를 동원한 분산 DoS.
  - 구조: **공격자(Attacker) → 마스터(Master/Handler) → 에이전트(Agent/Daemon, 좀비) → 희생자(Victim)**
  - 대표 도구: Trinoo, TFN(Tribe Flood Network), TFN2K, Stacheldraht
- **DRDoS (Distributed Reflection DoS, 분산 반사 서비스 거부)**: 출발지 IP를 **희생자 IP로 위조**해서 정상 서버들(DNS, NTP, 웹 서버 등 = **반사체, Reflector**)에 요청을 보냄 → 그 서버들의 **응답이 모두 희생자에게** 몰림. 작은 요청으로 큰 응답을 끌어내면 **증폭(Amplification)** 공격이 됨. 좀비 PC를 감염시킬 필요가 없고 추적이 어렵다.

### 3-2. 주요 DoS 공격 정리 (★ 최빈출)

| 공격 | 원리 | 핵심 키워드 | 대응 |
|---|---|---|---|
| **SYN Flooding** | TCP 3-way handshake에서 **SYN만 대량으로** 보내고 마지막 ACK를 보내지 않음 → 서버는 SYN/ACK를 보낸 뒤 **반쯤 열린(Half-Open) 연결**로 대기 → **백로그 큐(Backlog Queue)** 가 가득 차 새 연결 불가 | SYN, Half-Open, 백로그 큐 | **SYN 쿠키**, 백로그 큐 크기 증가, 대기 타임아웃 단축, 방화벽/IPS의 SYN 임계치 차단 |
| **UDP Flooding** | 대량의 UDP 패킷을 임의 포트로 전송 → 희생자는 ICMP Destination Unreachable 응답을 만드느라 자원·대역폭 소모 | UDP, 대역폭 고갈 | 불필요한 UDP 서비스 차단, 대역폭 제한 |
| **ICMP Flooding** | ICMP Echo Request(ping)를 대량 전송 | ping 폭주 | ICMP 응답 제한 |
| **Smurf** | 출발지 IP를 **희생자 IP로 위조**한 **ICMP Echo Request**를 네트워크의 **브로드캐스트 주소**로 전송 → 그 네트워크의 모든 호스트가 **Echo Reply를 희생자에게** 보냄 | ICMP + **Directed Broadcast** + 출발지 위조 | 라우터에서 **Directed Broadcast 차단**(Cisco: `no ip directed-broadcast`), 브로드캐스트 ICMP 무응답 설정 |
| **Ping of Death** | IP 패킷 최대 크기(**65,535바이트**)를 **초과**하는 ICMP 패킷을 보냄 → 잘게 단편화된 조각을 재조립하다 버퍼 오버플로·시스템 다운 | 비정상적으로 **큰** ICMP | OS 패치, 큰 ICMP 차단 |
| **Land Attack** | **출발지 IP = 목적지 IP (희생자 자신)** 로 위조한 패킷 전송 → 시스템이 자기 자신에게 응답하며 **무한 루프**, 자원 고갈 | 출발지 = 목적지 | 출발지·목적지가 같은 패킷 필터링, OS 패치 |
| **Teardrop** | IP **단편화(Fragmentation)의 오프셋(Fragment Offset) 값을 겹치거나 틈이 나게 조작** → 재조립(Reassembly) 과정에서 오류·다운 | **Fragment Offset** 조작 | OS 패치 |
| **Bonk / Boink** | Teardrop 변형 (UDP 단편 오프셋 조작 등) | 단편 재조립 오류 | OS 패치 |
| **HTTP GET Flooding** | 정상적인 HTTP GET 요청을 **대량**으로 보내 웹 서버·DB 부하 → 정상 요청과 구분이 어려움 (7계층 공격) | 7계층, 정상 요청처럼 보임 | 요청 임계치 제한, 캡차, WAF/DDoS 대응 장비 |
| **Slowloris (Slow HTTP Header DoS)** | HTTP **헤더를 끝내지 않고 아주 천천히** 조금씩 보내 연결을 **오래 붙잡아** 웹 서버의 동시 연결 수를 고갈 | 적은 트래픽으로 연결 고갈, 헤더 미완성 | 연결 타임아웃 단축, 동시 연결 수 제한 |
| **Slow HTTP POST (RUDY)** | POST 본문을 매우 천천히 전송 | 느린 본문 | 타임아웃 설정 |

**Smurf vs Land vs Ping of Death 한 번에 구분하기**
- 출발지 = **희생자**, 목적지 = **브로드캐스트** → **Smurf**
- 출발지 = 목적지 = **희생자 자신** → **Land**
- 크기가 **65,535바이트 초과** → **Ping of Death**
- **오프셋**이 이상함 → **Teardrop**

> 💡 시험 포인트: 공격 설명 주고 이름 고르기(특히 Smurf·Land·Teardrop·SYN Flooding), "SYN Flooding 대응책이 아닌 것", "DDoS 구성요소(마스터·에이전트)" 순으로 자주 나온다.

## 4. 스니핑 · 스푸핑 · 세션 하이재킹 · 중간자 공격

### 4-1. 스니핑 (Sniffing) — "엿듣기"

- 네트워크를 지나가는 패킷을 **몰래 엿보는 수동적 공격** → **기밀성** 침해.
- 일반 NIC(랜카드)는 **목적지 MAC이 자기 것인 프레임만** 받는다. 스니핑을 하려면 NIC를 **무차별 모드(Promiscuous Mode)** 로 설정해 **자기에게 오지 않은 패킷까지 모두** 받는다.
- 허브 환경(모든 포트로 전달)은 스니핑이 쉽고, 스위치 환경은 포트별로 전달되므로 공격자가 **ARP 스푸핑, 스위치 재밍(MAC Flooding), ICMP Redirect, 포트 미러링(SPAN) 악용** 등을 먼저 해야 한다.
  - **스위치 재밍(MAC Flooding)**: 가짜 MAC 주소를 대량으로 보내 스위치의 MAC 주소 테이블을 가득 채워, 스위치가 허브처럼 모든 포트로 프레임을 내보내게(Fail-Open) 만듦.
- 대표 도구: tcpdump, Wireshark(패킷 분석 도구 자체는 정상 관리 도구)
- **대응**: **암호화**(SSH, HTTPS, VPN), 스위치 사용, 무차별 모드 NIC 탐지

### 4-2. 스푸핑 (Spoofing) — "속이기(위장)"

| 종류 | 위조 대상 | 방법 | 대응 |
|---|---|---|---|
| **IP 스푸핑** | IP 주소 | 출발지 IP를 신뢰받는 호스트 IP로 위조 (트러스트 관계 악용, rlogin 등) | 트러스트 관계 제거, 라우터에서 출발지 IP 검증(Ingress/Egress 필터링) |
| **ARP 스푸핑** | **MAC 주소** (IP↔MAC 매핑) | 위조된 **ARP Reply**를 계속 보내 "게이트웨이 IP의 MAC = 공격자 MAC"이라고 속임 → 피해자의 **ARP 캐시 테이블 오염**, 트래픽이 공격자를 거쳐 감 | 중요 호스트·게이트웨이의 ARP 항목을 **정적(Static)** 으로 설정, ARP 감시 도구 |
| **DNS 스푸핑** | 도메인 ↔ IP 매핑 | 위조 DNS 응답을 먼저 보내거나 **DNS 서버 캐시를 오염**(DNS Cache Poisoning)시켜 정상 도메인을 **가짜 IP**로 연결 | DNSSEC, 중요 사이트 hosts 파일 고정 |
| **MAC 스푸핑** | 자신의 MAC 주소 | NIC의 MAC을 다른 장비 MAC으로 바꿔 MAC 필터링 우회 | 포트 보안(Port Security), 802.1X |
| **이메일 스푸핑** | 보낸 사람 주소 | 발신자 주소 위조 | SPF, DKIM 등 발신 인증 |

- ARP 스푸핑은 ARP가 브로드캐스트를 쓰므로 **같은 LAN(같은 브로드캐스트 도메인)** 안에서만 가능.
- ARP 스푸핑 → 공격자가 중간에서 패킷을 보고 다시 넘겨주면(IP 포워딩) 피해자는 눈치채기 어렵다 → **중간자 공격(MITM)** 으로 이어짐.

### 4-3. 세션 하이재킹 (Session Hijacking)

- 이미 **인증이 끝난 정상 세션을 가로채는** 공격. 인증 절차를 다시 거치지 않으므로 OTP 같은 강한 인증도 무력화될 수 있다.
- **TCP 세션 하이재킹**: TCP의 **시퀀스 번호(Sequence Number)** 를 추측·탈취하여 **비동기화 상태(Desynchronized)** 를 만든 뒤 공격자가 정상 사용자 대신 통신. 이 과정에서 ACK가 계속 오가는 **ACK Storm** 현상이 나타남.
- **웹 세션 하이재킹**: 쿠키·세션 ID를 탈취(예: XSS로 쿠키 탈취)하여 그 사용자로 로그인된 상태를 이용.
- **대응**: 암호화 통신(SSH, HTTPS), 세션 ID 재발급·만료 시간 설정, 비정상 ACK 폭주 탐지

### 4-4. 중간자 공격 (MITM, Man-In-The-Middle)

- 통신하는 두 당사자 사이에 끼어들어 **양쪽 모두에게 상대방인 척**하면서 내용을 엿보거나 바꾸는 공격.
- 수단: ARP 스푸핑, DNS 스푸핑, 가짜 AP(Evil Twin), Diffie-Hellman 키 교환에 끼어들기
- **대응**: 상호 인증, **인증서(PKI) 기반 TLS**, 인증서 경고 무시하지 않기

> 💡 시험 포인트: "자기에게 오지 않은 패킷도 받는 NIC 모드 = **Promiscuous(무차별) 모드**", "ARP 캐시 오염 = ARP 스푸핑 → 대응은 **정적 ARP**", "DNS 캐시 오염 = DNS 스푸핑", "시퀀스 번호 = TCP 세션 하이재킹".

## 5. 사회공학 공격 (Social Engineering)

기술의 허점이 아니라 **사람의 심리(신뢰, 호기심, 공포)** 를 이용하는 공격. 이름의 앞글자가 **수단**을 알려 준다.

| 공격 | 유래 | 수단 | 설명 |
|---|---|---|---|
| **피싱 (Phishing)** | Private data + Fishing | 이메일·메시지의 **가짜 링크** | 금융기관 등을 사칭한 메일로 가짜 사이트에 끌어들여 개인정보를 입력하게 함 |
| **스피어 피싱 (Spear Phishing)** | 작살(Spear) | **특정 대상 맞춤형** 메일 | 특정 조직·개인을 노려 신뢰할 만한 내용으로 위장 |
| **웨일링 (Whaling)** | 고래 | 경영진 대상 | CEO 등 고위직을 노린 스피어 피싱 |
| **파밍 (Pharming)** | Phishing + Farming | **hosts 파일·DNS 변조** | 사용자가 **정확한 도메인 주소를 입력해도** 가짜 사이트로 접속됨 (피싱보다 한 단계 진화) |
| **스미싱 (Smishing)** | **SMS** + Phishing | 문자 메시지 | 문자 속 링크 클릭 → 악성 앱 설치, 소액결제 |
| **비싱 (Vishing)** | **Voice** + Phishing | 전화(음성) | 보이스피싱 |
| **큐싱 (Qshing)** | **QR** 코드 + Phishing | QR 코드 | QR 코드로 악성 사이트·앱 유도 |
| **메모리 해킹** | - | 악성코드 | PC 메모리의 계좌번호·금액을 실시간 변조 |
| **어깨너머 훔쳐보기 (Shoulder Surfing)** | - | 직접 관찰 | 비밀번호 입력을 옆에서 엿봄 |
| **쓰레기통 뒤지기 (Dumpster Diving)** | - | 폐기 문서 | 버린 문서에서 정보 획득 |

> 💡 시험 포인트: "주소를 정확히 입력해도 가짜 사이트 = **파밍**" (피싱과 구분!), "SMS = 스미싱, Voice = 비싱, QR = 큐싱".

## 6. 웹 · 애플리케이션 공격

### 6-1. SQL 삽입 (SQL Injection)

- 웹의 입력값(로그인 창, 검색창, URL 파라미터)에 **SQL 문을 끼워 넣어** DB를 조작하는 공격.
- 대표 예: 로그인 비밀번호 칸에 `' OR '1'='1` 입력
  ```sql
  SELECT * FROM users WHERE id='admin' AND pw='' OR '1'='1';
  -- '1'='1'은 항상 참 → 비밀번호 없이 로그인 성공
  ```
- **주석 기호**(`--`, `#`)로 뒷부분 조건을 무력화하기도 함.
- **대응**: **입력값 검증(특수문자 필터링)**, **Prepared Statement(매개변수화 쿼리)** 사용, DB 계정 최소 권한, 상세 오류 메시지 노출 금지, WAF

### 6-2. 크로스 사이트 스크립팅 (XSS, Cross-Site Scripting)

- 게시판 등에 **악성 스크립트(JavaScript)** 를 삽입 → **다른 사용자의 브라우저**에서 실행되어 **쿠키·세션 탈취**, 악성 사이트 리다이렉트.
- 공격 대상이 서버가 아니라 **그 페이지를 보는 사용자(클라이언트)**.
- 유형
  - **저장형(Stored)**: 게시글에 스크립트를 저장 → 글을 열람하는 모든 사용자 피해
  - **반사형(Reflected)**: 스크립트가 담긴 URL을 클릭하게 유도 → 서버 응답에 반사되어 실행
  - **DOM 기반**: 클라이언트 측 스크립트(DOM) 조작
- **대응**: 입력값 검증, `<`, `>` 등 **HTML 특수문자 이스케이프(치환)**, 쿠키에 HttpOnly 설정

### 6-3. 크로스 사이트 요청 위조 (CSRF, Cross-Site Request Forgery)

- **로그인된 사용자**가 공격자가 만든 링크·이미지를 열면, **사용자 본인의 권한으로** 의도하지 않은 요청(비밀번호 변경, 송금, 글 작성)이 서버에 전송되는 공격.
- XSS와의 차이: XSS는 **사용자 브라우저에서 스크립트가 실행**되는 것이 핵심, CSRF는 **서버가 사용자의 정상 요청으로 착각**하고 처리하는 것이 핵심.
- **대응**: CSRF 토큰(요청마다 난수 값 검증), 중요 기능 재인증, Referer 검증

### 6-4. 디렉터리 트래버설 (Directory Traversal / Path Traversal)

- URL·파일 경로 파라미터에 `../` 를 넣어 웹 루트 **밖의 파일**(예: `/etc/passwd`)에 접근.
- 예: `http://site/view?file=../../../../etc/passwd`
- **대응**: `../` 등 경로 문자 필터링, 접근 가능한 디렉터리 제한

### 6-5. 버퍼 오버플로 (Buffer Overflow)

- 프로그램이 정해진 **버퍼(메모리) 크기보다 큰 데이터**를 입력받을 때 경계 검사를 하지 않아 옆 메모리(특히 **스택의 복귀 주소, Return Address**)를 덮어쓰고 공격자 코드를 실행시키는 공격.
- 종류: 스택 버퍼 오버플로, 힙 버퍼 오버플로
- 취약 함수(C언어): `strcpy`, `strcat`, `gets`, `sprintf` → 안전 함수 `strncpy`, `strncat`, `fgets`, `snprintf` 사용
- **대응**: 입력 길이 경계 검사, 안전한 함수 사용, **스택 가드(카나리, Canary)**, **ASLR**(메모리 주소 무작위화), **DEP/NX**(데이터 영역 실행 금지)

> 💡 시험 포인트: `' OR '1'='1` → SQL Injection / 게시판 스크립트·쿠키 탈취 → XSS / "사용자 권한으로 원치 않는 요청" → CSRF / `../` → 디렉터리 트래버설 / 복귀 주소 덮어쓰기 → 버퍼 오버플로.

## 7. 패스워드 공격 · 스캐닝 · APT · 제로데이

### 7-1. 패스워드 공격

| 공격 | 설명 |
|---|---|
| **무차별 대입 (Brute Force)** | 가능한 **모든 조합**을 하나씩 대입. 시간은 오래 걸리지만 결국 성공할 수 있음 |
| **사전 공격 (Dictionary Attack)** | 자주 쓰는 단어·비밀번호 **목록(사전 파일)** 을 대입. 빠르지만 사전에 없으면 실패 |
| **레인보우 테이블 (Rainbow Table)** | 평문과 그 **해시값을 미리 계산해 둔 거대한 테이블**로 해시 → 평문을 빠르게 역추적 |
| **크리덴셜 스터핑 (Credential Stuffing)** | 다른 사이트에서 유출된 ID/비밀번호를 그대로 대입 (재사용 노림) |

- **솔트 (Salt)**: 비밀번호를 해시할 때 **사용자마다 다른 무작위 값**을 붙여서 해시 → 같은 비밀번호라도 해시값이 달라짐 → **레인보우 테이블을 무력화**.
- **키 스트레칭 (Key Stretching)**: 해시를 수천~수만 번 반복해 계산 비용을 높임 (PBKDF2, bcrypt, scrypt).
- 대응: 복잡한 비밀번호 정책, **로그인 실패 횟수 제한(계정 잠금)**, 다중 인증(MFA)

### 7-2. 포트 스캐닝 (Port Scanning)

- 공격 전 정보 수집 단계에서 대상 호스트의 **열린 포트·실행 중인 서비스·OS**를 알아내는 작업. 대표 도구: **nmap**.
- 주요 TCP 스캔 방식

| 스캔 | 보내는 플래그 | 포트가 **열려 있으면** | 포트가 **닫혀 있으면** | 특징 |
|---|---|---|---|---|
| **TCP Connect (Open) 스캔** | SYN → 3-way handshake 완료 | SYN/ACK 수신 후 연결 완료 | RST/ACK | 가장 확실하지만 **로그가 남음** |
| **SYN (Half-Open) 스캔** | SYN | SYN/ACK 수신 → 공격자가 **RST**로 끊음 | RST/ACK | 연결을 완성하지 않아 **로그가 덜 남음** (스텔스 스캔) |
| **FIN 스캔** | FIN | **응답 없음** | RST | 스텔스 스캔 |
| **Xmas 스캔** | **FIN + PSH + URG** (크리스마스 트리처럼 여러 플래그) | **응답 없음** | RST | 스텔스 스캔 |
| **NULL 스캔** | **플래그 없음** | **응답 없음** | RST | 스텔스 스캔 |
| **UDP 스캔** | UDP 패킷 | 응답 없음(또는 UDP 응답) | ICMP Port Unreachable | 느림 |

> FIN/Xmas/NULL 스캔은 "열린 포트는 **무응답**, 닫힌 포트는 **RST**" 로 외운다.

### 7-3. APT와 제로데이

- **APT (Advanced Persistent Threat, 지능형 지속 위협)**: **특정 조직**을 목표로 정해 사회공학(스피어 피싱)·제로데이 등 다양한 수단으로 침투한 뒤, **오랜 기간 은밀하게 잠복**하며 정보를 빼내는 공격. "Advanced(지능적) + Persistent(지속적)".
- **제로데이 공격 (Zero-Day Attack)**: 소프트웨어 취약점이 발견됐지만 **보안 패치가 나오기 전**(또는 공개 전)에 그 취약점을 이용하는 공격. 시그니처가 없어 **오용 탐지로는 잡기 어려움**.

> 💡 시험 포인트: "레인보우 테이블 대응 = **솔트**", "특정 대상·장기간 잠복 = **APT**", "패치 전 취약점 = **제로데이**", "플래그 없음 = NULL 스캔, FIN+PSH+URG = Xmas 스캔".

## 8. 방화벽 (Firewall)

### 8-1. 방화벽이란

- 내부 네트워크와 외부 네트워크 사이에서 **미리 정한 보안 정책(규칙)** 에 따라 트래픽을 **허용(Allow)/차단(Deny)** 하는 시스템.
- 기본 정책 원칙: **"명시적으로 허용한 것 외에는 모두 차단(Default Deny)"** 이 더 안전하다.
- 주요 기능: 접근 통제(ACL), 사용자 인증, 감사·로그, NAT(내부 주소 은닉)
- **한계**: 
  - 내부자 공격은 막기 어려움
  - 방화벽을 **우회**하는 경로(무단 모뎀, 무선 AP)는 막지 못함
  - 허용된 포트로 들어오는 **바이러스·악성코드 내용까지 검사하기는 어려움**(기본 패킷 필터링의 경우)
  - 새로운 형태의 공격 탐지에 한계

### 8-2. 방화벽 종류 (동작 방식에 따른 분류)

| 종류 | 동작 계층 | 원리 | 장점 | 단점 |
|---|---|---|---|---|
| **패킷 필터링 (Packet Filtering)** | 3~4계층 (네트워크·전송) | IP 헤더·TCP/UDP 헤더의 **출발지/목적지 IP, 포트, 프로토콜**만 보고 ACL로 판단 | **빠름**, 투명성(사용자가 의식 못 함), 저비용 | 데이터 내용(페이로드) 검사 불가, IP 스푸핑에 취약, 로그 기능 약함 |
| **상태 검사 (Stateful Inspection)** | 3~4계층 + 세션 상태 | 패킷 필터링 + **세션(연결) 상태 테이블**을 유지하며 연결 흐름이 정상인지 확인 | 패킷 필터링보다 안전하면서 빠름 → 현재 방화벽의 기본 | 상태 테이블 공격(테이블 고갈)에 부담 |
| **애플리케이션 게이트웨이 (Application Gateway, 프록시 방화벽)** | **7계층 (응용)** | 서비스별 **프록시(Proxy) 데몬**이 연결을 대신 받아 **데이터 내용까지** 검사 | 가장 세밀한 통제, **사용자 인증**, **상세 로그**·감사 가능, 내부 구조 은닉 | **처리 속도 느림**, 서비스마다 프록시 필요, 유연성 낮음 |
| **서킷 게이트웨이 (Circuit Gateway)** | **5계층(세션)** ~ 7계층 사이 | 하나의 **일반(대표) 프록시**가 세션 연결을 중계 (예: SOCKS) | 서비스별 프록시 불필요 | 클라이언트에 전용 프로그램/설정 필요 |
| **하이브리드** | - | 패킷 필터링 + 애플리케이션 게이트웨이 혼합 | 유연한 정책 | 관리 복잡 |

### 8-3. 방화벽 구축 형태 (아키텍처) ★

먼저 알아 둘 용어 두 가지:
- **스크리닝 라우터 (Screening Router)**: 패킷 필터링 기능을 가진 라우터
- **배스천 호스트 (Bastion Host)**: 외부에 노출되어 공격을 정면으로 받는, **보안을 철저히 강화한 호스트**(프록시 서버 역할). "성의 돌출된 방어 요새"라는 뜻.

| 구축 형태 | 구성 | 특징 |
|---|---|---|
| **스크리닝 라우터** | 라우터 1대(패킷 필터링)만 | 구축 쉽고 저렴, 보안 수준 낮음, 로그 약함 |
| **배스천 호스트** | 배스천 호스트 1대 | 애플리케이션 수준 통제, 호스트가 뚫리면 내부 전체 노출 |
| **듀얼 홈드 게이트웨이 (Dual-Homed Gateway)** | **NIC 2개**를 가진 배스천 호스트가 외부·내부를 직접 분리 | 내부·외부 사이 **직접 라우팅 차단**(IP 포워딩 금지), 프록시로만 통신 |
| **스크린드 호스트 게이트웨이 (Screened Host Gateway)** | **스크리닝 라우터 + 배스천 호스트** | 1차로 라우터가 패킷 필터링, 2차로 배스천 호스트가 애플리케이션 수준 검사 → 2단계 방어. 라우터가 뚫리면 위험 |
| **스크린드 서브넷 게이트웨이 (Screened Subnet Gateway)** | **외부 스크리닝 라우터 – [DMZ: 배스천 호스트] – 내부 스크리닝 라우터** | 두 라우터 사이에 **완충 지대 서브넷(DMZ)** 을 둠 → **가장 안전**, 대신 **구축 비용 높고 복잡, 속도 느림** |

**DMZ (DeMilitarized Zone, 비무장지대)**
- 외부에서 접근해야 하는 공개 서버(**웹 서버, 메일 서버, DNS 서버**)를 두는 **완충 구역**.
- 외부 → DMZ 접근은 허용, 외부 → 내부망 직접 접근은 차단. DMZ 서버가 해킹당해도 내부망은 보호.

> 💡 시험 포인트: "7계층·프록시·사용자 인증·로그 우수·느림 = **애플리케이션 게이트웨이**", "두 라우터 사이 DMZ·가장 안전·비싸고 복잡 = **스크린드 서브넷**", "NIC 2개 = **듀얼 홈드**", "라우터 + 배스천 호스트 = **스크린드 호스트**".

## 9. 침입 탐지·차단 및 통합 보안 솔루션

### 9-1. IDS (Intrusion Detection System, 침입 탐지 시스템)

- 네트워크·시스템을 감시하다가 침입이나 이상 징후를 **탐지하고 경보(Alert)** 를 울리는 시스템. 기본적으로 **탐지·알림 중심**이고 직접 차단은 하지 않는다(미러링된 트래픽을 보는 **Out-of-Path** 구성).
- 동작 단계: **데이터 수집 → 데이터 가공·필터링 → 분석·탐지 → 보고·대응**

**데이터 수집 위치에 따른 분류**

| 구분 | HIDS (호스트 기반) | NIDS (네트워크 기반) |
|---|---|---|
| 설치 위치 | 개별 서버·PC에 설치 | 네트워크 세그먼트(스위치 미러 포트 등) |
| 감시 대상 | 시스템 로그, 파일 변경, 프로세스, 사용자 행위 | 네트워크를 지나가는 패킷 |
| 장점 | 암호화된 통신도 호스트에서 복호화 후 확인 가능, 공격 성공 여부 파악 쉬움, 내부자 행위 감시 | 하나로 네트워크 전체 감시, 호스트 자원 사용 안 함, 운영체제와 무관 |
| 단점 | 호스트마다 설치, 호스트 자원 소모 | **암호화된 패킷 내용 분석 어려움**, 고속망에서 패킷 누락 가능 |

**탐지 방법에 따른 분류 (★ 최빈출 비교)**

| 구분 | **오용 탐지 (Misuse Detection)** | **이상 탐지 (Anomaly Detection)** |
|---|---|---|
| 다른 이름 | **시그니처(Signature) 기반**, 지식 기반, 규칙 기반 | **행위(Behavior) 기반**, 통계 기반, 프로파일 기반 |
| 원리 | 이미 알려진 **공격 패턴(시그니처) DB**와 비교 | **정상 행위 프로파일(기준선)** 을 만들어 두고 그것에서 **벗어나면** 탐지 |
| 새로운 공격 (제로데이) | **탐지 어려움** (시그니처 업데이트 필요) | **탐지 가능** |
| 오탐(False Positive) | **낮음** | **높음** |
| 예 | 백신, 패턴 매칭 | 통계 분석, 머신러닝, 전문가 시스템 |

**오탐과 미탐**
- **오탐 (False Positive, 긍정 오류)**: **정상**을 공격이라고 잘못 판단 → 불필요한 경보 남발
- **미탐 (False Negative, 부정 오류)**: **실제 공격**을 정상이라고 놓침 → **보안상 더 위험**

### 9-2. IPS (Intrusion Prevention System, 침입 방지 시스템)

- IDS의 탐지 기능 + **실시간 차단** 기능. 트래픽이 지나가는 경로에 **직접(In-line)** 설치되어 공격 패킷을 **능동적으로 차단**.
- IDS = 감시 카메라(보고 알림) / IPS = 경비원(보고 막음)
- 단점: 인라인이므로 장비 장애나 오탐 시 **정상 트래픽까지 막힐** 수 있음.

### 9-3. 그 밖의 보안 솔루션

| 솔루션 | 설명 |
|---|---|
| **UTM (Unified Threat Management, 통합 위협 관리)** | 방화벽 + IDS/IPS + VPN + 안티바이러스 + 콘텐츠 필터링 등을 **하나의 장비**에 통합. 관리 편리·비용 절감, 대신 장비 하나에 부하·장애 집중 |
| **ESM (Enterprise Security Management, 통합 보안 관리)** | 방화벽·IDS·IPS·VPN 등 **여러 보안 장비의 로그·이벤트를 한 곳에서 통합 관리·분석** |
| **SIEM (Security Information & Event Management)** | ESM의 발전형. 보안 장비뿐 아니라 서버·네트워크 장비 등 **방대한 로그를 수집·상관 분석**(빅데이터 기반)하여 위협 탐지 |
| **NAC (Network Access Control, 네트워크 접근 제어)** | 단말이 내부망에 **접속하기 전에** 사용자 인증 + **보안 정책 준수 여부**(백신 설치·업데이트, OS 패치 등)를 검사해 미준수 단말은 격리·차단 |
| **DLP (Data Loss Prevention, 데이터 유출 방지)** | 기업 내부의 **중요 정보·개인정보가 외부로 유출**(메일, USB, 메신저, 출력)되는 것을 탐지·차단 |
| **WAF (Web Application Firewall, 웹 방화벽)** | **웹(HTTP/HTTPS) 트래픽**을 7계층에서 분석하여 SQL Injection, XSS, 파일 업로드 공격 등 **웹 공격을 차단** |
| **허니팟 (Honeypot)** | 일부러 취약하게 보이게 만든 **유인용(미끼) 시스템**. 공격자를 끌어들여 **공격 기법을 관찰·분석**하고 실제 시스템에서 주의를 돌림. 여러 개를 묶으면 **허니넷(Honeynet)** |
| **안티바이러스 (백신)** | 악성코드를 시그니처 기반으로 탐지·치료 |
| **TMS (Threat Management System)** | 위협 정보를 수집·분석해 위험 수준을 예측·관리 |

> 💡 시험 포인트: "새로운 공격 탐지 가능·오탐 높음 = **이상 탐지**", "알려진 패턴 DB = **오용 탐지**", "탐지 + 실시간 차단 = **IPS**", "여러 보안 기능을 장비 하나에 = **UTM**", "여러 보안 장비 로그 통합 관리 = **ESM**", "접속 전 단말 보안 상태 검사 = **NAC**", "유인용 미끼 = **허니팟**".

## 10. VPN (Virtual Private Network, 가상 사설망)

### 10-1. 개념

- 인터넷 같은 **공중망(Public Network)** 위에 **암호화된 터널**을 만들어 **전용선(사설망)처럼** 안전하게 쓰는 기술.
- 장점: 전용선 대비 **비용 절감**, 원격 근무자·지사 연결이 쉬움, 확장성
- 핵심 기술 4가지: **터널링(Tunneling)**, **암호화**, **인증**, **접근 통제(+키 관리)**
- 형태: Site-to-Site(본사↔지사, 게이트웨이 간), Remote Access(원격 사용자↔본사)

### 10-2. 계층별 VPN 프로토콜

| 계층 | 프로토콜 | 특징 |
|---|---|---|
| **2계층 (데이터링크)** | **PPTP** (Point-to-Point Tunneling Protocol) | **마이크로소프트** 주도, PPP 기반, 주로 원격 접속용. 보안 약함 |
| | **L2F** (Layer 2 Forwarding) | **시스코** 개발 |
| | **L2TP** (Layer 2 Tunneling Protocol) | **PPTP + L2F 결합**. **자체 암호화 기능이 없어** 보통 **IPSec과 함께(L2TP/IPSec)** 사용 |
| **3계층 (네트워크)** | **IPSec** | IP 계층에서 패킷 단위 암호화·인증. 상위 응용과 무관하게 모든 트래픽 보호. 주로 Site-to-Site |
| **4~7계층** | **SSL/TLS VPN** | **웹 브라우저**만으로 접속 가능 → **별도 클라이언트 설치가 필요 없음**(또는 경량), 원격 접속에 편리, 응용 단위 접근 통제 |

### 10-3. IPSec 상세 ★

**구성 프로토콜**

| 프로토콜 | 제공 기능 | 암호화(기밀성) |
|---|---|---|
| **AH (Authentication Header)** | **무결성 + 데이터 출처 인증 + 재전송 공격 방지** | **제공하지 않음** ✕ |
| **ESP (Encapsulating Security Payload)** | **기밀성(암호화)** + 무결성 + 인증 + 재전송 방지 | **제공** ○ |
| **IKE (Internet Key Exchange)** | 통신 양쪽이 사용할 **암호 키를 교환하고 SA(Security Association, 보안 연관)를 협상·수립** | - (ISAKMP 프레임워크 + Diffie-Hellman 기반) |

> 외우기: **AH는 "A"uthentication(인증)만, 암호화는 ESP만.**

**동작 모드**

| 모드 | 보호 범위 | IP 헤더 | 주 용도 |
|---|---|---|---|
| **전송 모드 (Transport Mode)** | IP 패킷의 **페이로드(데이터)만** 보호 | **원래 IP 헤더 그대로** 사용 | **호스트 ↔ 호스트**(종단 간) |
| **터널 모드 (Tunnel Mode)** | **원래 IP 헤더를 포함한 패킷 전체**를 보호(캡슐화) | **새로운 IP 헤더**를 앞에 추가 | **게이트웨이 ↔ 게이트웨이**(VPN 장비 간, Site-to-Site) |

> 💡 시험 포인트: "AH는 암호화 기능 없음", "터널 모드 = 패킷 전체 + 새 IP 헤더", "L2TP = PPTP + L2F, 자체 암호화 없음", "IPSec = 3계층", "SSL VPN = 브라우저만으로 접속".

## 11. 암호 기술

### 11-1. 기본 용어

- **평문(Plaintext)**: 원래 메시지 / **암호문(Ciphertext)**: 암호화된 메시지
- **암호화(Encryption)**: 평문 → 암호문 / **복호화(Decryption)**: 암호문 → 평문
- **키(Key)**: 암호화·복호화에 쓰는 비밀 값. 키 길이가 길수록 무차별 대입에 강함.
- 고전 암호 원리: **치환(Substitution, 글자를 다른 글자로 바꿈)**, **전치(Transposition, 글자 위치를 섞음)**

### 11-2. 대칭키 vs 비대칭키 ★

| 구분 | **대칭키 (비밀키, Symmetric)** | **비대칭키 (공개키, Asymmetric)** |
|---|---|---|
| 키 | 암호화 키 = 복호화 키 (**같은 키 1개** 공유) | **공개키(Public Key)** + **개인키(Private Key)** 쌍 |
| 속도 | **빠름** | **느림** (복잡한 수학 연산) |
| 키 배송(분배) 문제 | 있음 (키를 안전하게 전달하기 어려움) | 없음 (공개키는 공개해도 됨) |
| **n명이 서로 통신할 때 필요한 키 수** | **n(n−1)/2 개** | **2n 개** (각자 공개키 1 + 개인키 1) |
| 주 용도 | **대용량 데이터 암호화** | 키 교환, **전자서명**, 인증 |
| 대표 알고리즘 | DES, 3DES, AES, SEED, ARIA, IDEA, RC4 | RSA, ECC, Diffie-Hellman, ElGamal, DSA |

**키 개수 계산 예**
- 10명: 대칭키 = 10×9/2 = **45개**, 비대칭키 = 2×10 = **20개**
- 100명: 대칭키 = 100×99/2 = **4,950개**, 비대칭키 = **200개**

**실무 방식 = 하이브리드**: 데이터는 빠른 **대칭키(세션 키)** 로 암호화하고, 그 세션 키를 **비대칭키**로 안전하게 전달 (SSL/TLS, PGP 등).

### 11-3. 대칭키 알고리즘

| 알고리즘 | 블록 크기 | 키 길이 | 특징 |
|---|---|---|---|
| **DES** | 64비트 | **56비트** (+8비트 패리티 = 64) | 미국 표준(1977), 16라운드 Feistel 구조. 키가 짧아 **현재는 취약** |
| **3DES (Triple DES)** | 64비트 | 112 / 168비트 | DES를 **3번** 적용해 보완. 느림 |
| **AES** | **128비트** | **128 / 192 / 256비트** | DES 후속 미국 표준(Rijndael), SPN 구조, 현재 가장 널리 쓰임 |
| **SEED** | 128비트 | 128비트 (256 버전도 있음) | **한국(KISA)** 개발 국내 표준 |
| **ARIA** | 128비트 | 128 / 192 / 256비트 | **한국(국가보안기술연구소 주도)** 개발 국가 표준 |
| **IDEA** | 64비트 | 128비트 | 스위스 개발, PGP에 사용 |
| **RC4** | - (스트림) | 가변 | 대표 **스트림 암호**, WEP·구 SSL에 사용, 현재 취약 |

**블록 암호 vs 스트림 암호**
- **블록 암호**: 평문을 **일정 크기 블록** 단위로 암호화 (DES, AES, SEED, ARIA)
- **스트림 암호**: 평문을 **비트/바이트 단위로** 키 스트림과 XOR (RC4, LFSR) → 빠름, 실시간 통신·무선에 유리

### 11-4. 비대칭키 알고리즘

| 알고리즘 | 기반 수학 문제 | 용도·특징 |
|---|---|---|
| **RSA** | **큰 수의 소인수분해**의 어려움 | 가장 대표적인 공개키 알고리즘, 암호화 + 전자서명 |
| **ECC (타원곡선 암호)** | 타원곡선 위 이산대수 문제 | RSA보다 **짧은 키로 같은 보안 강도** → 모바일·IoT에 유리 |
| **Diffie-Hellman (DH)** | **이산대수** 문제 | 최초의 공개키 방식, **키 교환(키 합의) 전용**. 인증 기능이 없어 **중간자 공격에 취약** |
| **ElGamal** | 이산대수 문제 | 암호화·전자서명 |
| **DSA** | 이산대수 문제 | **전자서명 전용** 표준(DSS) |

### 11-5. 해시 함수 (Hash Function)

- 임의 길이 입력 → **고정 길이 출력(해시값, 메시지 다이제스트)**.
- 특징: **일방향성**(해시값으로 원문을 알아낼 수 없음), **충돌 회피성**(서로 다른 입력이 같은 해시를 갖기 어려움), 입력이 1비트만 바뀌어도 결과가 완전히 달라짐(눈사태 효과)
- 용도: **무결성 검증**, 비밀번호 저장, 전자서명(메시지 대신 해시에 서명)
- 키를 쓰지 않는다(키를 쓰는 해시 기반 인증은 **HMAC**).

| 알고리즘 | 출력 길이 | 비고 |
|---|---|---|
| **MD5** | **128비트** | 충돌 발견, 보안용으로 부적합 |
| **SHA-1** | **160비트** | 충돌 발견, 사용 중단 권고 |
| **SHA-256** (SHA-2 계열) | **256비트** | 현재 표준적으로 사용 (SHA-224/384/512 포함) |
| **HAS-160** | 160비트 | 한국 표준 해시 |

### 11-6. 공개키로 "암호화"할 때 vs "서명"할 때 ★

| 목적 | 암호화(서명)에 쓰는 키 | 복호화(검증)에 쓰는 키 | 얻는 보안 효과 |
|---|---|---|---|
| **기밀성 (비밀 메시지 보내기)** | **수신자의 공개키** | **수신자의 개인키** | 수신자만 읽을 수 있음 |
| **전자서명 (내가 보냈다는 증명)** | **송신자의 개인키** | **송신자의 공개키** | **인증 + 무결성 + 부인 방지** |

> 외우기: "**비밀은 받는 사람 공개키로 잠그고, 서명은 보내는 사람 개인키로 찍는다.**"

**전자서명 과정**
1. 송신자가 메시지를 **해시**하여 다이제스트 생성
2. 다이제스트를 **송신자 개인키로 암호화** = 전자서명
3. 메시지 + 서명 전송
4. 수신자는 **송신자 공개키로 서명을 복호화** → 다이제스트 A
5. 받은 메시지를 직접 해시 → 다이제스트 B
6. A = B이면 **위·변조 없음 + 송신자 본인 확인**

전자서명의 조건: **위조 불가, 서명자 인증, 부인 방지, 변경 불가, 재사용 불가**
※ 전자서명만으로는 **기밀성은 보장되지 않는다**(메시지 자체는 암호화되지 않음).

### 11-7. PKI (Public Key Infrastructure, 공개키 기반 구조)

공개키가 정말 그 사람의 것인지 보증해 주는 체계다.

| 구성 요소 | 역할 |
|---|---|
| **CA (Certificate Authority, 인증기관)** | **인증서 발급·갱신·폐기**, 인증서에 CA의 전자서명. 신뢰의 중심 |
| **RA (Registration Authority, 등록기관)** | 사용자의 **신원 확인 및 등록**을 대행 (예: 은행 창구) |
| **인증서 (Certificate)** | 사용자 정보 + **공개키** + CA 서명. 표준 형식은 **X.509** |
| **디렉터리 (Repository)** | 인증서와 CRL을 저장·공개 (LDAP) |
| **CRL (Certificate Revocation List)** | **폐기된 인증서 목록** (주기적으로 갱신 → 실시간성 부족) |
| **OCSP (Online Certificate Status Protocol)** | 인증서 유효 여부를 **실시간으로** 조회하는 프로토콜 |

X.509 인증서 주요 필드: 버전, **일련번호**, 서명 알고리즘, **발급자(CA)**, **유효 기간**, **주체(사용자)**, **주체의 공개키**, CA의 서명
※ 인증서에 **개인키는 절대 포함되지 않는다.**

> 💡 시험 포인트: "대칭키 키 개수 n(n−1)/2", "비대칭 알고리즘 고르기(RSA·ECC)", "RSA = 소인수분해", "DES 키 56비트", "AES 키 128/192/256", "전자서명 = 송신자 개인키", "실시간 인증서 상태 확인 = OCSP", "폐기 목록 = CRL".

## 12. 인증과 접근 통제

### 12-1. 인증 요소 (Authentication Factor)

| 유형 | 의미 | 예 |
|---|---|---|
| **지식 기반 (Something you know)** | 알고 있는 것 | 비밀번호, PIN, 보안 질문 |
| **소유 기반 (Something you have)** | 가지고 있는 것 | OTP 토큰, 스마트카드, 공인/공동 인증서, 휴대폰 |
| **존재(생체) 기반 (Something you are)** | 신체 특징 | 지문, 홍채, 얼굴, 정맥 |
| **행위 기반 (Something you do)** | 행동 특징 | 서명 패턴, 음성, 걸음걸이, 키보드 타이핑 습관 |

- **2요소 인증(2FA) / 다중 요소 인증(MFA)**: **서로 다른 유형**의 인증 요소를 2개 이상 결합 (예: 비밀번호 + OTP). ※ 비밀번호 + 보안 질문은 둘 다 "지식 기반"이므로 2요소 인증이 아님.
- **OTP (One-Time Password)**: 매번 바뀌는 **일회용 비밀번호** → 비밀번호 재사용·재전송(Replay) 공격 방지. 방식: 시간 동기화, 이벤트(카운터) 동기화, 질의-응답(Challenge-Response)
- **SSO (Single Sign-On)**: **한 번 로그인**으로 여러 시스템을 추가 인증 없이 사용. 편리하지만 **그 계정 하나가 뚫리면 모든 시스템이 위험**(단일 실패 지점). 예: Kerberos, SAML

### 12-2. AAA 와 인증 서버

- **AAA**: **Authentication(인증)** – 누구인가 / **Authorization(인가, 권한 부여)** – 무엇을 할 수 있는가 / **Accounting(과금·계정 관리)** – 무엇을 얼마나 했는가(기록)

| 구분 | **RADIUS** | **TACACS+** |
|---|---|---|
| 개발 | IETF 표준 | **시스코** |
| 전송 프로토콜 | **UDP** | **TCP** |
| 암호화 범위 | **비밀번호만** 암호화 | **패킷 전체(페이로드)** 암호화 |
| 인증·인가 | 인증과 인가를 **결합** | 인증·인가·과금을 **분리** |
| 주 용도 | 네트워크 접속 인증(무선 802.1X, ISP 등) | 네트워크 장비 관리자 접근 제어 |

### 12-3. Kerberos (커베로스)

- **MIT**에서 개발한 **티켓(Ticket) 기반** 인증 프로토콜, **대칭키** 암호 사용.
- 신뢰할 수 있는 제3자인 **KDC (Key Distribution Center)** 가 중심이며 KDC = **AS (Authentication Server, 인증 서버) + TGS (Ticket Granting Server, 티켓 발급 서버)**.
- 흐름: 사용자 → AS에서 **TGT(Ticket Granting Ticket)** 발급 → TGT를 TGS에 제시해 **서비스 티켓** 발급 → 서비스 티켓으로 서버 이용
- **타임스탬프**를 사용해 **재전송 공격 방지** → 모든 시스템의 **시간 동기화**가 필요.
- **SSO** 구현에 사용되며, Windows **Active Directory의 기본 인증 프로토콜**이기도 하다.
- 단점: KDC가 **단일 실패 지점**, KDC가 뚫리면 전체 위험.

### 12-4. 접근 통제 모델

| 모델 | 이름 | 누가 권한을 결정? | 특징 |
|---|---|---|---|
| **DAC** | 임의적 접근 통제 (Discretionary) | **자원의 소유자**가 재량으로 | 신분(ID) 기반, **ACL** 사용, 유연함. 유닉스/윈도우 파일 권한이 대표 예 |
| **MAC** | 강제적 접근 통제 (Mandatory) | **시스템(관리자)이 정한 보안 등급(레이블)** | 주체의 **보안 허가 등급**과 객체의 **비밀 등급**을 비교. 군·정부 기관, 매우 엄격 |
| **RBAC** | 역할 기반 접근 통제 (Role-Based) | **역할(직무)** 에 권한 부여 | 사용자에게 역할을 할당 → 인사 이동이 잦은 기업에 적합, 관리 편리 |

※ 여기서 MAC은 **Mandatory Access Control**이다. (MAC 주소, 메시지 인증 코드 MAC과 이름만 같음 — 문맥으로 구분)

**접근 통제 원칙**
- **최소 권한의 원칙 (Least Privilege)**: 업무에 **꼭 필요한 최소한의 권한만** 부여
- **직무 분리 (Separation of Duties)**: 하나의 중요한 업무를 여러 사람에게 나눠 부정 방지
- **알 필요성 (Need to Know)**: 알아야 할 정보만 접근

> 💡 시험 포인트: "티켓·KDC·TGT·타임스탬프 = **Kerberos**", "RADIUS = UDP·비밀번호만 암호화 / TACACS+ = TCP·전체 암호화·시스코", "소유자 재량 = DAC, 보안 등급(레이블) = MAC, 역할 = RBAC", "2요소 인증은 **서로 다른 유형**의 결합".

## 13. 보안 프로토콜

| 프로토콜 | 위치/용도 | 핵심 |
|---|---|---|
| **SSL / TLS** | **전송 계층(TCP)과 응용 계층 사이** | 넷스케이프의 SSL → IETF 표준화 TLS. 서버 인증(인증서), 기밀성(대칭키 암호화), 무결성(MAC). 현재 TLS 1.2 / **1.3** 사용, SSL 2.0/3.0은 취약해 폐기 |
| **HTTPS** | 웹 | **HTTP + SSL/TLS** |
| **SSH** | 원격 접속 | Telnet·rlogin·rsh를 대체하는 **암호화된 원격 로그인**, 안전한 파일 전송(SFTP, SCP), 포트 포워딩(터널링) |
| **S/MIME** | 전자우편 | MIME 이메일에 **PKI(X.509 인증서)** 기반 암호화·전자서명 |
| **PGP** (Pretty Good Privacy) | 전자우편 | 필 짐머만 개발, 이메일 암호화·서명. 중앙 CA 대신 **신뢰의 웹(Web of Trust)** 방식, IDEA·RSA 등 사용 |
| **PEM** (Privacy Enhanced Mail) | 전자우편 | IETF 이메일 보안 표준(구현 복잡해 잘 쓰이지 않음) |
| **SET** (Secure Electronic Transaction) | 전자상거래 | VISA·MasterCard가 만든 **신용카드 결제** 보안 프로토콜, **이중 서명(Dual Signature)** 으로 상점은 카드 정보를, 은행은 주문 정보를 못 보게 함 |
| **IPSec** | 네트워크 계층 | 10장 참조 |
| **DNSSEC** | DNS | DNS 응답에 전자서명 → DNS 스푸핑·캐시 포이즈닝 방지 |

**SSL/TLS 핸드셰이크 개념 흐름 (대략)**
1. **ClientHello**: 클라이언트가 지원하는 암호 방식(Cipher Suite)·난수 전달
2. **ServerHello + 서버 인증서**: 서버가 암호 방식 선택, 인증서(공개키) 전달
3. 클라이언트가 인증서를 검증(CA 서명 확인)하고 **세션 키 재료를 서버 공개키로 암호화**해 전달(또는 DH 키 교환)
4. 양쪽이 같은 **대칭 세션 키** 생성 → **Finished** 교환
5. 이후 데이터는 **대칭키로 암호화**하여 통신 → 하이브리드 방식

TLS 하위 프로토콜: **Handshake**(협상), **Change Cipher Spec**(암호 방식 변경 알림), **Alert**(오류 통지), **Record**(실제 데이터 단편화·압축·암호화)

> 💡 시험 포인트: "SSL/TLS는 전송 계층과 응용 계층 사이", "Telnet 대체 = SSH", "이메일 보안 = PGP·S/MIME", "신용카드 결제·이중 서명 = SET".

## 14. 무선 랜 보안

| 방식 | 암호 알고리즘 | 무결성 | 인증 | 보안 수준 |
|---|---|---|---|---|
| **WEP** (Wired Equivalent Privacy) | **RC4** (스트림) | CRC-32 | 공유 키 | **매우 취약** — 짧은 **24비트 IV** 재사용, **고정(정적) 키** → 쉽게 크랙 |
| **WPA** | RC4 기반 **TKIP** (키를 패킷마다 동적으로 변경) | MIC (Michael) | PSK 또는 802.1X | WEP의 임시 개선판 |
| **WPA2** | **AES 기반 CCMP** | CCMP | PSK(Personal) / **802.1X(Enterprise)** | 현재 널리 사용 (단, KRACK 취약점 존재) |
| **WPA3** | AES (GCMP 등) | - | **SAE** (Simultaneous Authentication of Equals) | **오프라인 사전 대입 공격에 강함**, 순방향 비밀성, 개방형 망 암호화(OWE) |

- **Personal(PSK) 모드**: 모든 사용자가 **같은 사전 공유 키(비밀번호)** 사용 → 가정·소규모용
- **Enterprise 모드**: **802.1X + EAP + RADIUS 서버**로 사용자별 인증 → 기업용

**IEEE 802.1X (포트 기반 네트워크 접근 제어)**
- 구성: **Supplicant(사용자 단말)** – **Authenticator(AP·스위치)** – **Authentication Server(RADIUS 서버)**
- 인증 전에는 해당 포트(연결)로 **EAP 인증 트래픽만** 통과시키고, 인증 성공 후 일반 트래픽 허용
- **EAP (Extensible Authentication Protocol)**: 다양한 인증 방식을 담는 확장형 프레임워크 (EAP-TLS, PEAP, EAP-TTLS 등)

**흔히 쓰지만 약한 보조 수단**
- **SSID 숨김(브로드캐스트 중지)**: 무선 패킷을 스니핑하면 SSID를 쉽게 알아낼 수 있음 → 단독으로는 무의미
- **MAC 주소 필터링**: MAC 주소는 **스푸핑(변경)이 쉬움** → 단독으로는 불충분
- ⇒ 반드시 **WPA2/WPA3 암호화**와 함께 사용해야 한다.

**무선 공격 예**: 가짜 AP(Rogue AP / **Evil Twin**)로 사용자 유인, War Driving(차로 돌며 취약 AP 탐색), WEP 크래킹

> 💡 시험 포인트: "WEP = RC4·취약", "WPA = TKIP", "WPA2 = AES-CCMP", "WPA3 = SAE", "SSID 숨김·MAC 필터링만으로는 안전하지 않다", "802.1X = 포트 기반 인증, RADIUS 연동".

## 15. 보안 관리 기본

### 15-1. 기본 원칙

- **보안 패치·업데이트** 적용: 알려진 취약점 제거 (제로데이를 제외한 대부분의 공격 예방)
- **최소 권한의 원칙**: 관리자 계정 사용 최소화, 서비스 계정 권한 제한
- **불필요한 서비스·포트 비활성화**: 공격 표면(Attack Surface) 줄이기
- **기본 계정·기본 비밀번호 변경**
- **로그 기록과 감사(Audit)**: 누가 언제 무엇을 했는지 기록하고 정기적으로 검토 → 책임 추적성, 사고 분석. 로그는 위·변조되지 않도록 별도 서버에 보관
- **보안 교육**: 사회공학 공격 대비

### 15-2. 백업 종류 ★

| 백업 | 무엇을 백업? | 백업 시간·용량 | 복구 시 필요한 것 | 복구 속도 |
|---|---|---|---|---|
| **전체 백업 (Full)** | **모든 데이터** | 가장 오래 걸림, 용량 큼 | 마지막 전체 백업 **1개** | **가장 빠름** |
| **차등 백업 (Differential)** | **마지막 "전체 백업" 이후** 변경된 모든 데이터 (날이 갈수록 누적되어 커짐) | 중간 | **전체 백업 + 마지막 차등 백업 1개** | 중간 |
| **증분 백업 (Incremental)** | **마지막 "백업"(전체든 증분이든) 이후** 변경된 데이터만 | **가장 빠름**, 용량 작음 | **전체 백업 + 그 이후 모든 증분 백업을 순서대로** | **가장 느림** |

**예시** (일요일 전체 백업, 목요일 장애)
- 차등 백업 사용 시: 일요일 전체 + **수요일 차등** 1개
- 증분 백업 사용 시: 일요일 전체 + **월·화·수 증분** 모두

- **3-2-1 백업 원칙**: 사본 **3개**, 서로 다른 매체 **2종류**, 그중 **1개는 외부(오프사이트)** 보관 → 랜섬웨어·재해 대비

> 💡 시험 포인트: "마지막 **전체** 백업 이후 변경분 = **차등**", "마지막 **백업** 이후 변경분 = **증분**", "복구가 가장 오래 걸리는 것 = 증분".

## ★ 핵심사항 (시험 직전 10분 암기용)

- **CIA** = 기밀성(엿보기 방지)·무결성(변경 방지)·가용성(언제든 사용). **부인 방지 = 전자서명**.
- 가로채기 → **기밀성**, 가로막기 → **가용성**, 변조 → **무결성**, 위조 → **인증(무결성)**.
- **웜** = 숙주 없이 네트워크로 자기 복제 / **바이러스** = 숙주 파일 필요 / **트로이 목마** = 정상 프로그램 위장, 자기 복제 X.
- **루트킷** = 관리자 권한 + 흔적 은폐 / **랜섬웨어** = 암호화 후 몸값 / **논리 폭탄** = 조건 충족 시 실행.
- **SYN Flooding** = SYN만 보내 백로그 큐(Half-Open) 고갈 → 대응 **SYN 쿠키**.
- **Smurf** = ICMP Echo + **브로드캐스트** + 출발지 위조 → 대응 **Directed Broadcast 차단**.
- **Land** = 출발지 IP = 목적지 IP. **Teardrop** = 단편 **오프셋** 조작. **Ping of Death** = **65,535바이트 초과** ICMP.
- **Slowloris** = HTTP 헤더를 천천히 보내 연결 고갈. **DRDoS** = 반사 서버를 이용한 증폭 공격.
- DDoS 구조: 공격자 → **마스터(핸들러)** → **에이전트(좀비)** → 희생자.
- 스니핑 = NIC **무차별(Promiscuous) 모드**, 대응 = **암호화**.
- **ARP 스푸핑** = ARP 캐시 오염(MAC 위조), 같은 LAN 내, 대응 = **정적 ARP**.
- **DNS 스푸핑** = DNS 캐시 오염, 대응 = DNSSEC. **세션 하이재킹** = TCP **시퀀스 번호** 탈취.
- **파밍** = 주소를 정확히 입력해도 가짜 사이트(hosts/DNS 변조). 스미싱=SMS, 비싱=음성, 큐싱=QR.
- `' OR '1'='1` = **SQL Injection** / 스크립트·쿠키 탈취 = **XSS** / 사용자 권한으로 원치 않는 요청 = **CSRF**.
- 레인보우 테이블 대응 = **솔트(Salt)**.
- 열린 포트에 FIN/Xmas/NULL 스캔 → **무응답**, 닫힌 포트 → **RST**. Xmas = FIN+PSH+URG.
- **APT** = 특정 대상, 장기 잠복 / **제로데이** = 패치 전 취약점 공격.
- 방화벽: **패킷 필터링**(3~4계층, 빠름) / **상태 검사**(세션 테이블) / **애플리케이션 게이트웨이**(7계층 프록시, 인증·로그 우수, 느림) / **서킷 게이트웨이**(5계층, 대표 프록시).
- **스크린드 서브넷** = 라우터 2개 사이 **DMZ**, 가장 안전·비쌈. **듀얼 홈드** = NIC 2개. **스크린드 호스트** = 라우터 + 배스천 호스트.
- **오용 탐지** = 시그니처, 신종 공격 탐지 X, 오탐 낮음 / **이상 탐지** = 정상 프로파일, 신종 탐지 O, 오탐 높음.
- 오탐(False Positive) = 정상을 공격으로 / **미탐(False Negative) = 공격을 놓침(더 위험)**.
- **IPS** = 인라인 실시간 차단 / **UTM** = 여러 보안 기능 통합 장비 / **ESM** = 보안 장비 로그 통합 관리 / **NAC** = 접속 전 단말 검사 / **DLP** = 정보 유출 방지 / **WAF** = 웹 방화벽 / **허니팟** = 미끼.
- **IPSec**: **AH = 인증·무결성(암호화 X)**, **ESP = 암호화 O**, **IKE = 키 교환·SA 협상**.
- **전송 모드** = 페이로드만, 호스트 간 / **터널 모드** = 패킷 전체 + **새 IP 헤더**, 게이트웨이 간.
- **L2TP = PPTP + L2F**, 자체 암호화 X → IPSec과 함께. **SSL VPN** = 웹 브라우저로 접속.
- 대칭키 키 수 **n(n−1)/2**, 비대칭키 **2n**. 대칭 = 빠름, 비대칭 = 느림·키 분배 해결.
- 대칭: **DES(56비트 키)**, 3DES, **AES(128/192/256)**, SEED, ARIA, IDEA, RC4(스트림).
- 비대칭: **RSA(소인수분해)**, ECC(짧은 키), **DH(키 교환)**, ElGamal, DSA.
- 해시: **MD5 128비트, SHA-1 160비트**, SHA-256 256비트. 일방향·고정 길이.
- 기밀성 = **수신자 공개키**로 암호화 / 전자서명 = **송신자 개인키**로 서명, 송신자 공개키로 검증.
- PKI: **CA**(발급·폐기), **RA**(신원 확인), **X.509**(인증서 형식), **CRL**(폐기 목록), **OCSP**(실시간 상태 조회).
- **Kerberos** = 티켓, KDC(AS+TGS), 대칭키, 타임스탬프, SSO. **RADIUS = UDP**, **TACACS+ = TCP·전체 암호화**.
- **DAC** = 소유자 재량 / **MAC** = 보안 등급 레이블 / **RBAC** = 역할.
- 무선: **WEP=RC4(취약)**, **WPA=TKIP**, **WPA2=AES-CCMP**, **WPA3=SAE**. SSID 숨김·MAC 필터링만으로는 불충분.
- 백업: **차등** = 마지막 전체 이후 / **증분** = 마지막 백업 이후 (복구 가장 느림).

## ⚠️ 헷갈리는 함정 포인트

| 헷갈리는 쌍 | 구분 포인트 |
|---|---|
| **웜 vs 바이러스** | 웜은 **독립 실행·네트워크 자가 전파**, 바이러스는 **숙주 파일에 기생** |
| **트로이 목마 vs 백도어** | 트로이 목마는 **위장 프로그램**(침투 수단), 백도어는 **인증 우회 출입구**(침투 후 통로). 트로이 목마가 백도어를 설치하기도 함 |
| **Smurf vs Land** | Smurf는 목적지가 **브로드캐스트**, Land는 목적지 = 출발지(**희생자 자신**) |
| **Teardrop vs Ping of Death** | Teardrop은 **오프셋 조작**, Ping of Death는 **크기 초과**. 둘 다 단편화와 관련 |
| **SYN Flooding vs Slowloris** | SYN Flooding은 **TCP 연결 단계(4계층)** 미완성, Slowloris는 **HTTP 헤더(7계층)** 를 느리게 |
| **피싱 vs 파밍** | 피싱은 사용자가 **가짜 링크를 클릭**, 파밍은 **정상 주소를 입력해도** 가짜 사이트(DNS/hosts 변조) |
| **XSS vs CSRF** | XSS = 스크립트가 **사용자 브라우저에서 실행**(쿠키 탈취), CSRF = 사용자 권한으로 **서버에 위조 요청** |
| **스니핑 vs 스푸핑** | 스니핑 = **엿보기(수동적)**, 스푸핑 = **속이기·위장(능동적)** |
| **ARP 스푸핑 vs DNS 스푸핑** | ARP는 **IP↔MAC** 매핑 위조(같은 LAN), DNS는 **도메인↔IP** 매핑 위조 |
| **오용 탐지 vs 이상 탐지** | 오용 = 알려진 패턴, **오탐 낮음·신종 못 잡음** / 이상 = 정상 기준선, **오탐 높음·신종 잡음** |
| **오탐 vs 미탐** | 오탐(False Positive) = **정상을 공격**으로 / 미탐(False Negative) = **공격을 정상**으로 |
| **IDS vs IPS** | IDS = 탐지·경보(Out-of-path) / IPS = 탐지 + **차단**(In-line) |
| **ESM vs UTM** | ESM = 여러 장비 **로그 통합 관리** / UTM = 여러 보안 **기능을 장비 하나에** |
| **AH vs ESP** | AH = **암호화 없음**(인증·무결성만) / ESP = **암호화 포함** |
| **전송 모드 vs 터널 모드** | 전송 = 원래 IP 헤더 유지·페이로드만 / 터널 = 전체 캡슐화·**새 IP 헤더** |
| **스크린드 호스트 vs 스크린드 서브넷** | 호스트 = 라우터 1 + 배스천 호스트 / 서브넷 = 라우터 2 사이 **DMZ** (가장 안전) |
| **기밀성 암호화 vs 전자서명** | 기밀성 = **수신자 공개키** / 서명 = **송신자 개인키** |
| **CRL vs OCSP** | CRL = **폐기 목록 파일**(주기적) / OCSP = **실시간 조회** |
| **RADIUS vs TACACS+** | RADIUS = **UDP**, 비밀번호만 암호화 / TACACS+ = **TCP**, 전체 암호화, 시스코 |
| **DAC vs MAC(접근통제)** | DAC = **소유자**가 결정 / MAC = **시스템이 보안 등급**으로 강제 |
| **차등 vs 증분 백업** | 차등 = 마지막 **전체** 이후(복구 2개) / 증분 = 마지막 **백업** 이후(복구 전부) |
| **WPA vs WPA2** | WPA = TKIP(RC4 기반) / WPA2 = **AES-CCMP** |
| **해시 vs 암호화** | 해시는 **복호화 불가(일방향)**, 무결성 검증용 / 암호화는 복호화 가능, 기밀성용 |

## 🧠 암기 팁

- **CIA = "기무가"** → 기(밀성)·무(결성)·가(용성). "**기**밀은 **가로채**고, **가**용은 **가로막**고"
  - 가로**채**기 → 기밀성 (채 = 훔쳐**채**감 → 비밀 노출)
  - 가로**막**기 → 가용성 (막히면 못 씀)
- **Smurf = 스머프 마을 전체(브로드캐스트)가 한 명에게 답장** → ICMP + 브로드캐스트
- **Land = 땅(Land)에 자기 발자국만** → 출발지 = 목적지 = 나 자신
- **Teardrop = 눈물(조각)이 겹친다** → 조각(Fragment) 오프셋 겹침
- **Ping of Death = 죽을 만큼 큰 핑** → 65,535바이트 초과
- **Xmas 스캔 = 크리스마스 트리처럼 플래그(FIN·PSH·URG) 불이 다 켜짐**, NULL 스캔 = 불이 하나도 안 켜짐
- 사회공학: **S**MS → **S**mishing, **V**oice → **V**ishing, **Q**R → **Q**shing, **Ph**arming → DNS **농장**(Farm)을 통째로 바꿈
- 방화벽 속도 순서: **패킷 필터링 > 상태 검사 > 서킷 > 애플리케이션 게이트웨이** (보안 세밀도는 반대)
- IPSec: "**A**H는 **A**uthentication만, **E**SP는 **E**ncryption까지"
- 터널 모드 = "**터널**은 차 전체(패킷 전체)를 **새 껍데기**(새 IP 헤더)로 감싼다"
- L2TP = "**L**2F + **P**PTP → **L2TP**" (이름에 둘 다 들어 있음)
- 키 개수: **대칭은 "악수 횟수"** (n명이 서로 한 번씩 악수 = n(n−1)/2), **비대칭은 "1인 2키"** (2n)
- 해시 길이: **MD5 = 128비트, SHA-1 = 160비트** → "MD5는 **AES 최소 키(128)** 와 같고, SHA-1은 거기에 **32를 더한 160**"
- DES = "**DES 56**" (데스 오륙), AES = "**AES 128·192·256** (64의 2·3·4배)"
- 공개키 사용법: "**비밀 편지는 받는 사람 자물쇠(공개키)로 잠그고, 사인은 내 도장(개인키)으로 찍는다**"
- RADIUS = **UDP**, **T**ACACS+ = **T**CP (**T**는 **T**CP, 시스코 장비 관리용)
- 접근통제: **D**AC = **D**iscretionary(**D**ecide by owner, 소유자 결정), **M**AC = **M**andatory(**M**ilitary, 군 등급), **R**BAC = **R**ole(역할)
- 무선 보안 진화: **WEP(RC4) → WPA(TKIP) → WPA2(AES) → WPA3(SAE)** = "**R-T-A-S**"
- 백업: **차**등 = "**차**곡차곡 누적(전체 이후 전부)", **증**분 = "**증**가분만(직전 이후만)"

**[보안-02]** 정보보안 요소와 그 설명의 연결로 옳지 않은 것은?

① 기밀성 – 인가된 사용자만 정보를 열람할 수 있도록 한다.
② 무결성 – 인가되지 않은 사용자가 정보를 변경하지 못하도록 한다.
③ 가용성 – 인가된 사용자가 필요할 때 언제든 정보와 서비스를 사용할 수 있도록 한다.
④ 부인 방지 – 시스템에 접근하려는 사용자가 자신이 주장하는 사람이 맞는지 확인한다.

---

**[보안-03]** 다음 설명에 해당하는 악성코드는?

> 다른 프로그램이나 파일에 기생하지 않고 독립적으로 실행되며, 자기 자신을 복제하여 네트워크를 통해 다른 시스템으로 스스로 확산한다. 확산 과정에서 네트워크 대역폭과 시스템 자원을 크게 소모한다.

① 바이러스 ② 웜 ③ 트로이 목마 ④ 스파이웨어

**[보안-04]** 트로이 목마(Trojan Horse)에 대한 설명으로 옳은 것은?

① 유용한 정상 프로그램으로 위장하여 사용자가 직접 실행하도록 유도하며, 일반적으로 자기 복제 기능은 없다.
② 실행 파일이나 부트 섹터에 자신의 코드를 삽입하여 감염된 파일이 실행될 때마다 복제된다.
③ 특정 날짜나 조건이 충족될 때까지 잠복해 있다가 조건이 맞으면 악성 행위를 실행한다.
④ 사용자의 동의 없이 광고를 반복적으로 화면에 표시하는 것이 주목적이다.

**[보안-06]** SYN Flooding 공격에 대한 대응 방법으로 가장 거리가 먼 것은?

② 라우터에서 Directed Broadcast 패킷의 전달을 차단한다.

**[보안-07]** 다음 설명에 해당하는 서비스 거부 공격은?

**[보안-09]** 서비스 거부 공격과 그 설명의 연결로 옳지 않은 것은?

① Teardrop – IP 단편(Fragment)의 오프셋 값을 겹치거나 어긋나게 조작하여 재조립 과정에서 오류를 일으킨다.
② Ping of Death – IP 패킷의 최대 크기(65,535바이트)를 초과하는 ICMP 패킷을 보내 시스템을 다운시킨다.
③ Slowloris – 대량의 UDP 패킷을 임의의 포트로 전송하여 네트워크 대역폭을 고갈시킨다.
④ HTTP GET Flooding – 정상적인 HTTP GET 요청을 대량으로 전송하여 웹 서버에 과부하를 일으킨다.

| 보안-05 | ③ | 파일 암호화 후 **몸값(Ransom)** 요구 = **랜섬웨어**. ① 루트킷은 권한 획득·흔적 은폐, ② 키로거는 키 입력 탈취, ④ 백도어는 인증 우회 통로. |
| 보안-06 | ② | **Directed Broadcast 차단은 Smurf 공격 대응책**이다. SYN Flooding 대응은 SYN 쿠키(①), 백로그 큐 증가(③), Half-Open 타임아웃 단축(④). |
| 보안-07 | ④ | 출발지 IP를 희생자로 위조 + **ICMP Echo Request** + **브로드캐스트 주소** = **Smurf**. ① Land는 출발지=목적지, ② Teardrop은 오프셋 조작, ③ Ping of Death는 크기 초과. |
| 보안-08 | ① | **출발지 IP = 목적지 IP**로 위조하여 자기 자신에게 응답하게 만드는 것은 **Land Attack**. ② SYN Flooding은 SYN만 대량 전송, ③ UDP Flooding은 UDP 대량 전송, ④ Smurf는 브로드캐스트 이용. |
| 보안-09 | ③ | **Slowloris는 HTTP 헤더를 끝내지 않고 아주 느리게 보내 웹 서버의 연결을 오래 점유**하여 동시 연결 수를 고갈시키는 공격이다. ③의 설명은 **UDP Flooding**. ①②④는 올바른 연결. |
| 보안-10 | ② | **마지막 전체 백업 이후** 변경분을 매번 백업하는 것은 **차등 백업** → 복구 시 전체 + 마지막 차등 1개. 증분 백업이라면 전체 + 월·화·수 증분 모두 필요하다. |
| 보안-11 | ① | 자신에게 오지 않은 패킷까지 수신하는 NIC 모드 = **무차별(Promiscuous) 모드**. ② 반이중은 전송 방식, ③④ 터널/전송 모드는 IPSec 동작 모드. |
| 보안-12 | ④ | ④는 **DNS 스푸핑(DNS 캐시 포이즈닝)** 설명이다. ARP 스푸핑은 **IP↔MAC 매핑을 위조**하여 ARP 캐시를 오염시키며 같은 LAN에서 발생하고, 정적 ARP 설정으로 대응한다(①②③ 옳음). |
| 보안-13 | ③ | 정확한 주소를 입력해도 **hosts 파일·DNS 변조**로 가짜 사이트에 접속 = **파밍**. ① 피싱은 가짜 링크 클릭 유도, ② 스미싱은 문자 메시지, ④ 비싱은 음성 전화. |
