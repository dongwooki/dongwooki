## 1. OSI 7계층

### 1-1. OSI 참조 모델이란?

- **OSI(Open Systems Interconnection)** : ISO(국제표준화기구)가 만든 **네트워크 통신 과정을 7단계로 나눈 표준 참조 모델**.
- 왜 나눴나? → 통신 과정을 단계별로 쪼개면 **문제 발생 시 어느 단계가 문제인지 찾기 쉽고**, 각 계층을 **독립적으로 개발/교체**할 수 있기 때문.
- 데이터를 보낼 때는 7 → 1계층으로 내려가며 각 계층이 **헤더를 붙이고(캡슐화, Encapsulation)**, 받을 때는 1 → 7계층으로 올라가며 **헤더를 떼어냄(역캡슐화, Decapsulation)**.

### 1-2. 계층별 정리 (가장 중요한 표!)

| 계층 | 이름 | 핵심 기능 | PDU(데이터 단위) | 대표 프로토콜/규격 | 대표 장비 |
|:---:|---|---|---|---|---|
| 7 | **응용(Application)** | 사용자와 네트워크 사이 인터페이스, 응용 서비스 제공 | 데이터(메시지) | HTTP, FTP, SMTP, DNS, Telnet | 게이트웨이 |
| 6 | **표현(Presentation)** | **데이터 형식 변환, 암호화/복호화, 압축**, 코드 변환 | 데이터 | JPEG, MPEG, GIF, ASCII, EBCDIC | - |
| 5 | **세션(Session)** | **대화(세션) 설정·유지·종료, 동기점(Sync Point) 삽입**, 대화 제어(반이중/전이중) | 데이터 | NetBIOS, RPC, SSH(세션 관리 측면) | - |
| 4 | **전송(Transport)** | **종단 간(End-to-End) 신뢰성** 있는 전송, 포트 번호로 프로세스 구분, 분할/재조립, 흐름·오류 제어 | **세그먼트** | TCP, UDP | (L4 스위치) |
| 3 | **네트워크(Network)** | **논리 주소(IP) 지정, 라우팅(최적 경로 선택)**, 패킷 전달 | **패킷** | IP, ICMP, ARP*, IGMP, OSPF | **라우터**, L3 스위치 |
| 2 | **데이터링크(Data Link)** | **물리 주소(MAC)** 지정, **프레임** 구성, 인접 노드 간 오류·흐름 제어, 매체 접근 제어 | **프레임** | Ethernet, HDLC, PPP, Frame Relay | **브리지, 스위치**, NIC |
| 1 | **물리(Physical)** | 전기적·기계적 신호 전송 (0과 1을 신호로) | **비트** | RS-232C, X.21, 케이블 규격 | **리피터, 허브**, 케이블 |

> *ARP는 2계층과 3계층 사이(2.5계층)로 보기도 함. 시험에서는 보통 "네트워크 계층" 소속으로 출제.

### 1-3. 외우는 방법과 흐름 이해

- 위에서 아래로: **응-표-세-전-네-데-물** → "**응표세전네데물**" (아래에서 위로: "물데네전세표응" = "**물 데 네 전 세 표 응**")
- 영어 두문자(위→아래): **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing
- 데이터 단위(4→1계층): **세그먼트 → 패킷 → 프레임 → 비트** ("**세패프비**")

### 1-4. 계층별 자주 나오는 포인트

- **물리 계층**: "신호", "전압", "핀 배치", "케이블", "비트 동기" 같은 단어가 나오면 물리.
- **데이터링크 계층**: "MAC 주소", "프레임", "인접 노드(Hop-to-Hop)", "오류 검출(CRC)", "흐름 제어" → 데이터링크.
  - IEEE는 데이터링크 계층을 2개 부계층으로 나눔: **LLC(Logical Link Control, 802.2)** + **MAC(Media Access Control)**.
- **네트워크 계층**: "IP 주소", "라우팅", "경로 선택", "혼잡 제어(패킷 수준)" → 네트워크.
- **전송 계층**: "종단 간(End-to-End)", "포트 번호", "세그먼트", "신뢰성", "TCP/UDP" → 전송.
- **세션 계층**: "대화 제어", "동기점(체크포인트)", "세션 연결/해제" → 세션.
- **표현 계층**: "암호화", "압축", "형식 변환", "코드 변환(ASCII ↔ EBCDIC)" → 표현.
- **응용 계층**: "사용자 인터페이스", "파일 전송/전자우편/웹 서비스" → 응용.

### 1-5. TCP/IP 4계층과 OSI 7계층 대응

| TCP/IP 4계층 | 대응되는 OSI 계층 |
|---|---|
| 응용(Application) | 응용 + 표현 + 세션 (5~7계층) |
| 전송(Transport) | 전송 (4계층) |
| 인터넷(Internet) | 네트워크 (3계층) |
| 네트워크 접근(Network Access / Network Interface) | 데이터링크 + 물리 (1~2계층) |

- 개별 프로토콜(TCP, UDP, IP, ARP 등)의 상세 내용은 TCP/IP 노트(02, 03)에서 다룸.

> 💡 **시험 포인트:** "○○ 기능을 하는 계층은?", "계층과 PDU/장비 연결이 옳지 않은 것은?" 형태가 단골. **라우팅=3계층, MAC=2계층, 암호화·압축=6계층, 동기점=5계층, 종단간=4계층**은 반사적으로 나와야 함.

## 2. 통신 방식

### 2-1. 전송 방향에 따른 분류

| 방식 | 설명 | 예시 |
|---|---|---|
| **단방향(Simplex)** | 한쪽은 송신만, 다른 쪽은 수신만 | TV 방송, 라디오, 키보드→PC |
| **반이중(Half-Duplex)** | 양쪽 다 송수신 가능하지만 **동시에는 한쪽만** | **무전기**, 허브 기반 이더넷 |
| **전이중(Full-Duplex)** | 양쪽이 **동시에** 송수신 | **전화**, 스위치 기반 이더넷 |

### 2-2. 직렬 vs 병렬 전송

| 구분 | 직렬(Serial) | 병렬(Parallel) |
|---|---|---|
| 방식 | 비트를 **한 줄로 하나씩** 전송 | 여러 비트를 **여러 선으로 동시에** 전송 |
| 거리 | **원거리**에 적합 | **근거리**에 적합 |
| 비용 | 저렴(선이 적음) | 비쌈(선이 많음) |
| 예 | USB, 네트워크 통신, RS-232C | 옛날 프린터 포트, CPU 내부 버스 |

- 병렬은 선이 많아 빨라 보이지만, 거리가 멀어지면 비트 간 도착 시간 차이(스큐, Skew)와 간섭 때문에 불리 → 네트워크 통신은 거의 직렬.

### 2-3. 동기식 vs 비동기식 전송

| 구분 | 비동기식(Asynchronous) | 동기식(Synchronous) |
|---|---|---|
| 전송 단위 | **문자(Character)** 단위 | **블록(Block, 프레임)** 단위 |
| 동기화 | 각 문자 앞뒤에 **시작 비트(Start bit)**, **정지 비트(Stop bit)** | 송수신 측이 **클록(Clock)을 맞춤**, 동기 문자(SYN)나 플래그 사용 |
| 휴지 시간 | 문자 사이 **휴지 시간(Idle) 있음** | 휴지 시간 없음 |
| 효율/속도 | 오버헤드 커서 **효율 낮음, 저속** | 오버헤드 작아 **효율 높음, 고속** |
| 비용 | 단순·저렴 | 복잡·비쌈 |

- 동기식은 다시 **문자 동기(BSC: SYN 문자 사용)**와 **비트 동기(HDLC: 플래그 01111110 사용)**로 나뉨.

> 💡 **시험 포인트:** "무전기=반이중, 전화=전이중", "비동기=Start/Stop 비트, 문자 단위, 저속" 이 셋이 거의 그대로 나온다.

## 3. 전송 매체

### 3-1. 유선 vs 무선

- **유도 매체(유선)**: 꼬임쌍선(Twisted Pair), 동축 케이블, 광섬유
- **비유도 매체(무선)**: 전파(라디오파), 마이크로파, 적외선, 위성

### 3-2. 꼬임쌍선(Twisted Pair)

- 구리선 2가닥을 **꼬아서** 만든 케이블. 꼬는 이유 → **전자기 간섭(EMI)과 혼선(Crosstalk) 감소**.
- 커넥터: **RJ-45** (8핀). 전화선은 RJ-11.
- 종류
  - **UTP (Unshielded Twisted Pair)**: 차폐 없음. 저렴·설치 쉬움 → 가장 많이 사용.
  - **STP (Shielded Twisted Pair)**: 금속 차폐(실드) 있음 → 간섭에 강하지만 비싸고 두꺼움.
  - (FTP/ScTP: 전체를 호일로 감싼 형태)
- **최대 전송 거리: 100m** (UTP 기반 이더넷 공통)

| 카테고리 | 대역폭 | 대표 용도/속도 |
|---|---|---|
| Cat 3 | 16MHz | 10Mbps (10Base-T), 전화 |
| Cat 5 | 100MHz | 100Mbps (100Base-TX) |
| **Cat 5e** | 100MHz | **1Gbps (1000Base-T)** |
| Cat 6 | 250MHz | 1Gbps (짧은 거리 10Gbps) |
| Cat 6a | 500MHz | 10Gbps (100m) |
| Cat 7 | 600MHz | 10Gbps (STP 계열) |

### 3-3. 동축 케이블(Coaxial Cable)

- 중심 도체 + 절연체 + 외부 도체(망) + 피복 구조. 꼬임쌍선보다 간섭에 강하고 대역폭 큼.
- **50Ω**: 데이터 통신(구형 이더넷 10Base5, 10Base2)
- **75Ω**: **CATV(케이블 TV)**, 영상 신호
- 커넥터: BNC (10Base2), F형(TV)

### 3-4. 광섬유 케이블(Optical Fiber)

- 빛(레이저/LED)을 이용해 전송. **빛의 전반사(Total Internal Reflection)** 원리.
- 구조: **코어(Core, 굴절률 높음)** + **클래딩(Cladding, 굴절률 낮음)** + 피복
- 장점: **대역폭 매우 넓음, 감쇠 적어 장거리 가능, 전자기 간섭(EMI) 없음, 도청 어려워 보안성 높음, 가볍고 가늘다**
- 단점: 비싸고, 설치·접속(융착)·분기가 어렵다.

| 구분 | 싱글모드(SMF, Single Mode) | 멀티모드(MMF, Multi Mode) |
|---|---|---|
| 코어 직경 | **작다 (약 8~10μm)** | **크다 (50μm / 62.5μm)** |
| 광원 | **레이저(LD)** | **LED** (또는 저가 레이저) |
| 전송 거리 | **장거리 (수십 km 이상)** | **단거리 (수백 m~2km)** |
| 모드 분산 | 거의 없음 | 있음 (여러 경로로 빛이 퍼짐) |
| 가격 | 장비 비쌈 | 상대적으로 저렴 |

- 기억법: **싱글 = 한 줄기 빛 = 가늘고 멀리**, **멀티 = 여러 줄기 = 굵고 가까이**.

### 3-5. 무선 매체

- **라디오파**: 전방향(Omni-directional), 장애물 투과 → 무선LAN, 방송
- **마이크로파**: 직진성 강함, **가시거리(LOS)** 통신, 위성·지상 중계
- **적외선(IR)**: 근거리, 벽 투과 불가 → 리모컨, IrDA

> 💡 **시험 포인트:** "**광섬유 = 전반사, EMI 없음, 싱글모드=코어 작고 장거리**", "**UTP 최대 100m**", "**동축 75Ω = CATV**" 가 오답 선지로 자주 비틀어져 나온다.

## 4. 네트워크 토폴로지 & 네트워크 분류

### 4-1. 토폴로지(Topology, 망 구성 형태)

| 형태 | 구조 | 장점 | 단점 |
|---|---|---|---|
| **버스(Bus)** | 하나의 공통 케이블(백본)에 모든 노드 연결, 양 끝에 **터미네이터** | 설치 쉬움, 케이블 적음, 노드 추가/제거 쉬움 | 백본 고장 시 전체 마비, 노드 많으면 충돌 증가 |
| **스타(Star, 성형)** | **중앙 장비(허브/스위치)**에 모든 노드가 1:1 연결 | 관리·장애 진단 쉬움, 한 노드 고장이 다른 노드에 영향 적음 | **중앙 장비 고장 시 전체 마비**, 케이블 많이 듦 |
| **링(Ring, 환형)** | 노드들이 원형으로 연결, 데이터가 한 방향으로 순환 (토큰 링) | 충돌 없음, 공평한 전송 기회 | 한 노드 고장 시 전체 영향(이중 링으로 보완), 추가/제거 어려움 |
| **메시(Mesh, 망형)** | 모든 노드가 서로 직접 연결 | **신뢰성·장애 대응 최고**, 경로 다양 | **회선·포트 많이 필요, 비용 큼** |
| **트리(Tree, 계층형)** | 스타를 계층적으로 연결 | 확장 쉬움, 분산 처리 | 상위 노드 고장 시 하위 전체 영향 |

#### 메시형 계산 공식 (계산 문제 단골!)

- 노드 수가 **n**개일 때
  - **필요한 회선(링크) 수 = n(n−1)/2**
  - **노드 1개당 필요한 포트 수 = n−1**
- 예) n = 5 → 회선 5×4/2 = **10개**, 포트 **4개**
- 예) n = 10 → 회선 10×9/2 = **45개**, 포트 **9개**

### 4-2. 네트워크 분류 (규모 기준)

| 구분 | 범위 | 예 |
|---|---|---|
| **PAN** (Personal Area Network) | 개인 주변 수 m | 블루투스, Zigbee |
| **LAN** (Local Area Network) | 건물·캠퍼스 (수 km 이내) | 사무실 이더넷, 무선LAN |
| **MAN** (Metropolitan Area Network) | 도시 단위 (수십 km) | IEEE 802.6 DQDB, 802.16 WiMAX |
| **WAN** (Wide Area Network) | 국가·대륙 | 인터넷, 전용선, ISDN |

- 규모 작은 순서: **PAN < LAN < MAN < WAN**
- LAN 특징: 전송 속도 빠르고 **오류율 낮음**, 단일 기관 소유/관리.

> 💡 **시험 포인트:** "**중앙 장비 고장 → 전체 마비 = 스타형**", "**메시형 회선 수 n(n−1)/2**", "**터미네이터 = 버스형**" 이 핵심.

## 5. 교환 방식 (Switching)

### 5-1. 회선 교환 vs 메시지 교환 vs 패킷 교환

| 구분 | 회선 교환(Circuit) | 메시지 교환(Message) | 패킷 교환(Packet) |
|---|---|---|---|
| 원리 | 통신 전 **전용 물리 경로를 설정·점유** | 메시지 전체를 **저장 후 전달(Store-and-Forward)** | 메시지를 **패킷으로 쪼개** 저장 후 전달 |
| 실시간성 | **좋음** (음성 전화에 적합) | 나쁨 (지연 큼) | 비교적 좋음 |
| 회선 효율 | 낮음(통신 안 해도 점유) | 높음 | **높음** |
| 대표 예 | 전화망(PSTN) | 전보, 이메일 개념 | 인터넷, X.25 |
| 특징 | 연결 설정 시간 필요, 고정 대역폭 | 메시지 길이 제한 없음, 브로드캐스트 가능 | 패킷 길이 제한, 오류 제어·경로 제어 가능 |

### 5-2. 패킷 교환의 두 가지 방식

| 구분 | **가상 회선(Virtual Circuit)** | **데이터그램(Datagram)** |
|---|---|---|
| 연결 | **연결형** (전송 전 논리적 경로 설정) | **비연결형** (경로 설정 없음) |
| 경로 | 모든 패킷이 **같은 경로** | 각 패킷이 **독립적으로 경로 선택** |
| 순서 | **순서 보장** | 순서 **뒤바뀔 수 있음** → 수신 측에서 재조립 |
| 장애 대응 | 경로 상 노드 고장 시 영향 큼 | 우회 가능해 **유연** |
| 적합 | 긴 메시지, 연속 데이터 | 짧은 메시지 |
| 예 | X.25, 프레임 릴레이, ATM | IP |

> 💡 **시험 포인트:** "**전용 경로 점유 + 실시간 = 회선 교환**", "**데이터그램 = 비연결, 독립 경로, 순서 바뀔 수 있음**", "**가상회선 = 논리적 경로 설정, 순서 보장**".

## 6. 다중화 (Multiplexing)

- **다중화란?** 하나의 통신 회선을 **여러 사용자(신호)가 나눠 쓰는 기술**. 회선 비용 절감이 목적.
- 다중화기(MUX) ↔ 역다중화기(DEMUX)

| 방식 | 나누는 기준 | 설명 |
|---|---|---|
| **FDM** (Frequency Division) | **주파수** | 대역을 여러 주파수로 나눔. 채널 간 간섭 방지 위해 **보호 대역(Guard Band)** 필요. **아날로그** 신호. 예: 라디오·TV 방송 |
| **TDM** (Time Division, 동기식) | **시간** | 시간을 **타임 슬롯**으로 나눠 각 단말에 **고정 할당**. 보낼 데이터 없어도 슬롯 할당 → **낭비 발생**. 디지털 신호 |
| **STDM** (Statistical TDM, 통계적·비동기식·지능형) | **시간(동적)** | **전송할 데이터가 있는 단말에만** 슬롯 **동적 할당** → 효율 높음. 대신 슬롯에 **주소(제어) 정보** 필요, 버퍼 필요 |
| **WDM** (Wavelength Division) | **빛의 파장** | **광섬유**에서 파장별로 나눔(본질적으로 광 FDM). DWDM은 고밀도 |
| **CDM** (Code Division) | **코드** | 각 사용자에 고유 코드 할당, 같은 시간·주파수 공유. **CDMA** 이동통신 |

- 동기식 TDM vs 통계적 TDM 비교가 제일 자주 나옴
  - 동기식: 고정 할당, 낭비 있음, 구조 단순
  - 통계적(비동기): 동적 할당, 효율 높음, 주소 정보 필요, 구조 복잡

> 💡 **시험 포인트:** "**보호 대역 = FDM**", "**광섬유·파장 = WDM**", "**데이터 있는 단말에만 동적 할당 = 통계적(비동기) TDM**".

## 7. 변조 & PCM

### 7-1. 변조(Modulation)란?

- 데이터를 전송 매체에 맞는 신호로 바꾸는 것. 반송파(Carrier)의 **진폭/주파수/위상**을 바꿔 정보를 실음.
- **모뎀(MODEM = MOdulator + DEModulator)**: 디지털 ↔ 아날로그 변환.

| 데이터 → 신호 | 방식 |
|---|---|
| **디지털 → 아날로그** (모뎀) | **ASK**(진폭 편이), **FSK**(주파수 편이), **PSK**(위상 편이), **QAM**(진폭+위상 혼합) |
| **아날로그 → 아날로그** | AM(진폭), FM(주파수), PM(위상) |
| **아날로그 → 디지털** (코덱) | **PCM**(펄스 코드 변조), 델타 변조 |
| **디지털 → 디지털** (라인 코딩) | NRZ, 맨체스터, 차등 맨체스터, AMI 등 |

- **QAM**은 진폭과 위상을 함께 바꿔 한 번에 많은 비트를 보냄 → 고속 모뎀, 케이블 모뎀, 무선LAN에 사용.
- **맨체스터 코딩**: 비트 중간에서 전압이 반드시 바뀜 → **동기화(클록 추출) 용이**, 10Mbps 이더넷에서 사용.

### 7-2. PCM (Pulse Code Modulation) 과정

아날로그 음성을 디지털로 바꾸는 순서:

> **표본화(Sampling) → 양자화(Quantization) → 부호화(Encoding)** → (전송) → 복호화(Decoding) → 여과(Filtering)

| 단계 | 설명 |
|---|---|
| 표본화 | 일정 시간 간격으로 아날로그 신호 값을 **샘플링** (PAM 신호 생성) |
| 양자화 | 샘플 값을 **정해진 단계(레벨)의 근사값**으로 바꿈 → 이때 **양자화 잡음** 발생 |
| 부호화 | 양자화된 값을 **2진수(0/1)** 로 변환 |
| 복호화 | 수신 측에서 디지털 → PAM 신호로 |
| 여과 | 저역 통과 필터(LPF)로 원래 아날로그 신호 복원 |

- 기억법: "**표양부 복여**" (표본을 양껏 부어, 복을 여과)

### 7-3. 나이퀴스트(Nyquist) 표본화 정리

- 원 신호를 복원하려면 **최고 주파수의 2배 이상**으로 표본화해야 함.
  - 표본화 주파수 fs ≥ 2 × fmax
- 예) 음성 최고 주파수 **4kHz** → 초당 **8,000번** 표본화 → 표본화 주기 = 1/8000초 = **125μs**
- 음성 PCM: 8,000 샘플/초 × 8비트 = **64kbps** (→ 디지털 전화 채널 1개 = DS0 = 64kbps의 근거)

### 7-4. 채널 용량

- **나이퀴스트 용량(잡음 없는 채널)**: C = 2B log₂M (B: 대역폭, M: 신호 레벨 수)
- **샤논(Shannon) 용량(잡음 있는 채널)**: **C = B log₂(1 + S/N)** (S/N: 신호 대 잡음비)
  - 의미: 채널 용량은 **대역폭(B)과 신호 대 잡음비(S/N)** 에 의해 결정됨. 대역폭을 늘리거나 S/N을 높이면 용량 증가.

### 7-5. baud와 bps

- **baud(보, 변조 속도)**: 초당 **신호 변화(심볼) 횟수**
- **bps(비트 속도)**: 초당 전송되는 **비트 수**
- **bps = baud × (한 번에 보내는 비트 수)** = baud × log₂M

| 방식 | 한 심볼당 비트 수 | bps |
|---|---|---|
| 1비트(2진) | 1 (Monobit) | baud × 1 |
| 4진(QPSK 등) | 2 (Dibit) | baud × 2 |
| 8진(8-PSK 등) | 3 (Tribit) | baud × 3 |
| 16진(16-QAM 등) | 4 (Quadbit) | baud × 4 |

- 예) 2,400 baud, 16-QAM → 2,400 × 4 = **9,600bps**

> 💡 **시험 포인트:** "**PCM 순서 = 표본화→양자화→부호화**", "**4kHz → 8,000회/초**", "**bps = baud × 비트 수**" 계산, "**샤논 = 대역폭과 S/N**".

## 8. 오류 검출 및 정정

### 8-1. 오류 제어 방식 분류

| 구분 | 의미 | 대표 기법 |
|---|---|---|
| **BEC** (Backward Error Correction, 후진 오류 수정) | 수신 측은 **오류 검출만** 하고, 송신 측에 **재전송 요청** | 패리티, CRC, 체크섬 + **ARQ** |
| **FEC** (Forward Error Correction, 전진 오류 수정) | 수신 측이 **스스로 오류를 검출하고 정정** (재전송 X) | **해밍 코드**, 상승 코드(컨볼루션), 리드-솔로몬 |

- FEC는 재전송이 어려운 환경(위성, 실시간 방송)에 유리하지만 **추가 비트(오버헤드)가 많음**.

### 8-2. 패리티 검사 (Parity Check)

- 데이터에 **1비트(패리티 비트)** 를 추가해 1의 개수를 **짝수(Even) 또는 홀수(Odd)** 로 맞춤.
- **1비트 오류(홀수 개 오류) 검출 가능**, **정정은 불가**, 짝수 개 비트 오류는 검출 못 함.
- 예) 데이터 1011001 (1이 4개) → 짝수 패리티면 0 추가, 홀수 패리티면 1 추가.
- 2차원(블록) 패리티: 가로·세로 패리티 → 1비트 오류의 위치까지 찾을 수 있음.

### 8-3. CRC (Cyclic Redundancy Check, 순환 중복 검사)

- **다항식(생성 다항식)** 으로 나눗셈한 **나머지(FCS)** 를 데이터 뒤에 붙여 전송.
- **집단 오류(Burst Error)** 검출에 강함. 이더넷·HDLC 프레임의 **FCS 필드**가 CRC.
- 데이터링크 계층에서 주로 사용, **검출만** 가능(정정 X).

### 8-4. 체크섬 (Checksum)

- 데이터를 일정 단위로 더한 합(의 보수)을 함께 보냄. 주로 **상위 계층(IP, TCP, UDP 헤더)** 에서 사용. 검출만 가능.

### 8-5. 해밍 코드 (Hamming Code)

- **1비트 오류 검출 + 정정 가능** (FEC 대표). 2비트 오류는 검출만 가능.
- 패리티 비트 위치: **2의 거듭제곱 위치(1, 2, 4, 8, 16 …번째)**
- **필요한 패리티 비트 수 p 공식: 2ᵖ ≥ m + p + 1** (m: 데이터 비트 수)

| 데이터 비트(m) | 필요한 패리티 비트(p) | 전체 비트 |
|---|---|---|
| 4 | 3 (2³=8 ≥ 4+3+1=8) | 7 → **해밍(7,4)** |
| 8 | 4 (2⁴=16 ≥ 8+4+1=13) | 12 |
| 16 | 5 (2⁵=32 ≥ 16+5+1=22) | 21 |

### 8-6. 해밍 거리 (Hamming Distance)

- 두 코드에서 **서로 다른 비트 수**. 예) 1011과 1001 → 3번째 비트만 다름 → 해밍 거리 1.
- 최소 해밍 거리가 d이면
  - **검출 가능 오류 수 = d − 1**
  - **정정 가능 오류 수 = ⌊(d − 1) / 2⌋**

> 💡 **시험 포인트:** "**FEC = 해밍 코드(수신 측이 직접 정정)**", "**BEC = ARQ(재전송)**", "**패리티는 짝수 개 오류 검출 불가**", "**해밍 패리티 수 2ᵖ ≥ m+p+1**".

## 9. ARQ & 흐름 제어

### 9-1. ARQ (Automatic Repeat reQuest, 자동 반복 요청)

- 오류가 검출되면 **수신 측이 송신 측에 재전송을 요청**하는 방식 (BEC의 일종).
- ACK(긍정 응답), NAK(부정 응답) 사용.

| 방식 | 동작 | 특징 |
|---|---|---|
| **정지-대기(Stop-and-Wait)** | 프레임 **1개 전송 후 ACK를 기다림** | 구현 단순, **전송 효율 가장 낮음** |
| **Go-Back-N** | 연속 전송 중 오류 발생 시 **오류 난 프레임부터 그 이후 전부 재전송** | 연속적 ARQ, 가장 널리 사용, 중복 전송 발생 |
| **선택적 재전송(Selective Repeat)** | **오류 난 프레임만** 재전송 | 효율 높음, 수신 측에 **큰 버퍼와 재정렬 기능 필요**, 구현 복잡 |
| **적응적(Adaptive) ARQ** | 채널 상태에 따라 **프레임 길이를 동적으로 변경** | 효율 최대, 제어 회로 복잡 |

- 예) 0~7번 프레임을 보냈는데 **4번**에 오류
  - Go-Back-N → **4, 5, 6, 7번** 재전송 (4개)
  - Selective Repeat → **4번만** 재전송

### 9-2. 흐름 제어 (Flow Control)

- **송신 측이 수신 측의 처리 능력보다 빨리 보내지 않도록 전송량/속도를 조절**하는 것 (수신 버퍼 넘침 방지).
- **정지-대기**: 한 번에 1개씩.
- **슬라이딩 윈도우(Sliding Window)**: ACK를 받지 않고도 **윈도우 크기만큼 여러 프레임을 연속 전송**. ACK를 받으면 윈도우가 **오른쪽으로 미끄러지듯(slide)** 이동.
  - 수신 측 상황에 따라 **윈도우 크기를 동적으로 조절** 가능
  - 순서 번호가 n비트일 때 최대 윈도우 크기: Go-Back-N은 **2ⁿ − 1**, Selective Repeat은 **2ⁿ⁻¹**
- 참고: **오류 제어**는 "틀린 걸 다시", **흐름 제어**는 "속도 조절", **혼잡 제어**는 "네트워크 전체가 막히지 않게".

> 💡 **시험 포인트:** "**Go-Back-N = 오류 프레임부터 이후 전부**", "**Selective Repeat = 오류 프레임만, 버퍼 필요**", "**슬라이딩 윈도우 = 여러 프레임 연속 전송 + 윈도우 크기 조절**".

## 10. 매체 접근 제어 (MAC, Media Access Control)

여러 장치가 하나의 전송 매체를 공유할 때 **누가 언제 보낼지** 정하는 규칙.

### 10-1. CSMA/CD (Carrier Sense Multiple Access / Collision Detection)

- **IEEE 802.3 유선 이더넷**의 방식.
- 동작 순서
  1. **반송파 감지(Carrier Sense)**: 회선이 비었는지 확인
  2. 비어 있으면 전송
  3. **충돌 감지(Collision Detection)** 시 즉시 전송 중단, **잼(Jam) 신호** 전송 → 모두에게 충돌 알림
  4. **임의 시간(백오프, Binary Exponential Backoff)** 대기 후 재전송
- 특징: 노드가 많고 트래픽 많을수록 충돌 증가 → 성능 저하. **충돌 발생 가능성 있음**(완전 회피 X). 버스형·허브 환경과 궁합.
- 전이중 스위치 환경에서는 충돌이 없어 사실상 CSMA/CD가 필요 없음.

### 10-2. CSMA/CA (Carrier Sense Multiple Access / Collision Avoidance)

- **IEEE 802.11 무선 LAN**의 방식.
- 무선은 송신하면서 충돌을 감지하기 어려움(숨겨진 노드 문제 등) → 충돌을 **사전에 회피**.
- 회선이 비어도 **IFS(Inter Frame Space)** 만큼 + 임의 백오프 시간 대기 후 전송
- **RTS(Request To Send) / CTS(Clear To Send)** 로 전송 예약 → **숨겨진 터미널(Hidden Terminal) 문제** 해결
- 수신 측은 **ACK**로 정상 수신 확인

### 10-3. 토큰 패싱 (Token Passing)

- **토큰(Token)** 이라는 제어 프레임을 가진 노드만 전송 → **충돌 없음**.
- **토큰 링(IEEE 802.5)**: 링형 토폴로지
- **토큰 버스(IEEE 802.4)**: 물리적으로 버스, 논리적으로 링
- 트래픽이 많을 때도 성능 안정적, 전송 지연 예측 가능. 토큰 분실/중복 관리 필요.

| 구분 | CSMA/CD | CSMA/CA | 토큰 패싱 |
|---|---|---|---|
| 표준 | IEEE 802.3 | IEEE 802.11 | IEEE 802.4/802.5 |
| 매체 | 유선 이더넷 | 무선 LAN | 토큰 버스/링 |
| 충돌 | 감지 후 처리 | 사전 회피 | 없음 |
| 키워드 | 잼 신호, 백오프 | RTS/CTS, IFS, ACK | 토큰 |

> 💡 **시험 포인트:** "**유선=CD(감지), 무선=CA(회피)**", "**RTS/CTS = CSMA/CA**", "**잼 신호 = CSMA/CD**", "**토큰 = 충돌 없음**".

### 11-2. 이더넷 규격 읽는 법

**[속도][전송방식][매체/거리]** 예) **10Base-T**
- **10** → 전송 속도 10Mbps
- **Base** → **베이스밴드(Baseband)** 전송 (디지털 신호 그대로, ↔ Broad는 브로드밴드)
- **T** → **Twisted Pair (UTP)**
- 숫자로 끝나면 최대 길이(대략 100m 단위): 10Base**5** → 500m, 10Base**2** → 185m(≈200m)

| 규격 | 속도 | 매체 | 최대 길이 | 비고 |
|---|---|---|---|---|
| **10Base5** | 10Mbps | 굵은 동축(Thick) | **500m** | Thicknet, 버스형 |
| **10Base2** | 10Mbps | 가는 동축(Thin) | **185m** | Thinnet, BNC 커넥터 |
| **10Base-T** | 10Mbps | UTP (Cat3 이상) | **100m** | 스타형(허브) |
| 10Base-F | 10Mbps | 광섬유 | 2km | |
| **100Base-TX** | 100Mbps | UTP Cat5 (2쌍) | 100m | Fast Ethernet |
| 100Base-T4 | 100Mbps | UTP Cat3 (4쌍) | 100m | |
| **100Base-FX** | 100Mbps | 광섬유 | 멀티모드 약 2km | |
| **1000Base-T** | 1Gbps | UTP **Cat5e** 이상 (4쌍) | 100m | Gigabit Ethernet, 802.3ab |
| **1000Base-SX** | 1Gbps | **멀티모드** 광 (단파장 850nm) | 약 220~550m | **S = Short** wavelength |
| **1000Base-LX** | 1Gbps | **싱글/멀티모드** 광 (장파장 1300nm) | 싱글모드 약 5km | **L = Long** wavelength |
| 1000Base-CX | 1Gbps | 차폐 구리선 | 25m | |
| 10GBase-T | 10Gbps | UTP Cat6a 이상 | 100m | 802.3an |
| 10GBase-SR/LR/ER | 10Gbps | 광섬유 | SR 단거리, LR 10km, ER 40km | |

### 11-3. 무선 LAN (IEEE 802.11)

| 규격 | 주파수 | 최대 속도 | 핵심 기술/별칭 |
|---|---|---|---|
| 802.11 (초기) | 2.4GHz | 2Mbps | |
| **802.11a** | **5GHz** | **54Mbps** | OFDM |
| **802.11b** | **2.4GHz** | **11Mbps** | DSSS |
| **802.11g** | **2.4GHz** | **54Mbps** | OFDM, b와 호환 |
| **802.11n** | 2.4 / 5GHz | **600Mbps** | **MIMO**, 채널 결합(40MHz), Wi-Fi 4 |

> 💡 **시험 포인트:** "**802.3=이더넷, 802.5=토큰링, 802.11=무선LAN, 802.15.1=블루투스**", "**10Base-T 최대 100m / 10Base2 185m / 10Base5 500m**", "**802.11b = 2.4GHz 11Mbps**".

## 12. 데이터링크 프로토콜 (HDLC, PPP)

### 12-1. HDLC (High-level Data Link Control)

- ISO 표준 **비트 위주(Bit-oriented) 동기식** 데이터링크 프로토콜.
- 프레임 구조

| 플래그 | 주소 | 제어 | 정보(데이터) | FCS | 플래그 |
|---|---|---|---|---|---|
| **01111110** | 8비트 | 8/16비트 | 가변 | 16/32비트(CRC) | 01111110 |

- **플래그(01111110)**: 프레임 시작과 끝 표시, 동기화
- **비트 스터핑(Bit Stuffing)**: 데이터 안에 1이 **연속 5개** 나오면 그 뒤에 **0을 강제로 삽입** → 데이터가 플래그로 오인되는 것 방지 (데이터 투명성)
- **FCS**: CRC 기반 오류 검출

- **프레임 종류 (제어 필드로 구분)**

| 프레임 | 용도 |
|---|---|
| **I-프레임 (Information)** | **사용자 데이터 전송** (순서 번호 포함) |
| **S-프레임 (Supervisory)** | **감독**: 오류 제어·흐름 제어 (RR, RNR, REJ, SREJ) |
| **U-프레임 (Unnumbered)** | **비번호**: 링크 설정·해제 등 제어 (SNRM, SABM, DISC 등) |

- **동작 모드**

| 모드 | 설명 |
|---|---|
| **NRM** (정규 응답 모드) | 주국(Primary)의 **허가(폴링)를 받아야** 종국(Secondary)이 전송. 포인트-투-멀티포인트 |
| **ABM** (비동기 균형 모드) | 혼합국끼리 **허가 없이 누구나 전송**. 포인트-투-포인트, 가장 많이 사용 |
| **ARM** (비동기 응답 모드) | 종국이 주국의 허가 없이 전송 가능(제어는 주국) |

- 지원 ARQ: Stop-and-Wait, Go-Back-N, Selective Repeat 모두 사용 가능.

### 12-2. PPP (Point-to-Point Protocol)

- 두 지점 간(점대점) 직렬 링크에서 사용하는 데이터링크 프로토콜 (전화 접속, xDSL의 PPPoE 등).
- 다양한 네트워크 계층 프로토콜(IP 등)을 동시에 지원.
- 구성 요소
  - **LCP (Link Control Protocol)**: **링크 설정·유지·종료**, 옵션 협상(최대 프레임 크기, 인증 방식 등)
  - **NCP (Network Control Protocol)**: **네트워크 계층 프로토콜 설정** (예: IP용 **IPCP**)
  - **인증**: **PAP**(평문 비밀번호, 2-way) / **CHAP**(챌린지-응답, 해시 사용, 3-way, 더 안전)
- 절차: 링크 설정(LCP) → 인증(PAP/CHAP) → 네트워크 계층 설정(NCP) → 데이터 전송 → 종료

> 💡 **시험 포인트:** "**HDLC 플래그 01111110 / 비트 스터핑(1 다섯 개 뒤 0)**", "**I=정보, S=감독, U=비번호**", "**PPP: LCP=링크, NCP=네트워크 계층**".

## 13. WAN 기술

| 기술 | 핵심 내용 |
|---|---|
| **X.25** | ITU-T의 **패킷 교환망** 표준. DTE(단말)와 DCE(망) 사이의 인터페이스 규정. OSI **1~3계층** 대응. 노드마다 오류·흐름 제어 → **신뢰성 높지만 느림** |
| **프레임 릴레이(Frame Relay)** | X.25를 **간소화**. 중간 노드의 오류 제어·흐름 제어를 **생략**(종단에서 처리) → **고속**. 2계층 동작, **DLCI**로 가상 회선 식별, **CIR**(약정 전송 속도) |
| **ATM** (Asynchronous Transfer Mode) | **53바이트 고정 길이 셀(Cell)** = **헤더 5바이트 + 페이로드 48바이트**. 연결형(VPI/VCI로 가상 경로/회선 식별). 음성·영상·데이터 통합, **B-ISDN**의 핵심 기술. 셀이 고정 길이라 **하드웨어 고속 스위칭** 가능 |
| **ISDN** (종합정보통신망) | 음성+데이터를 **디지털**로 통합. B채널(64kbps, 사용자 정보), D채널(신호/제어) |
| **xDSL** | 기존 **전화선(구리선)** 으로 고속 데이터 전송 |

### 13-1. ISDN 인터페이스

| 구분 | 구성 | 속도 |
|---|---|---|
| **BRI** (기본 속도 인터페이스) | **2B + D** (D = 16kbps) | 64×2 + 16 = **144kbps** |
| **PRI** (1차군 속도 인터페이스) – 북미/일본 | **23B + D** (D = 64kbps) | **1.544Mbps** (T1) |
| **PRI** – 유럽/한국 | **30B + D** (D = 64kbps) | **2.048Mbps** (E1) |

- 광대역은 **B-ISDN** (ATM 기반).

### 13-2. xDSL 종류

| 종류 | 특징 |
|---|---|
| **ADSL** (Asymmetric) | **비대칭**: **하향(다운로드) 속도 > 상향(업로드) 속도**. 전화와 데이터 동시 사용(스플리터) |
| **VDSL** (Very high-bit-rate) | ADSL보다 훨씬 고속, 대신 **짧은 거리** |
| SDSL / HDSL | **대칭**형 (상·하향 속도 동일) |

> 💡 **시험 포인트:** "**ATM = 53바이트(5+48) 고정 셀**", "**프레임 릴레이 = X.25 간소화, 오류 제어 생략, DLCI**", "**BRI = 2B+D = 144kbps**", "**ADSL = 비대칭(하향이 빠름)**".

## 15. 신기술 용어

### 15-1. SDN & NFV

- **SDN (Software Defined Networking, 소프트웨어 정의 네트워킹)**
  - 네트워크 장비의 **제어부(Control Plane)와 데이터 전달부(Data Plane)를 분리**하고, 제어는 **중앙 컨트롤러(소프트웨어)** 에서 프로그래밍으로 수행.
  - 대표 프로토콜: **OpenFlow** (컨트롤러 ↔ 스위치 통신)
  - 장점: 네트워크를 유연하게 구성·자동화, 벤더 종속 감소.
- **NFV (Network Functions Virtualization, 네트워크 기능 가상화)**
  - 방화벽, 라우터, 로드밸런서 같은 **네트워크 기능을 전용 하드웨어 대신 범용 서버의 가상 머신(소프트웨어)으로 구현**.
- 차이: **SDN = 제어와 전달을 분리(구조)**, **NFV = 장비 기능을 소프트웨어로(가상화)**. 서로 보완 관계.

### 15-2. 클라우드 컴퓨팅 서비스 모델

| 모델 | 제공하는 것 | 사용자가 관리하는 것 | 예 |
|---|---|---|---|
| **IaaS** (Infrastructure) | **서버·스토리지·네트워크 등 인프라(가상 머신)** | OS, 미들웨어, 앱 | AWS EC2 |
| **PaaS** (Platform) | **개발·실행 플랫폼**(OS, 런타임, DB 등) | 앱과 데이터 | Google App Engine, Heroku |
| **SaaS** (Software) | **완성된 응용 소프트웨어** | 거의 없음(사용만) | 웹메일, Google Docs, Microsoft 365 |

- 아래에서 위로 쌓이는 순서: **IaaS → PaaS → SaaS** (위로 갈수록 사용자가 관리할 것이 줄어듦)
- 배포 모델: **퍼블릭(공용) / 프라이빗(사설) / 하이브리드** 클라우드

### 15-3. 기타 용어

- **IoT (Internet of Things, 사물인터넷)**: 사물에 센서·통신 기능을 넣어 인터넷으로 정보를 주고받는 기술. Zigbee, BLE, LoRa 등 저전력 통신 사용.
- **엣지 컴퓨팅**: 데이터를 중앙 클라우드가 아닌 **발생 지점 가까이에서 처리** → 지연 감소.
- **가상화(Virtualization)**: 하나의 물리 자원을 여러 개의 논리 자원처럼 사용 (하이퍼바이저).

> 💡 **시험 포인트:** "**제어부/데이터부 분리 = SDN (OpenFlow)**", "**장비 기능을 소프트웨어로 = NFV**", "**완성된 앱 제공 = SaaS / 인프라 제공 = IaaS**".

## ★ 핵심사항 (시험 직전 10분 암기용)

- OSI 7계층(위→아래): **응용-표현-세션-전송-네트워크-데이터링크-물리**
- PDU: **전송=세그먼트, 네트워크=패킷, 데이터링크=프레임, 물리=비트**
- 장비: **물리=리피터·허브 / 데이터링크=브리지·스위치 / 네트워크=라우터 / 응용(상위)=게이트웨이**
- **라우팅·IP = 3계층**, **MAC·프레임 = 2계층**, **암호화·압축·코드변환 = 6계층**, **동기점·대화제어 = 5계층**, **종단 간·포트 = 4계층**
- TCP/IP 4계층: **응용(5~7) / 전송(4) / 인터넷(3) / 네트워크 접근(1~2)**
- **무전기 = 반이중, 전화 = 전이중, TV = 단방향**
- **비동기 = 문자 단위 + Start/Stop 비트, 동기 = 블록 단위 + 클록 동기**
- **UTP 최대 100m**, Cat5e부터 1Gbps, 커넥터 RJ-45
- **광섬유 = 전반사, EMI 없음, 보안 우수 / 싱글모드 = 코어 작고 레이저·장거리**
- 동축 **50Ω = 데이터, 75Ω = CATV**
- **스타형 = 중앙 장비 고장 시 전체 마비**, **버스형 = 터미네이터**
- **메시형 회선 수 = n(n−1)/2, 포트 수 = n−1**
- **회선 교환 = 전용 경로·실시간**, **데이터그램 = 비연결·독립 경로·순서 바뀜**, **가상 회선 = 논리 경로·순서 보장**
- **FDM = 보호 대역**, **통계적 TDM = 데이터 있는 곳만 동적 할당**, **WDM = 광 파장**, **CDM = 코드**
- **PCM: 표본화 → 양자화 → 부호화** (양자화 잡음은 양자화 단계)
- **나이퀴스트: 최고 주파수 × 2 이상 표본화** (4kHz → 8,000회/초, 125μs)
- **샤논 C = B log₂(1+S/N)**
- **bps = baud × 심볼당 비트 수** (4진=2, 8진=3, 16진=4)
- **FEC(수신 측이 정정) = 해밍 코드**, **BEC(재전송) = ARQ**
- **해밍 패리티 수: 2ᵖ ≥ m + p + 1** (데이터 4비트 → 3개)
- **패리티 = 짝수 개 오류 검출 불가, 정정 불가**, **CRC = 집단 오류 검출**
- **Stop-and-Wait = 1개씩**, **Go-Back-N = 오류 프레임부터 전부**, **Selective Repeat = 오류 프레임만**
- **CSMA/CD = 802.3 유선, 잼 신호 / CSMA/CA = 802.11 무선, RTS/CTS / 토큰 = 충돌 없음**
- IEEE: **802.2 LLC, 802.3 이더넷, 802.5 토큰링, 802.11 무선LAN, 802.15.1 블루투스, 802.15.4 Zigbee, 802.16 WiMAX**
- **10Base5 500m / 10Base2 185m / 10Base-T 100m**, **1000Base-SX = 멀티모드 단파장, LX = 장파장**
- **802.11a = 5GHz 54M, b = 2.4GHz 11M, g = 2.4GHz 54M, n = MIMO 600M, ac = 5GHz, ax = Wi-Fi 6(OFDMA)**
- **HDLC 플래그 01111110, 비트 스터핑, I(정보)/S(감독)/U(비번호)**, 모드 **NRM/ABM/ARM**
- **PPP: LCP = 링크 설정, NCP = 네트워크 계층 설정, 인증 PAP/CHAP**
- **ATM = 53바이트 셀(5+48)**, **프레임 릴레이 = X.25 간소화·DLCI**
- **ISDN BRI = 2B+D = 144kbps**, PRI = 23B+D(1.544M) / 30B+D(2.048M)
- **ADSL = 비대칭(하향 > 상향)**
- **NFC = 13.56MHz·10cm**, **Zigbee = 저전력 저속 센서**, **블루투스 = 피코넷(마스터1+슬레이브7)**
- **SDN = 제어/데이터 평면 분리(OpenFlow)**, **NFV = 네트워크 기능 가상화**
- **IaaS = 인프라, PaaS = 플랫폼, SaaS = 완성 소프트웨어**

## ⚠️ 헷갈리는 함정 포인트

| 헷갈리는 쌍 | 구분법 |
|---|---|
| 데이터링크 계층 vs 전송 계층의 오류/흐름 제어 | 데이터링크 = **인접 노드 간(Hop-to-Hop)**, 전송 = **종단 간(End-to-End)** |
| 세션 계층 vs 표현 계층 | 세션 = **대화·동기점**, 표현 = **암호화·압축·형식 변환** |
| 패킷 vs 세그먼트 vs 프레임 | 3계층 **패킷**, 4계층 **세그먼트**, 2계층 **프레임** ("네트워크-세그먼트"는 오답!) |
| 싱글모드 vs 멀티모드 | 싱글 = **코어 작고 장거리·레이저**, 멀티 = **코어 크고 단거리·LED** (반대로 써놓은 선지 주의) |
| 10Base2 vs 10Base5 vs 10Base-T | **185m / 500m / 100m** |
| 1000Base-SX vs LX | **S=Short(단파장, 멀티모드)**, **L=Long(장파장, 싱글모드 가능)** |
| 동기식 TDM vs 통계적 TDM | 동기식 = **고정 슬롯(낭비)**, 통계적 = **동적 할당(주소 필요)** |
| FDM vs WDM | FDM = 전기 신호 **주파수**, WDM = 광섬유 **파장** |
| FEC vs BEC | FEC = **수신 측 직접 정정(해밍)**, BEC = **재전송 요청(ARQ)** |
| Go-Back-N vs Selective Repeat | GBN = **오류 이후 전부**, SR = **오류 난 것만(버퍼 필요)** |
| CSMA/CD vs CSMA/CA | CD = **유선·충돌 감지·잼 신호**, CA = **무선·충돌 회피·RTS/CTS** |
| 802.15.1 vs 802.15.4 | **.1 = 블루투스**, **.4 = Zigbee** |
| 802.11a vs 802.11b | **a = 5GHz 54Mbps**, **b = 2.4GHz 11Mbps** (알파벳 순서와 출시·속도 순서가 반대라 헷갈림) |
| baud vs bps | baud = **신호 변화 수**, bps = **비트 수** → bps가 baud보다 크거나 같음 |
| 가상 회선 vs 데이터그램 | 가상 회선 = **연결형·순서 보장**, 데이터그램 = **비연결·순서 뒤바뀔 수 있음** |
| ISDN BRI vs PRI | BRI = **2B+D (144kbps)**, PRI = **23B+D 또는 30B+D** |
| SDN vs NFV | SDN = **제어/전달 분리**, NFV = **장비 기능 소프트웨어화** |

## 🧠 암기 팁

- **OSI 7계층**: "**물데네전세표응**" (아래→위) / "**응표세전네데물**" (위→아래)
- **PDU 4→1계층**: "**세패프비**" (세그먼트-패킷-프레임-비트)
- **PCM**: "**표양부**" → 표본화·양자화·부호화 ("표를 양껏 부어라")
- **802 표준**: "**3이더 5토링 11와이파이 15블루투스**"
- **802.11**: "**a는 5(에이-오), b는 11(비-일일)**", "g는 b의 속도 업그레이드판(54)"
- **메시형**: "**사람 n명이 서로 악수하는 횟수 = n(n−1)/2**"
- **해밍 거리**: "검출은 d−1, 정정은 그 절반 내림"
- **HDLC 프레임**: "**I**는 정보(Information), **S**는 감시(Supervisory), **U**는 번호 없음(Unnumbered)"
- **ISDN BRI**: "**2B+D, 일사사(144)**"
- **ATM 셀**: "**오(5) 사팔(48) = 오삼(53)**"
- **클라우드**: "**I**(인프라)-**P**(플랫폼)-**S**(소프트웨어) — 아래층부터 쌓는 집"

| 일반-01 | ① | **네트워크 계층(3계층)** 이 IP 같은 논리 주소와 라우팅을 담당. 데이터링크는 MAC·프레임, 전송은 종단 간 신뢰성, 세션은 대화 제어. |
