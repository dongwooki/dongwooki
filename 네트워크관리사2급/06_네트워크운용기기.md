# 06. 네트워크 운용기기

> **과목**: 네트워크 운용기기
> **출제 비중 체감**: ★★★☆☆ (문항 수는 적은 편이지만, 장비 계층·스위치 기능·STP·RAID는 거의 매회 나오는 "점수 주는" 파트)
> **목표 공부시간**: 2~3시간 (본문 1.5~2시간 + 연습문제 40분)

---

## 이 노트에서 다루는 것

- 네트워크 장비 한눈에 보기 (동작 계층·기능 비교표), NIC와 MAC 주소
- 장비별 상세: 리피터, 허브, 브리지, 스위치(L2/L3/L4/L7), 라우터, 게이트웨이, AP, 모뎀·CSU/DSU
- 충돌 도메인 vs 브로드캐스트 도메인 (개수 세기 예제)
- 스위치(브리지) 동작: Learning / Flooding / Forwarding / Filtering / Aging
- 스위칭 방식: Store-and-Forward / Cut-Through / Fragment-Free
- 이더넷 프레임 구조
- VLAN: 액세스/트렁크, IEEE 802.1Q, ISL, Native VLAN, VTP, VLAN 간 통신
- STP: 루트 브리지 선출, 포트 역할·상태, 타이머, RSTP·MSTP
- 링크 집합(EtherChannel/LACP), PoE
- UTP 케이블 결선: T568A/B, 다이렉트·크로스오버·롤오버, Auto-MDIX
- 라우터 내부 구성요소와 부팅 순서
- Cisco IOS 모드와 대표 명령어 (정적 경로 포함)
- 서버·스토리지: RAID 0/1/5/6/1+0, DAS/NAS/SAN, iSCSI, 핫스왑
- 고가용성: 이중화, 로드밸런싱, VRRP/HSRP/GLBP
- 무선 장비(AP, SSID, 무선 컨트롤러), UPS

## 1. 네트워크 장비 한눈에 보기

처음 공부할 때 가장 중요한 것은 **"이 장비는 OSI 몇 계층에서 일하는가?"** 입니다.
장비가 어느 계층에서 동작하는지 알면, 그 장비가 **무엇을 보고(주소)** 판단하는지, **무엇을 나눌 수 있는지(도메인)** 가 자동으로 따라옵니다.

| 계층 | 장비 | 판단 기준(보는 주소) | 하는 일 한 줄 요약 |
|---|---|---|---|
| 1계층 물리 | 리피터, 허브(더미 허브) | 없음 (전기 신호만 봄) | 약해진 신호를 재생·증폭해서 그대로 뿌림 |
| 2계층 데이터링크 | 브리지, L2 스위치, NIC(랜카드) | **MAC 주소** | MAC 주소 테이블을 보고 필요한 포트로만 전달 |
| 3계층 네트워크 | 라우터, L3 스위치 | **IP 주소** | 라우팅 테이블을 보고 최적 경로로 패킷 전달 |
| 4계층 전송 | L4 스위치 | IP + **포트 번호**(TCP/UDP) | 서버 부하 분산(로드밸런싱) |
| 7계층 응용 | L7 스위치 | URL, 쿠키, HTTP 헤더 등 **콘텐츠** | 콘텐츠 기반 부하 분산·필터링 |
| 상위 계층(전 계층) | 게이트웨이 | 프로토콜 전체 | 서로 다른 프로토콜/네트워크 간 **프로토콜 변환** |

> 참고: NIC는 물리 계층(신호 송수신)과 데이터링크 계층(MAC 주소, 프레임 처리)에 걸쳐 동작하지만, 시험에서는 보통 **2계층 장비**로 분류합니다.

### 1-1. NIC(Network Interface Card, 랜카드)와 MAC 주소

NIC는 컴퓨터를 네트워크에 연결하는 카드입니다. 하는 일:

- 컴퓨터 내부의 **병렬 데이터 ↔ 케이블의 직렬 신호** 변환
- 프레임 생성(헤더 붙이기)과 오류 검출(FCS)
- **MAC 주소**를 가지고 있어 자기에게 온 프레임인지 판단

**MAC 주소(물리 주소, 하드웨어 주소)**

| 항목 | 내용 |
|---|---|
| 크기 | **48비트 (6바이트)** |
| 표기 | 16진수 **12자리**, 예: `00-1A-2B-3C-4D-5E`, `00:1A:2B:3C:4D:5E`, `001A.2B3C.4D5E` |
| 앞 24비트 | **OUI** (Organizationally Unique Identifier) — **제조사 식별 번호**, IEEE가 할당 |
| 뒤 24비트 | 제조사가 붙이는 **일련번호** (장치 고유 번호) |
| 특징 | 원칙적으로 전 세계에서 유일, NIC의 ROM에 기록(BIA, Burned-In Address) |
| 브로드캐스트 MAC | `FF-FF-FF-FF-FF-FF` (48비트 모두 1) |
| Windows 확인 | `ipconfig /all` → "물리적 주소" / `getmac` |
| Linux 확인 | `ip link`, `ifconfig` |

- 첫 바이트의 최하위 비트(I/G 비트)가 1이면 **멀티캐스트/그룹 주소**, 0이면 유니캐스트입니다.
- **중요한 동작 원리**: IP 주소는 출발지→목적지까지 그대로 유지되지만, **MAC 주소는 라우터를 하나 지날 때마다(홉마다) 바뀝니다.** 라우터가 새 프레임을 만들 때 출발지 MAC은 자기 출구 인터페이스의 MAC으로, 목적지 MAC은 다음 홉의 MAC으로 바꿔 붙이기 때문입니다.

> 💡 시험 포인트: "MAC 주소 48비트, 앞 24비트 OUI(제조사), 16진수 12자리", "MAC은 홉마다 바뀌고 IP는 유지된다"가 옳고/틀림 선지로 나온다.

## 2. 장비별 상세

### 2-1. 리피터(Repeater) — 1계층

- 케이블로 신호를 멀리 보내면 **감쇠(약해짐)** 됩니다. 리피터는 이 신호를 **재생·증폭**해 전송 거리를 늘립니다.
- 주소를 보지 않습니다. 들어온 신호를 그대로 반대편에 내보낼 뿐이므로 **충돌 도메인도, 브로드캐스트 도메인도 나누지 못합니다.**
- 노이즈까지 같이 증폭되는 단순 증폭기(앰프)와 달리, 디지털 리피터는 신호를 **재생(regeneration)** 합니다.

### 2-2. 허브(Hub) — 1계층

- **"포트가 여러 개인 리피터(멀티포트 리피터)"** 라고 생각하면 됩니다.
- 한 포트로 들어온 신호를 **나머지 모든 포트로 그대로 전송** → 모든 PC가 같은 신호를 받습니다.
- 한 번에 한 장치만 전송 가능(**반이중, Half-duplex**) → 동시에 보내면 충돌 발생 → CSMA/CD로 처리.
- **대역폭 공유**: 10Mbps 허브에 PC 10대가 붙으면 10대가 10Mbps를 나눠 씁니다.
- 허브 전체가 **하나의 충돌 도메인**이자 **하나의 브로드캐스트 도메인**.

| 허브 종류 | 설명 |
|---|---|
| 더미 허브(Dummy Hub) | 관리 기능 없이 신호만 중계하는 단순 허브 |
| 인텔리전트 허브(Intelligent Hub) | 관리 기능(포트 상태 모니터링, SNMP 등) 탑재 — "매니지드(관리형) 허브" |
| 스택형 허브(Stackable Hub) | 여러 허브를 케이블로 쌓아 하나처럼 동작 (포트 확장) |
| 스위칭 허브 | 사실상 **스위치** (2계층, MAC 기반 전달) |

### 2-3. 브리지(Bridge) — 2계층

- 두 개(또는 소수)의 네트워크 세그먼트를 연결하고, **MAC 주소를 보고 프레임을 전달할지 말지 결정**합니다.
- 같은 세그먼트 안의 통신은 다른 쪽으로 넘기지 않으므로(필터링) **충돌 도메인을 분할**합니다.
- 브로드캐스트 프레임은 그대로 전달하므로 **브로드캐스트 도메인은 분할하지 못합니다.**
- 처리를 **소프트웨어**로 하므로 스위치보다 느리고 포트 수가 적습니다.

| 브리지 종류 | 설명 |
|---|---|
| 투명 브리지(Transparent) | 이더넷에서 사용, 스스로 MAC을 학습. 호스트는 브리지 존재를 모름 |
| 소스 라우팅 브리지(Source Routing) | 토큰링에서 사용, 송신 호스트가 경로를 지정 |
| 변환 브리지(Translational) | 서로 다른 2계층 매체(예: 이더넷 ↔ 토큰링) 연결 |

### 2-4. 스위치(Switch) — L2 / L3 / L4 / L7

**L2 스위치** (일반적으로 "스위치"라고 하면 이것)
- "포트가 많은 고속 브리지". **하드웨어(ASIC)** 로 처리해 빠릅니다.
- **포트마다 독립된 충돌 도메인** → 충돌이 거의 없음, **전이중(Full-duplex)** 가능.
- **포트마다 전용 대역폭**: 100Mbps 스위치면 포트마다 100Mbps.
- 여러 포트 쌍이 **동시에** 통신 가능.
- 브로드캐스트는 모든 포트로 전달 → **브로드캐스트 도메인은 분할하지 못함** (VLAN을 쓰면 분할 가능).

**브리지 vs 스위치**

| 비교 | 브리지 | 스위치 |
|---|---|---|
| 처리 방식 | 소프트웨어 | **하드웨어(ASIC)** |
| 속도 | 느림 | 빠름 |
| 포트 수 | 적음(2~16 정도) | 많음(수십 개) |
| 스위칭 방식 | Store-and-Forward 위주 | Store-and-Forward, Cut-Through, Fragment-Free |
| 공통점 | 2계층, MAC 기반, 충돌 도메인 분할, 브로드캐스트 도메인은 분할 못함 | |

**L3 스위치**
- L2 스위치 + **라우팅 기능(IP 기반 전달)** 을 하드웨어로 수행.
- 주 용도: **VLAN 간 라우팅(Inter-VLAN Routing)**. VLAN마다 SVI(`interface vlan 10`)라는 가상 인터페이스에 IP를 주고 게이트웨이로 씁니다.
- 라우터보다 빠르지만 WAN 인터페이스·고급 기능은 라우터가 더 풍부.

**L4 스위치**
- IP 주소 + **TCP/UDP 포트 번호**까지 보고 트래픽을 여러 서버로 분산 → **서버 로드밸런싱(부하 분산)** 장비.
- 예: 웹 서버 3대 앞에 L4 스위치를 두고 가상 IP(VIP) 하나로 받은 80번 포트 요청을 3대에 나눠 줌.

**L7 스위치**
- 패킷의 **애플리케이션 데이터(URL, 쿠키, HTTP 헤더 등)** 까지 보고 분산·제어.
- 예: `/image/*` 요청은 이미지 서버로, `/api/*`는 API 서버로. 콘텐츠 기반 필터링도 가능.

### 2-5. 라우터(Router) — 3계층

- 서로 다른 네트워크(서브넷)를 연결하고, **IP 주소를 보고 라우팅 테이블에 따라 최적 경로로 패킷을 전달**합니다.
- **브로드캐스트를 다른 인터페이스로 넘기지 않음** → **브로드캐스트 도메인을 분할**합니다. (당연히 충돌 도메인도 분할)
- 각 인터페이스는 서로 다른 네트워크에 속해야 함.
- 라우팅 테이블은 **정적 경로(관리자가 직접 입력)** 또는 **동적 라우팅 프로토콜(자동 학습)** 로 만듭니다. (라우팅 프로토콜 이론은 TCP/IP 노트 참고)
- 부가 기능: 패킷 필터링(ACL), NAT, QoS 등.

### 2-6. 게이트웨이(Gateway) — 상위 계층(전 계층)

- **서로 다른 프로토콜/구조를 가진 네트워크를 연결**하며 **프로토콜 변환**을 수행.
- 예: 이메일 게이트웨이, VoIP 게이트웨이(인터넷 전화 ↔ 일반 전화망), 메인프레임 ↔ TCP/IP 네트워크.
- 시험에서는 "OSI 전 계층(주로 4~7 상위 계층)에서 동작하며 프로토콜 변환" 으로 나옵니다.
- 참고: PC 설정의 **"기본 게이트웨이(Default Gateway)"** 는 "내 네트워크 밖으로 나갈 때 보내는 출구 = 보통 라우터의 IP"를 뜻합니다.

### 2-7. AP(Access Point, 무선 접속 장치) — 2계층

- 무선 단말(스마트폰, 노트북)을 유선 네트워크에 연결해 주는 장치. 유선 LAN ↔ 무선 LAN의 **브리지** 역할.
- 자세한 내용은 15절 참고.

### 2-8. 모뎀, CSU/DSU — WAN 접속 장비 (1계층)

| 장비 | 회선 | 하는 일 |
|---|---|---|
| **모뎀(MODEM)** | **아날로그** 회선(전화선 등) | 디지털 신호 ↔ 아날로그 신호 **변조(Modulation)/복조(Demodulation)** |
| **CSU/DSU** | **디지털** 전용선(T1/E1 등) | 라우터 같은 장비(DTE)를 디지털 전용 회선에 연결. DSU는 단극성 신호를 회선용 양극성 신호로 변환, CSU는 회선 종단·프레임 동기·회선 보호 |

- 두 장비 모두 통신 회선 쪽 장비이므로 **DCE**(데이터 회선 종단 장치), 이들에 붙는 PC·라우터는 **DTE**(데이터 단말 장치).

> 💡 시험 포인트: "장비 ↔ 계층" 짝 맞추기, "리피터/허브는 도메인 분할 X, 브리지/스위치는 충돌만, 라우터는 브로드캐스트까지", "L4는 포트 기반 로드밸런싱", "게이트웨이는 프로토콜 변환", "디지털 전용선 = CSU/DSU, 아날로그 = 모뎀".

## 3. 충돌 도메인 vs 브로드캐스트 도메인

### 3-1. 개념

| 구분 | 충돌 도메인(Collision Domain) | 브로드캐스트 도메인(Broadcast Domain) |
|---|---|---|
| 뜻 | 동시에 전송하면 **충돌이 일어날 수 있는 범위** | **브로드캐스트 프레임 하나가 전달되는 범위** |
| 너무 크면 | 충돌 증가 → 성능 저하 | 브로드캐스트 폭주 → 대역폭·CPU 낭비 |
| 분할하는 장비 | **브리지, 스위치, 라우터** | **라우터, L3 스위치** (L2 스위치는 **VLAN** 설정 시) |
| 분할 못 하는 장비 | 리피터, 허브 | 리피터, 허브, 브리지, (VLAN 없는) L2 스위치 |

| 장비 | 충돌 도메인 분할 | 브로드캐스트 도메인 분할 |
|---|:---:|:---:|
| 리피터 / 허브 | ✗ | ✗ |
| 브리지 / L2 스위치 | ○ (포트마다 1개) | ✗ (VLAN 시 ○) |
| 라우터 / L3 스위치 | ○ | ○ (인터페이스·VLAN마다 1개) |

### 3-2. 개수 세는 법 (공식처럼 외우기)

- **충돌 도메인** = 스위치·브리지·라우터의 **"사용 중인 포트(링크)" 하나당 1개**. 단, **허브에 묶인 장치들은 통째로 1개**.
- **브로드캐스트 도메인** = **라우터의 사용 중인 인터페이스 하나당 1개** (VLAN이 있으면 VLAN 하나당 1개).
- 장비와 장비를 잇는 링크(예: 라우터–스위치)도 충돌 도메인 1개입니다. 단, 그 링크 반대편이 허브라면 허브 쪽 전체와 합쳐서 1개.

### 3-3. 예제 1

```
              [Router]
             /        \
      (Fa0/0)          (Fa0/1)
          |                |
      [Switch]           [Hub]
      /  |  \            / | \
    PC1 PC2 PC3        PC4 PC5 PC6
```

- **충돌 도메인**
  - 스위치 쪽: 라우터–스위치 링크 1 + PC1·PC2·PC3 각 1 = **4개**
  - 허브 쪽: 라우터–허브 링크와 PC4~6이 전부 같은 허브 → **1개**
  - 합계 **5개**
- **브로드캐스트 도메인**: 라우터 인터페이스 2개 → **2개**

### 3-4. 예제 2 (VLAN이 있을 때)

- 스위치 1대에 PC 8대 연결, VLAN 10(4대), VLAN 20(4대)으로 나눔, 라우터 없음.
  - 충돌 도메인 = 사용 포트 8개 → **8개**
  - 브로드캐스트 도메인 = VLAN 2개 → **2개** (단, 라우터/L3가 없으므로 두 VLAN끼리는 통신 불가)

> 💡 시험 포인트: 그림 주고 "충돌 도메인/브로드캐스트 도메인 수는?" 계산형, 또는 "브로드캐스트 도메인을 나누는 장비는?" 단답형.

## 4. 스위치(브리지)의 동작 원리

스위치는 **MAC 주소 테이블(CAM 테이블)** 을 가지고 있습니다. 테이블은 "**어떤 MAC 주소가 몇 번 포트 너머에 있는지**"를 적은 표입니다.

| MAC 주소 | 포트 | 남은 시간 |
|---|---|---|
| AAAA.AAAA.AAAA | Fa0/1 | 280초 |
| BBBB.BBBB.BBBB | Fa0/2 | 120초 |

### 4-1. 5가지 기능

| 기능 | 언제 / 무엇을 | 기억 포인트 |
|---|---|---|
| **Learning (학습)** | 프레임이 들어오면 **출발지 MAC 주소**와 들어온 포트를 테이블에 기록 | 배우는 건 **출발지(Source)** MAC! |
| **Flooding (플러딩)** | 목적지 MAC이 **테이블에 없거나**, **브로드캐스트/멀티캐스트**이면 **들어온 포트를 제외한 모든 포트**로 전송 | "모르면 다 뿌린다" |
| **Forwarding (포워딩)** | 목적지 MAC이 테이블에 있으면 **해당 포트로만** 전송 | 아는 곳에만 보냄 |
| **Filtering (필터링)** | 목적지 MAC이 **들어온 포트와 같은 포트** 쪽에 있으면 **전송하지 않고 버림** | 같은 세그먼트 안 통신은 넘기지 않음 |
| **Aging (에이징)** | 일정 시간(Cisco 기본 **300초**) 동안 그 MAC으로부터 프레임이 안 오면 **테이블에서 삭제** | 오래된 정보 정리 |

### 4-2. 동작 시나리오 (처음 켠 스위치)

1. 스위치를 켜면 MAC 테이블은 **비어 있음**.
2. PC-A(포트1) → PC-B로 프레임 전송
   - Learning: "A는 포트1" 기록
   - 목적지 B는 테이블에 없음 → **Flooding** (포트1 제외 전 포트로)
3. PC-B(포트2)가 응답
   - Learning: "B는 포트2" 기록
   - 목적지 A는 포트1로 알고 있음 → **Forwarding** (포트1로만)
4. 이후 A↔B 통신은 둘 사이에서만 오감.

> 💡 시험 포인트: "스위치가 MAC 테이블을 만들 때 참조하는 주소 = 출발지 MAC", "목적지를 모를 때 = Flooding", "일정 시간 후 삭제 = Aging" 이 단골.

## 5. 스위칭 방식 (프레임을 언제 내보내는가)

| 방식 | 동작 | 오류 검사 | 지연(Latency) |
|---|---|---|---|
| **Store-and-Forward** | 프레임 **전체**를 버퍼에 저장한 후 **FCS(CRC)로 오류 검사**, 정상일 때만 전송 | **○ (오류 프레임 폐기)** | 가장 큼 (프레임 길이에 비례) |
| **Cut-Through** | 프레임의 **목적지 MAC 주소(처음 6바이트)** 만 읽고 **즉시 전송** | ✗ (오류 프레임도 그대로 전달) | **가장 작음** |
| **Fragment-Free** | 프레임의 **처음 64바이트**까지 받아본 후 전송 | 일부 (충돌 조각 Runt 걸러냄) | 중간 |

- **왜 64바이트?** 이더넷 최소 프레임 크기가 64바이트이고, 충돌은 대부분 처음 64바이트 안에서 일어나기 때문. 64바이트보다 짧은 충돌 조각(**Runt**)을 걸러냅니다. Cut-Through의 개량형이라 "**변형된 Cut-Through**" 라고도 부릅니다.
- **속도가 다른 포트 간 전송**(예: 100Mbps 포트 → 1Gbps 포트)에는 프레임을 일단 저장해야 하므로 **Store-and-Forward** 방식이 필요합니다.
- 대부분의 현대 스위치 기본값은 Store-and-Forward.

> 💡 시험 포인트: "처음 64바이트 = Fragment-Free", "목적지 주소만 보고 바로 = Cut-Through(가장 빠름, 오류 검사 X)", "전체 저장 후 CRC = Store-and-Forward(가장 신뢰성↑, 지연↑)".

## 6. 이더넷 프레임 구조 (Ethernet II)

```
| Preamble | SFD | 목적지 MAC | 출발지 MAC | Type | Data(Payload) | FCS |
|  7바이트  | 1   |   6바이트   |   6바이트   |  2   |   46~1500     |  4  |
```

| 필드 | 크기 | 설명 |
|---|---|---|
| Preamble(프리앰블) | 7바이트 | `10101010` 반복. 수신 측이 **비트 동기**를 맞추게 함 |
| SFD(Start Frame Delimiter) | 1바이트 | `10101011`. "이제 프레임 시작" 표시 |
| 목적지 MAC(DA) | 6바이트 | 받을 장치의 MAC. **목적지가 출발지보다 먼저** 온다 (그래야 Cut-Through 가능) |
| 출발지 MAC(SA) | 6바이트 | 보낸 장치의 MAC |
| Type / Length | 2바이트 | Ethernet II는 **상위 프로토콜 종류**(예: `0x0800` = IPv4, `0x0806` = ARP, `0x86DD` = IPv6). IEEE 802.3에서는 길이 |
| Data | **46~1500바이트** | 상위 계층 데이터. 46바이트보다 적으면 **패딩(Padding)** 으로 채움 |
| FCS(Frame Check Sequence) | 4바이트 | **CRC-32**로 계산한 **오류 검출** 값 |

**외울 숫자**

- 프레임 크기(목적지 MAC ~ FCS): **최소 64바이트 ~ 최대 1518바이트**
  - 최소: 6+6+2+46+4 = **64**
  - 최대: 6+6+2+1500+4 = **1518**
- 프리앰블+SFD(8바이트)는 프레임 크기 계산에서 **제외**하는 것이 일반적.
- **MTU(Maximum Transmission Unit)** = 한 프레임에 담을 수 있는 최대 데이터 크기 = 이더넷 **1500바이트**.
- 802.1Q 태그(4바이트)가 붙으면 최대 **1522바이트**.
- 1500바이트를 넘는 큰 프레임(약 9000바이트) = **점보 프레임(Jumbo Frame)**.
- 64바이트보다 작은 비정상 프레임 = **런트(Runt)**, 1518바이트보다 큰 비정상 프레임 = **자이언트(Giant)**.

> 💡 시험 포인트: "데이터 필드 46~1500", "프레임 64~1518", "FCS = 오류 검출(CRC)", "MTU 1500"이 숫자 문제로 나온다.

## 7. VLAN (Virtual LAN)

### 7-1. VLAN이란?

- **물리적 위치와 상관없이 스위치 포트를 논리적으로 묶어 별도의 네트워크처럼 쓰는 기술.**
- 한 대의 스위치를 여러 대의 "가상 스위치"로 쪼갠다고 생각하면 됩니다.
- **VLAN 하나 = 브로드캐스트 도메인 하나** → L2 스위치로도 브로드캐스트 도메인을 분할할 수 있게 됨.

**VLAN을 쓰는 이유(장점)**

1. **브로드캐스트 트래픽 감소** → 성능 향상
2. **보안 강화**: 부서별로 분리하면 다른 VLAN 트래픽을 볼 수 없음
3. **관리 유연성**: 자리를 옮겨도 포트의 VLAN만 바꾸면 됨 (케이블 재배선 불필요)
4. 비용 절감: 부서마다 스위치를 따로 살 필요 없음

**VLAN 구성 방식**

| 방식 | 설명 |
|---|---|
| **포트 기반(Static VLAN)** | 스위치 **포트 번호**에 VLAN을 지정. 가장 일반적 |
| **MAC 기반(Dynamic VLAN)** | 접속한 장치의 **MAC 주소**에 따라 VLAN 자동 할당 (VMPS 등) |
| 프로토콜 기반 | 3계층 프로토콜 종류에 따라 지정 |
| 서브넷(IP) 기반 | IP 서브넷에 따라 지정 |

### 7-2. 액세스 포트 vs 트렁크 포트

| 구분 | 액세스(Access) 포트 | 트렁크(Trunk) 포트 |
|---|---|---|
| 소속 VLAN | **하나의 VLAN**만 | **여러 VLAN**의 프레임을 한 링크로 전달 |
| 연결 대상 | PC, 프린터 등 **단말** | **스위치–스위치**, 스위치–라우터(Router-on-a-stick), 스위치–서버(가상화) |
| 태그 | 붙이지 않음 | **VLAN 태그를 붙여** 어느 VLAN 프레임인지 구분 |

### 7-3. 트렁크 프로토콜: IEEE 802.1Q vs ISL

| 구분 | **IEEE 802.1Q (dot1q)** | ISL (Inter-Switch Link) |
|---|---|---|
| 표준 | **IEEE 국제 표준** (모든 제조사) | **Cisco 전용** (현재는 거의 사용 안 함) |
| 방식 | 원래 프레임 내부(출발지 MAC과 Type 사이)에 **4바이트 태그 삽입** | 원래 프레임 **전체를 캡슐화**(26바이트 헤더 + 4바이트 CRC 추가) |
| Native VLAN | 있음 (태그 없이 전송) | 없음 |

**802.1Q 태그 4바이트 구성**

| 필드 | 크기 | 내용 |
|---|---|---|
| TPID | 16비트 | `0x8100` — "이 프레임은 802.1Q 태그가 있다" |
| PCP(Priority) | 3비트 | 우선순위(CoS, 802.1p) 0~7 |
| DEI(CFI) | 1비트 | 폐기 적격 표시 |
| **VID(VLAN ID)** | **12비트** | VLAN 번호. 2^12 = 4096개 → 0과 4095는 예약, **1~4094 사용** |

- 태그를 삽입하면 FCS를 **다시 계산**합니다.

**Native VLAN**
- 802.1Q 트렁크에서 **태그를 붙이지 않고 보내는 VLAN**. 기본값은 **VLAN 1**.
- 트렁크 양쪽 스위치의 Native VLAN이 일치해야 함.
- VLAN 1은 기본 VLAN(Default VLAN)으로 모든 포트가 처음에 소속되며 삭제할 수 없습니다.

### 7-4. VTP (VLAN Trunking Protocol) — Cisco 전용

여러 스위치에 VLAN 정보를 일일이 만들지 않고 **한 곳에서 만든 VLAN 정보를 트렁크로 자동 전파**하는 프로토콜.

| 모드 | VLAN 생성/삭제/수정 | 다른 스위치의 정보로 동기화 | VTP 광고 전달 |
|---|:---:|:---:|:---:|
| **Server** (기본값) | ○ | ○ | ○ (생성·전파) |
| **Client** | ✗ | ○ | ○ |
| **Transparent** | ○ (**자기 스위치에만** 적용) | ✗ | ○ (받은 광고를 **통과만** 시킴) |

### 7-5. VLAN 간 통신 (Inter-VLAN Routing)

- **서로 다른 VLAN = 서로 다른 브로드캐스트 도메인 = 서로 다른 네트워크(서브넷)** 이므로 **L2 스위치만으로는 통신 불가**.
- **3계층 장비가 필요**합니다:
  1. **라우터** — 라우터 인터페이스를 VLAN 수만큼 연결하거나, 하나의 물리 인터페이스를 **서브 인터페이스**로 나눠 트렁크로 연결(**Router-on-a-stick**)
  2. **L3 스위치** — VLAN마다 SVI(`interface vlan 10`)에 IP를 주고 하드웨어로 라우팅 (가장 일반적)

```
! 스위치 VLAN 설정 예 (Cisco)
Switch(config)# vlan 10
Switch(config-vlan)# name SALES
Switch(config)# interface fastethernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config)# interface gigabitethernet 0/1
Switch(config-if)# switchport mode trunk
Switch# show vlan brief

! Router-on-a-stick 예
Router(config)# interface fastethernet 0/0.10
Router(config-subif)# encapsulation dot1q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
```

> 💡 시험 포인트: "VLAN은 브로드캐스트 도메인 분할", "VLAN 간 통신은 라우터/L3 스위치 필요", "802.1Q = IEEE 표준, 4바이트 태그, VID 12비트", "ISL = Cisco 전용, 캡슐화", "VTP Transparent = 자기만 만들고 전달만".

## 8. STP (Spanning Tree Protocol)

### 8-1. 왜 필요한가?

- 장애 대비로 스위치를 **이중(여러 경로)** 으로 연결하면 **루프(Loop)** 가 생깁니다.
- 2계층 프레임에는 IP의 TTL 같은 "수명"이 없어서, 루프가 생기면 브로드캐스트가 **끝없이 돌며 폭증** → **브로드캐스트 스톰(Broadcast Storm)**, **MAC 테이블 불안정(플래핑)**, **중복 프레임 수신** 발생 → 네트워크 마비.
- **STP는 일부 포트를 차단(Blocking)해 논리적으로 루프 없는 트리 구조를 만들고, 장애 시 차단 포트를 열어 우회 경로를 제공**합니다.
- 표준: **IEEE 802.1D**. 스위치끼리 **BPDU(Bridge Protocol Data Unit)** 를 교환(기본 2초마다)하며 계산.

### 8-2. 동작 단계 (3단계로 외우기)

**① 루트 브리지(Root Bridge) 선출 — 네트워크당 1개**

- **Bridge ID(BID)가 가장 낮은 스위치**가 루트 브리지.
- **BID = 브리지 우선순위(Priority, 2바이트) + MAC 주소(6바이트) = 8바이트**
- 우선순위 기본값 **32768** (0~65535, 실제 설정은 4096 단위).
- 비교 순서: **① 우선순위가 낮은 것 → ② 같으면 MAC 주소가 낮은 것**.
- 관리자가 원하는 스위치를 루트로 만들려면 우선순위를 낮게 설정.

**② 루트 포트(Root Port) 선정 — 루트가 아닌 스위치마다 1개**

- 루트 브리지까지 **경로 비용(Path Cost)이 가장 낮은 포트**.
- 비용이 같으면 → 상대(송신) BID가 낮은 쪽 → 상대 포트 ID가 낮은 쪽.

| 링크 속도 | 경로 비용 (IEEE 기본값) |
|---|---|
| 10Mbps | 100 |
| 100Mbps | 19 |
| 1Gbps | 4 |
| 10Gbps | 2 |

**③ 지정 포트(Designated Port) 선정 — 세그먼트(링크)마다 1개**

- 각 세그먼트에서 루트 브리지까지 비용이 가장 낮은 쪽의 포트.
- **루트 브리지의 모든 포트는 지정 포트**.
- 루트 포트도 지정 포트도 아닌 나머지 포트 → **차단(Blocking) 포트 = 대체(Alternate)/Non-designated 포트**.

### 8-3. 포트 상태 (802.1D)

| 상태 | 데이터 프레임 전달 | MAC 주소 학습 | BPDU | 머무는 시간 |
|---|:---:|:---:|---|---|
| **Disabled** | ✗ | ✗ | ✗ | 관리자가 끈 포트 |
| **Blocking** | ✗ | ✗ | **수신만** | 최대 Max Age 20초 |
| **Listening** | ✗ | ✗ | 송·수신 (역할 결정 중) | Forward Delay 15초 |
| **Learning** | ✗ | **○** | 송·수신 | Forward Delay 15초 |
| **Forwarding** | **○** | ○ | 송·수신 | 정상 동작 |

- 순서: **Blocking → Listening → Learning → Forwarding**
- 최악의 경우 수렴 시간: 20 + 15 + 15 = **약 50초** (그래서 느리다는 단점)

### 8-4. STP 타이머 (기본값)

| 타이머 | 기본값 | 의미 |
|---|---|---|
| **Hello Time** | **2초** | 루트 브리지가 BPDU를 보내는 주기 |
| **Max Age** | **20초** | BPDU를 못 받았을 때 정보를 유지하는 최대 시간 |
| **Forward Delay** | **15초** | Listening, Learning 상태에 각각 머무는 시간 |

### 8-5. STP 개선 버전

| 프로토콜 | 표준 | 특징 |
|---|---|---|
| STP | IEEE **802.1D** | 원조. 수렴 30~50초 |
| **RSTP** (Rapid STP) | IEEE **802.1w** | **빠른 수렴(수 초 이내)**. 포트 상태 3개: **Discarding / Learning / Forwarding**. 포트 역할: Root, Designated, **Alternate, Backup** |
| **MSTP** (Multiple STP) | IEEE **802.1s** | 여러 VLAN을 묶어 **인스턴스별로 STP** 운영 → 부하 분산 |
| PVST+ | Cisco 전용 | VLAN마다 별도의 STP |

- **PortFast**(Cisco): PC·서버가 연결된 액세스 포트를 Listening/Learning을 건너뛰고 **즉시 Forwarding**으로 전환. (스위치끼리 연결된 포트에는 쓰면 안 됨)

> 💡 시험 포인트: "STP = 802.1D, 루프 방지", "루트 브리지 = BID(우선순위+MAC) **가장 낮은** 것", "포트 상태 순서", "MAC만 배우고 전달 안 함 = Learning", "Hello 2 / Max Age 20 / Forward Delay 15", "RSTP = 802.1w".

## 9. 링크 집합(EtherChannel / LACP)과 PoE

### 9-1. 링크 집합 (Link Aggregation)

- 스위치 간 여러 개의 물리 링크를 **하나의 논리 링크로 묶어** 대역폭을 늘리고 이중화하는 기술.
  - 예: 1Gbps 링크 4개를 묶어 최대 4Gbps 논리 링크.
- STP는 묶인 링크를 **하나의 링크로 보므로** 차단하지 않음 → 대역폭 낭비 없음.
- 하나가 끊어져도 나머지로 계속 통신(장애 대비).
- Cisco 장비에서는 **EtherChannel**이라고 부르며 보통 **최대 8개** 링크를 묶음.

| 협상 프로토콜 | 표준 |
|---|---|
| **LACP** (Link Aggregation Control Protocol) | **IEEE 802.3ad** (현재 802.1AX로 이관) — 표준 |
| PAgP (Port Aggregation Protocol) | Cisco 전용 |

### 9-2. PoE (Power over Ethernet)

- **UTP 랜 케이블로 데이터와 전원을 함께 공급**하는 기술. 별도 전원 공사 없이 **IP 전화기, 무선 AP, IP 카메라(CCTV)** 등에 전원 공급.
- 전원을 주는 쪽(PoE 스위치) = **PSE**, 받는 쪽(AP, 카메라) = **PD**.

| 표준 | 별칭 | 포트당 최대 전력(PSE 기준) |
|---|---|---|
| **IEEE 802.3af** | PoE | 약 **15.4W** |
| **IEEE 802.3at** | **PoE+** | 약 **30W** |
| IEEE 802.3bt | PoE++ | 약 60W / 90W |

> 💡 시험 포인트: "여러 링크를 하나로 = 링크 집합, LACP = 802.3ad", "랜선으로 전원 공급 = PoE, 802.3af/at".

## 10. UTP 케이블 결선

### 10-1. T568A / T568B 핀 배열 (8핀, RJ-45)

| 핀 | T568A | T568B |
|---|---|---|
| 1 | 흰녹 | **흰주** |
| 2 | 녹 | **주** |
| 3 | 흰주 | **흰녹** |
| 4 | 파 | 파 |
| 5 | 흰파 | 흰파 |
| 6 | 주 | **녹** |
| 7 | 흰갈 | 흰갈 |
| 8 | 갈 | 갈 |

- T568A와 T568B는 **주황 쌍과 녹색 쌍(1·2번 ↔ 3·6번)의 위치만 서로 바뀐 것**입니다.
- 10/100Mbps 이더넷은 **1, 2번(송신)과 3, 6번(수신)** 4가닥만 사용. 1Gbps(1000BASE-T)는 8가닥 모두 사용.
- 국내 실무에서는 주로 **T568B**를 많이 씁니다.

### 10-2. 케이블 종류와 사용처

| 케이블 | 결선 | 사용처 |
|---|---|---|
| **다이렉트(Straight-through)** | 양쪽 **같은** 규격 (B–B 또는 A–A) | **서로 다른 종류** 장비: PC–스위치, PC–허브, 스위치–라우터, 허브–라우터 |
| **크로스오버(Crossover)** | 한쪽 **A**, 한쪽 **B** (송신↔수신 교차) | **같은 종류** 장비: **PC–PC, 스위치–스위치, 허브–허브, 라우터–라우터, PC–라우터** |
| **롤오버(Rollover)** (콘솔 케이블) | 한쪽의 1~8번이 반대쪽 8~1번으로 **완전히 뒤집힘** | PC의 시리얼(COM) 포트 ↔ 라우터/스위치 **콘솔 포트** (초기 설정용) |

**쉽게 외우기**: PC와 라우터는 "단말 같은 장비(MDI)", 허브와 스위치는 "중계 장비(MDI-X)".
- **다른 그룹끼리 = 다이렉트**, **같은 그룹끼리 = 크로스**.
- 그래서 **PC–라우터는 크로스**가 맞습니다(둘 다 같은 그룹).

**Auto-MDIX**
- 포트가 상대 장비를 감지해 **송·수신 핀을 자동으로 바꿔 주는 기능**. 이 기능이 있으면 다이렉트/크로스 어느 것을 써도 동작합니다. (시험 문제는 보통 "Auto-MDIX가 없다고 가정"하고 묻습니다.)

> 💡 시험 포인트: "스위치–스위치 연결 케이블 = 크로스오버", "콘솔 접속 = 롤오버", "T568A/B 1·2번 색상".

## 11. 라우터 구성요소와 부팅 순서

### 11-1. 내부 구성요소 (★매우 자주 출제)

| 구성요소 | 휘발성 | 저장 내용 / 역할 |
|---|---|---|
| **CPU** | - | 명령 처리, 라우팅 계산 |
| **ROM** | 비휘발성 | **POST**(전원 켤 때 하드웨어 자가 진단), **Bootstrap**(IOS를 찾아 올리는 프로그램), ROMMON(비상 모드), (구형) Mini IOS |
| **Flash** | 비휘발성 | **IOS(운영체제) 이미지** 저장. 지워도 다시 쓸 수 있는 메모리 |
| **NVRAM** | 비휘발성 | **startup-config**(시작 설정 파일) 저장, 설정 레지스터 |
| **RAM(DRAM)** | **휘발성** (전원 끄면 사라짐) | **running-config**(현재 동작 설정), **라우팅 테이블**, ARP 캐시, 패킷 버퍼, 실행 중인 IOS |

**외우기**: "**R**OM은 **부팅**, **F**lash는 **IOS**, **NV**RAM은 **시작 설정(startup)**, **RAM**은 **현재 설정(running)**"

**인터페이스/포트**
- LAN 인터페이스: Ethernet, FastEthernet(Fa), GigabitEthernet(Gi)
- WAN 인터페이스: Serial(S) — CSU/DSU 연결
- **Console 포트**: 롤오버 케이블로 PC와 직접 연결, **초기 설정·관리**용
- **AUX 포트**: 모뎀을 연결해 **원격 관리**(전화 회선 경유)

### 11-2. 라우터 부팅 순서

1. **POST** (ROM) — 하드웨어 점검
2. **Bootstrap 로드** (ROM) — IOS 찾기 시작
3. **IOS 로드** — 보통 **Flash**에서 찾아 RAM으로 올림 → 없으면 **TFTP 서버** → 그래도 없으면 **ROMMON** 모드
4. **설정 파일 로드** — **NVRAM의 startup-config**를 RAM으로 복사해 running-config로 사용 → 없으면 TFTP → 그래도 없으면 **Setup 모드(초기 설정 대화 모드)**

- 설정 레지스터(Configuration Register) 기본값 `0x2102` = 정상 부팅. `0x2142` = NVRAM의 startup-config를 무시하고 부팅(**비밀번호 복구** 시 사용).

> 💡 시험 포인트: "startup-config 저장 위치 = NVRAM", "IOS 저장 = Flash", "running-config·라우팅 테이블 = RAM(휘발성)", "POST·부트스트랩 = ROM", "부팅 순서 POST → Bootstrap → IOS → Config".

### 12-3. 정적 경로(Static Route) 설정 형식

```
Router(config)# ip route [목적지 네트워크] [서브넷 마스크] [다음 홉 IP 또는 출구 인터페이스]

예) 기본 경로(Default Route): 모르는 목적지는 전부 10.0.0.1로
```

- **전역 설정 모드**에서 입력.

## 13. 서버·스토리지: RAID, DAS/NAS/SAN

### 13-1. RAID (Redundant Array of Independent Disks)

여러 개의 디스크를 묶어 **성능(속도)** 이나 **안정성(내결함성)** 을 높이는 기술.
- **스트라이핑(Striping)**: 데이터를 쪼개 여러 디스크에 **나눠** 저장 → 속도↑
- **미러링(Mirroring)**: 같은 데이터를 두 디스크에 **똑같이** 저장 → 안정성↑
- **패리티(Parity)**: 데이터로 계산한 **복구용 정보** → 디스크 하나가 고장 나도 나머지로 계산해서 복구

| RAID | 방식 | 최소 디스크 | 사용 가능 용량 (N개, 디스크당 D) | 내결함성 | 특징 |
|---|---|:---:|---|---|---|
| **RAID 0** | 스트라이핑 | **2** | **N × D (100%)** | **없음** (1개 고장 = 전체 손실) | 가장 빠름, 가장 위험 |
| **RAID 1** | 미러링 | **2** | **N × D ÷ 2 (50%)** | 1개 고장 허용(쌍당) | 안정성 높음, 용량 효율 낮음 |
| RAID 2 | 비트 단위 + **해밍 코드** | - | - | - | 사용 안 함 |
| RAID 3 | 바이트 단위 + **전용 패리티 디스크** | 3 | (N−1) × D | 1개 | 사용 거의 안 함 |
| RAID 4 | 블록 단위 + **전용 패리티 디스크** | 3 | (N−1) × D | 1개 | 패리티 디스크 병목 |
| **RAID 5** | 블록 스트라이핑 + **분산 패리티** | **3** | **(N−1) × D** | **1개** 고장 허용 | 가장 널리 사용 |
| **RAID 6** | 블록 스트라이핑 + **이중 분산 패리티** | **4** | **(N−2) × D** | **2개** 동시 고장 허용 | RAID 5보다 안전, 쓰기 느림 |
| **RAID 1+0 (10)** | 미러링 후 스트라이핑 | **4** | **N × D ÷ 2 (50%)** | 미러 쌍마다 1개 | 성능+안정성, 비용 높음 |

**계산 연습**
- 1TB × 4개 → RAID 0 = 4TB / RAID 1(4개를 미러로 운용 시) = 2TB / RAID 5 = 3TB / RAID 6 = 2TB / RAID 10 = 2TB
- 2TB × 5개 → RAID 5 = (5−1)×2 = **8TB**, RAID 6 = (5−2)×2 = **6TB**

**핫스왑(Hot Swap)과 핫스페어(Hot Spare)**
- **핫스왑**: 시스템 전원을 끄지 않고 디스크(부품)를 교체할 수 있는 기능.
- **핫스페어**: 평소엔 대기하다가 디스크 고장 시 자동으로 대신 투입되는 예비 디스크.

> RAID는 장애 대비이지 **백업이 아닙니다**. 실수로 지운 파일은 모든 디스크에서 같이 지워집니다.
> (Windows Server의 소프트웨어 볼륨 — 스팬/스트라이프/미러/RAID-5 볼륨 — 은 Windows 노트 참고)

### 13-2. DAS / NAS / SAN

| 구분 | **DAS** (Direct Attached Storage) | **NAS** (Network Attached Storage) | **SAN** (Storage Area Network) |
|---|---|---|---|
| 연결 | 서버에 **직접** 연결 (SCSI, SAS, SATA 케이블) | 기존 **LAN(이더넷)** 에 연결 | **스토리지 전용 고속 네트워크** |
| 접근 단위 | 블록 | **파일 단위** | **블록 단위** |
| 프로토콜 | SCSI/SAS | **NFS, SMB/CIFS** | **Fibre Channel(FC)**, **iSCSI**, FCoE |
| 공유 | 어려움 (해당 서버 전용) | **쉬움** (여러 클라이언트가 파일 공유) | 여러 서버가 블록 스토리지 공유 |
| 장점 | 단순, 저렴 | 설치·공유 쉬움 | 고성능, 대규모, 확장성 |
| 단점 | 확장성·공유성 낮음 | LAN 트래픽 영향, 대용량 DB엔 성능 한계 | **비쌈**, 구축 복잡 |

- **iSCSI**: SCSI 명령을 **TCP/IP(이더넷)** 위에 실어 보내는 프로토콜 → 비싼 FC 장비 없이 **IP 네트워크로 SAN 구성** 가능 (IP-SAN).
- **Fibre Channel**: 광 채널. SAN 전용 고속 통신 기술, FC 스위치·HBA 카드 필요.

> 💡 시험 포인트: "RAID 5 최소 3개, 1개 고장 허용, (N−1)", "RAID 6 최소 4개, 2개 고장 허용, (N−2)", "RAID 0은 내결함성 없음", 용량 계산, "파일 단위 LAN 공유 = NAS, 블록 단위 전용망 = SAN, iSCSI = SCSI over TCP/IP".

## 14. 고가용성(HA): 이중화와 로드밸런싱

### 14-1. 이중화

- **고가용성(High Availability)**: 장애가 나도 서비스가 멈추지 않게 하는 것. 핵심은 **단일 장애점(SPOF, Single Point of Failure) 제거**.
- 이중화 대상: 전원(이중 파워, UPS), 디스크(RAID), NIC(티밍/본딩), 링크(링크 집합), 스위치(STP), 게이트웨이(VRRP/HSRP), 서버(클러스터링).
- 구성 방식
  - **Active–Standby**: 평소엔 한 대만 일하고, 장애 시 대기 장비가 넘겨받음(**Failover**).
  - **Active–Active**: 두 대가 동시에 일하며 부하를 나눔.

### 14-2. 게이트웨이 이중화 프로토콜 (FHRP)

PC는 기본 게이트웨이를 **하나만** 설정할 수 있습니다. 그 라우터가 죽으면 외부와 통신이 끊기므로, 라우터 여러 대가 **가상 IP(+가상 MAC) 하나를 공유**하게 만드는 기술입니다. PC는 가상 IP를 게이트웨이로 씁니다.

| 프로토콜 | 표준 | 역할 이름 | 특징 |
|---|---|---|---|
| **HSRP** (Hot Standby Router Protocol) | **Cisco 전용** | Active / Standby | 한 대만 실제 전달 |
| **VRRP** (Virtual Router Redundancy Protocol) | **IETF 표준** (RFC) | Master / Backup | 여러 제조사 장비 혼용 가능 |
| GLBP (Gateway Load Balancing Protocol) | Cisco 전용 | AVG / AVF | 이중화 + **부하 분산**까지 |

### 14-3. 로드밸런싱(부하 분산)

여러 서버에 요청을 나눠 줘서 성능과 가용성을 높이는 것. **L4/L7 스위치** 또는 전용 로드밸런서가 담당.

| 알고리즘 | 설명 |
|---|---|
| **라운드 로빈(Round Robin)** | 서버에 **순서대로 돌아가며** 하나씩 배분 |
| 가중 라운드 로빈(Weighted RR) | 성능 좋은 서버에 **가중치**만큼 더 배분 |
| **최소 연결(Least Connection)** | 현재 **연결 수가 가장 적은** 서버에 배분 |
| 응답 시간(Response Time) | 응답이 가장 빠른 서버에 배분 |
| 해시(Hash) | 출발지 IP 등을 해시해서 같은 사용자는 같은 서버로 |

> 💡 시험 포인트: "가상 게이트웨이 이중화 — HSRP(Cisco), VRRP(표준)", "순서대로 돌아가며 = 라운드 로빈", "SPOF 제거가 이중화 목적".

## 15. 무선 장비와 전원 장비

### 15-1. AP(Access Point)와 SSID

- **SSID(Service Set Identifier)**: 무선 네트워크의 **이름**. 최대 **32자(바이트)**. 대소문자 구분.
  - SSID 브로드캐스트를 끄면(숨김) 목록에 안 보이지만, 그것만으로 완벽한 보안은 아님.
- **BSS**: AP 1대 + 단말들의 기본 단위 / **ESS**: 같은 SSID를 쓰는 여러 AP를 묶은 확장 영역(로밍 가능).
- **애드혹(Ad-hoc, IBSS)** 모드: AP 없이 단말끼리 직접 통신 / **인프라스트럭처** 모드: AP를 통해 통신.

**AP 동작 모드**

| 모드 | 설명 |
|---|---|
| Root(AP) 모드 | 일반적인 AP. 무선 단말을 유선망에 연결 |
| Repeater 모드 | 다른 AP의 신호를 받아 **중계**해 커버리지 확장 |
| Bridge 모드 | 두 건물 등 **유선 네트워크끼리 무선으로 연결** |
| Client 모드 | AP가 단말처럼 다른 AP에 접속 |

**AP 종류**

| 종류 | 설명 |
|---|---|
| **Fat AP**(Autonomous, 독립형) | AP마다 설정·관리 기능을 모두 가짐. 소규모용 |
| **Thin AP**(Lightweight, 컨트롤러 기반) | 설정·관리·보안 정책을 **무선 랜 컨트롤러(WLC)** 가 중앙에서 일괄 처리 (Cisco는 CAPWAP 프로토콜 사용). 대규모·로밍 환경용 |

- 무선 랜 컨트롤러(WLC): 수많은 AP를 **중앙에서 관리**(설정 배포, 채널·출력 자동 조정, 로밍 지원, 인증).

### 15-2. UPS (무정전 전원 장치)

정전·전압 변동 시 배터리로 전원을 공급해 서버·네트워크 장비를 보호.

| 방식 | 평상시 | 정전 시 | 특징 |
|---|---|---|---|
| **Off-line (Standby)** | 상용 전원 직접 공급 | 인버터로 **전환**(짧은 절체 시간 있음) | 저렴, 소형 |
| Line-Interactive | 상용 전원 + 전압 조정 | 인버터 전환 | 중간 |
| **On-line** | **항상 인버터**를 거쳐 공급 | 전환 없이 배터리 공급 (**무순단**) | 가장 안정적, 고가 — 서버실용 |

> 💡 시험 포인트: "SSID = 무선망 이름, 최대 32자", "AP 여러 대를 중앙 관리 = 무선 랜 컨트롤러", "On-line UPS = 무순단".

## ★ 핵심사항 (시험 직전 10분 암기용)

- 리피터·허브 = **1계층**, 브리지·L2 스위치·NIC = **2계층(MAC)**, 라우터·L3 스위치 = **3계층(IP)**, L4 = **포트**, L7 = **콘텐츠**, 게이트웨이 = **프로토콜 변환(상위 계층)**
- MAC 주소 = **48비트**, 16진수 12자리, **앞 24비트 OUI(제조사)**, 뒤 24비트 일련번호
- MAC은 **홉마다 바뀜**, IP는 끝까지 유지
- 충돌 도메인 분할: **브리지·스위치·라우터** / 브로드캐스트 도메인 분할: **라우터·L3 스위치(·VLAN)**
- 허브 = 반이중, 대역폭 공유, 허브 전체가 충돌 도메인 1개
- 스위치 = 포트별 충돌 도메인, 전이중, 포트별 전용 대역폭, 하드웨어(ASIC)
- 스위치 5기능: **Learning(출발지 MAC 학습)**, **Flooding(모르면 전부)**, **Forwarding(아는 포트로)**, **Filtering(같은 포트면 폐기)**, **Aging(300초 후 삭제)**
- Store-and-Forward = 전체 저장 + CRC 검사 / Cut-Through = 목적지 MAC만 보고 즉시(가장 빠름) / Fragment-Free = **처음 64바이트**
- 이더넷 프레임 **64~1518바이트**, 데이터 **46~1500**, FCS **4바이트 CRC-32**, MTU **1500**, 프리앰블 7 + SFD 1
- VLAN = 논리적 그룹, **브로드캐스트 도메인 분할**, VLAN 간 통신은 **라우터/L3 스위치** 필요
- **802.1Q** = IEEE 표준, **4바이트 태그 삽입**, **VID 12비트(1~4094)**, Native VLAN(기본 VLAN 1)은 태그 없음
- **ISL** = Cisco 전용, 프레임 전체 캡슐화
- 액세스 포트 = VLAN 1개(단말), 트렁크 포트 = 여러 VLAN(스위치 간)
- VTP: Server(생성·전파) / Client(생성 불가) / **Transparent(자기만 생성, 통과만)**
- STP = **802.1D**, 루프·브로드캐스트 스톰 방지, BPDU 교환
- 루트 브리지 = **BID 가장 낮은 것** (우선순위 기본 32768 → 같으면 MAC 낮은 것)
- 루트 포트 = 비루트 스위치마다 1개(루트까지 비용 최소) / 지정 포트 = 세그먼트마다 1개 / 나머지 = Blocking
- 포트 상태: **Blocking → Listening → Learning → Forwarding** (Learning = MAC 학습O, 전달X)
- 타이머: **Hello 2초, Max Age 20초, Forward Delay 15초** / 경로 비용 10M=100, 100M=19, 1G=4
- RSTP = **802.1w** (빠른 수렴), MSTP = **802.1s**
- 링크 집합: LACP = **802.3ad** (표준), PAgP = Cisco / PoE = **802.3af(15.4W)**, PoE+ = **802.3at(30W)**
- 다른 종류 장비 = **다이렉트**, 같은 종류(PC–PC, 스위치–스위치, PC–라우터) = **크로스오버**, 콘솔 = **롤오버**
- 라우터: **ROM**(POST·Bootstrap) / **Flash**(IOS) / **NVRAM**(startup-config) / **RAM**(running-config·라우팅 테이블, 휘발성)
- 부팅: **POST → Bootstrap → IOS 로드(Flash) → startup-config 로드(NVRAM)**, 설정 없으면 Setup 모드
- 프롬프트: `>` 사용자 / `#` 특권(enable) / `(config)#` 전역(configure terminal) / `(config-if)#` 인터페이스
- 저장: **copy running-config startup-config** / 라우팅 테이블: **show ip route**
- 정적 경로: **ip route 목적지 마스크 다음홉** / 기본 경로: ip route 0.0.0.0 0.0.0.0 다음홉
- RAID 0(2개, 100%, 내결함성X) / 1(2개, 50%) / **5(3개, N−1, 1개 고장 OK)** / **6(4개, N−2, 2개 고장 OK)** / 10(4개, 50%)
- **NAS = 파일 단위, LAN, NFS/SMB** / **SAN = 블록 단위, 전용망, FC/iSCSI** / DAS = 직접 연결
- 게이트웨이 이중화: **HSRP(Cisco)**, **VRRP(IETF 표준)**, GLBP(Cisco, 부하 분산)
- 디지털 전용선 = **CSU/DSU**, 아날로그 회선 = **모뎀**

## ⚠️ 헷갈리는 함정 포인트

| 헷갈리는 쌍 | 정답 정리 |
|---|---|
| 스위치가 배우는 MAC | **출발지 MAC** (목적지 아님!) 목적지 MAC은 "어디로 보낼지" 찾을 때 사용 |
| 스위치 vs 라우터의 브로드캐스트 | 스위치는 브로드캐스트를 **전 포트로 전달**(분할 X), 라우터는 **막음**(분할 O) |
| 브리지와 브로드캐스트 도메인 | 브리지도 2계층이라 **브로드캐스트 도메인 분할 못 함** — "브리지는 브로드캐스트 도메인을 나눈다" = 틀림 |
| Cut-Through vs Fragment-Free | Cut-Through = 목적지 주소(6바이트)만 / Fragment-Free = **64바이트** |
| 가장 빠른 방식 vs 가장 신뢰성 높은 방식 | 빠름 = Cut-Through / 신뢰성 = Store-and-Forward |
| 프레임 크기 vs 데이터 크기 | 프레임 64~**1518** / 데이터(MTU) 46~**1500** |
| 802.1Q vs ISL | 802.1Q = 표준, 태그 **삽입**(4바이트) / ISL = Cisco, **캡슐화** |
| 802.1Q vs 802.1D vs 802.1w vs 802.3ad | Q = VLAN 태깅 / D = STP / w = RSTP / s = MSTP / 3ad = LACP / 3af·at = PoE |
| 루트 브리지 선출 | BID가 **가장 낮은(작은)** 것. "가장 높은" = 틀림. 우선순위 먼저, 같으면 MAC |
| Listening vs Learning | Listening = MAC 학습 X / **Learning = MAC 학습 O** (둘 다 데이터 전달 X) |
| NVRAM vs RAM | NVRAM = **startup**-config(저장, 비휘발) / RAM = **running**-config(현재, 휘발) |
| ROM vs Flash | ROM = POST·부트스트랩 / Flash = **IOS** |
| copy 방향 | `copy [원본] [대상]` → 저장은 **running → startup** |
| PC–라우터 케이블 | 다른 장비처럼 보이지만 **크로스오버** |
| RAID 5 vs RAID 6 | 5 = 최소 **3개**, 패리티 1, **1개** 고장 허용 / 6 = 최소 **4개**, 패리티 2, **2개** 고장 허용 |
| RAID 0 vs RAID 1 | 0 = 스트라이핑(속도, 내결함성 없음) / 1 = 미러링(안전, 효율 50%) |
| NAS vs SAN | NAS = **파일**, LAN / SAN = **블록**, 전용망 (글자 순서 반대라 헷갈림 주의) |
| HSRP vs VRRP | HSRP = **Cisco 전용**(Active/Standby) / VRRP = **표준**(Master/Backup) |
| 모뎀 vs CSU/DSU | 모뎀 = **아날로그** 회선 / CSU/DSU = **디지털** 전용선 |

## 🧠 암기 팁

- **장비 계층**: "**리허(1) 브스(2) 라(3)**" — 리피터·허브 1, 브리지·스위치 2, 라우터 3
- **도메인 분할**: "**충돌은 둘(2계층)부터, 방송(브로드캐스트)은 셋(3계층)부터**"
- **스위치 5기능**: "**러플포필에**" — Learning, Flooding, Forwarding, Filtering, Aging
- **스위칭 방식**: "**저장(Store)은 꼼꼼, 컷(Cut)은 성급, 프래그(Fragment)는 64만 확인**"
- **프레임 숫자**: "**64 ~ 1518**, 그 안의 데이터 **46 ~ 1500**" — 차이는 둘 다 18(헤더 14 + FCS 4)
- **IEEE 802.1 패밀리**: "**D**는 **D**ead loop 방지(STP), **w**는 **w**ow 빠름(RSTP), **s**는 **s**everal(MSTP), **Q**는 **Q**ueue처럼 태그 붙이기(VLAN)"
- **STP 상태**: "**블리스러포**" — **B**locking → **Li**stening → **Le**arning → **Fo**rwarding (블→리→러→포)
- **STP 타이머**: "**2·20·15**" — 헬로 2, 맥스 20, 포워드 15

## ✅ 정답 및 해설

| 문항 | 정답 | 해설 |
|---|:---:|---|
| 장비-01 | ④ | MAC 주소는 라우터를 지날 때마다(홉마다) 라우터가 새 프레임을 만들면서 **출발지·목적지 MAC이 바뀐다**. 끝까지 유지되는 것은 IP 주소. ①②③은 모두 옳은 설명. |
| 장비-02 | ② | 허브는 **물리 계층(1계층)** 장비(멀티포트 리피터). 리피터 1계층, 브리지 2계층, 라우터 3계층은 옳다. |
| 장비-03 | ③ | 스위치 쪽: 라우터–스위치 링크 1 + PC 4대 = 5개. 허브 쪽: 허브에 묶인 전체(라우터 링크 포함)가 1개. 합계 **6개**. (브로드캐스트 도메인은 라우터 인터페이스 수인 2개) |
| 장비-04 | ① | 목적지를 모르거나 브로드캐스트일 때 수신 포트 제외 전 포트로 보내는 것은 **Flooding**. Filtering은 같은 포트 쪽이면 폐기, Learning은 출발지 MAC 기록, Aging은 오래된 엔트리 삭제. |
| 장비-05 | ④ | 스위치는 **출발지 MAC 주소**와 들어온 포트를 기록해 테이블을 만든다(Learning). 목적지 MAC은 전달 포트를 찾을 때 쓰고, IP 주소는 2계층 스위치가 보지 않는다. |
| 장비-06 | ① | 프레임 전체를 받은 뒤 CRC 검사를 하는 것은 **Store-and-Forward**. Cut-Through는 목적지 MAC만 보고 즉시 보내므로 **오류 검사를 하지 않아** 오류 프레임도 전달한다. ②③④는 옳다. |
| 장비-07 | ④ | L2 스위치는 브로드캐스트를 모든 포트로 전달하므로 **VLAN이 없으면 전체가 하나의 브로드캐스트 도메인**. 포트별 전용 대역폭·전이중·포트별 충돌 도메인은 스위치의 특징. |
| 장비-08 | ② | 데이터 필드는 **46~1500바이트**(46 미만은 패딩). ③ 64~1518은 프레임 전체 크기(목적지 MAC~FCS). |
| 장비-09 | ③ | 다른 VLAN은 다른 브로드캐스트 도메인(다른 네트워크)이므로 **라우터나 L3 스위치**를 거쳐야 통신할 수 있다. ①②④는 VLAN의 특징·장점. |
| 장비-10 | ③ | 802.1Q는 출발지 MAC과 Type 사이에 **4바이트 태그**를 삽입하고, 그 안의 VID가 **12비트**(1~4094 사용). ① Cisco 전용은 ISL, ② 캡슐화도 ISL 방식, ④ Native VLAN은 **태그 없이** 전송. |
| 장비-11 | ① | **Auto-MDIX** = 케이블 종류 자동 인식·전환. PoE는 LAN 케이블 전원 공급, LACP는 링크 집합, STP는 루프 방지. |
| 장비-12 | ② | 루트 브리지는 브리지 ID가 **가장 낮은(작은)** 스위치. ①③④는 옳은 설명. |
| 장비-13 | ② | 우선순위를 먼저 비교 → 가장 낮은 값은 B의 **4096**. MAC 주소는 우선순위가 같을 때만 비교하므로 A·C의 MAC이 더 작아도 무관. |
| 장비-14 | ④ | **Learning** 상태는 MAC 주소를 학습하지만 데이터는 전달하지 않는다. Listening은 학습도 안 함, Blocking은 BPDU 수신만, Forwarding은 학습과 전달 모두 수행. |
| 장비-15 | ① | 802.1D 기본값: **Hello 2초, Max Age 20초, Forward Delay 15초**. |
| 장비-16 | ③ | LACP = **IEEE 802.3ad**(현재 802.1AX). 802.1Q는 VLAN 태깅, 802.1D는 STP, 802.3af는 PoE. |
| 장비-17 | ① | 같은 종류 장비끼리(스위치–스위치, PC–PC, PC–라우터 등)는 **크로스오버**. PC–스위치, 라우터–스위치, PC–허브는 서로 다른 그룹이라 다이렉트 케이블. |
| 장비-18 | ③ | startup-config는 **NVRAM**(비휘발성)에 저장. ROM은 POST·부트스트랩, RAM은 running-config, Flash는 IOS 이미지. |
| 장비-19 | ① | `copy [원본] [대상]` 형식이므로 현재 설정(running)을 시작 설정(startup)으로 복사해야 저장된다. ②는 반대 방향, ③은 보기만 함, ④는 저장된 설정 삭제. |
| 장비-20 | ② | 형식은 `ip route [목적지 네트워크] [서브넷 마스크] [다음 홉]`이며 **전역 설정 모드**에서 입력. ①은 순서가 뒤바뀜, ③은 와일드카드 마스크를 사용해 틀림, ④는 특권 모드(`#`)라 입력 불가. |
| 장비-21 | ③ | **POST(ROM) → Bootstrap(ROM) → IOS 로드(Flash) → startup-config 로드(NVRAM)**. |
| 장비-22 | ④ | RAID 6은 **이중 패리티**를 사용해 디스크 **2개**가 동시에 고장 나도 복구 가능하다(최소 4개). 1개만 허용하는 것은 RAID 5. |
| 장비-23 | ② | RAID 6 사용 용량 = (N − 2) × D = (6 − 2) × 2TB = **8TB**. |
| 장비-24 | ② | **iSCSI** = SCSI over TCP/IP → IP 기반 SAN(블록 단위). NFS·SMB는 NAS의 **파일 단위** 공유 프로토콜, FTP는 파일 전송 프로토콜. |
| 장비-25 | ③ | **VRRP**는 IETF 표준 게이트웨이 이중화 프로토콜(Master/Backup). HSRP와 GLBP는 Cisco 전용, STP는 2계층 루프 방지 프로토콜. |
